# 5.14 「客户端怎么知道思考开始了」这一问，答案是**协议**，不是参数（2026-10-05 学习者提出）

> 本文件是 `NOTES.md` 第 5 节「决策与教训存档」的原文搬移（内容未改），供「当初为什么这么定」被质疑时查阅。回 [NOTES.md](../../NOTES.md)。

---


学习者看完 `llm/0005` 追问两件事：**边界是不是 API 请求参数告诉客户端的**、**模型自己怎么决定开始和结束**。查完一手资料，答案分成两半，**两半都不在原课里**。

- **请求参数只给"许可和预算"，不含任何位置信息。** 边界在**响应结构**里：思考是一类**独立的内容块**（`type: "thinking"`），答案是另一类（`type: "text"`），`content` 数组按顺序排好。客户端靠**块的类型**认起止 —— 这是 1.4 说的"进阶版才装机制边界"里最该留在基础课的一条，因为**没有"块"这个概念，第 5 节④「思考块原样带回去」就是一句空话**。
  - **判据：讲"多出来的那一步"时，代价层面（慢/贵/占上下文/改代码）讲全了，但"它在协议里长什么样"可以整节缺失而读者读得下去** —— 说明缺的是**另一根轴**，不是主线漏了一句。**发现主线自洽 ≠ 讲完了。**
- **模型的开始/结束没有开关、没有控制器**，就是第 1 课那个"抽下一个 token"：抽到一个"这段想完了"的 token 就转去写正文。**跟第 1 课"抽到结束符整条回复就停"是同一类事件**，只是这次结束的不是整条回复而是思考这一段。
  - **判据：跨课接机制时，先问"这是不是前一课那个机制的又一次发生"** —— 是的话直接接上，比重新解释一遍省力，而且读者会立刻有"哦原来就是它"的感觉（本例正是学习者自己把两课挂上的）。
- **两件差点写错、查了才发现的事**：
  1. **"第 4/5 节"那两个引用本来以为是小节号漂移**，逐条读上下文才发现**它们指的是脚本输出里编号的 `[4]` `[5]` 段**，不是本课小节（就在 `<pre>` 输出下面的"四处要看懂"里）。**差点把对的改成错的** —— 5.4「正则只用来定位，不用来定性」这条在"引用同一份文件里的另一种编号"上同样适用。
  2. **自适应模式下思考块可能压根不产生**，所以"客户端判断这次想没想"只能靠有没有块。这一条如果漏了，读者会建一个"我开了思考就一定有那段文字"的错模型 —— **它的破坏力不在漏掉，而在会把后面所有关于计费和延迟的推论带歪**。

## 5.14.1 这一轮的取舍

- 学习者选定形态：**基础课加一小节 ＋ 术语表补两条**（`#thinking-block` / `#signature`），流式细节、`display` 三档、加密机制**下沉**。
  - ⚠ **但 `llm/0005` 还没有进阶版**，1.5 那条"次要细节去处"的 ② 是空的。所以这轮实际落点是：① 正文只留主线（块是什么 + 靠类型认边界），② 下沉的东西进了**术语表**和 **ask-teacher**（补了两问：思考块会不会出现好几次、厂商不给文字时客户端怎么显示"正在思考"）。
  - **判据：选了"下沉"但目标文件不存在时，不要假装下沉了 —— 把落点改到真正存在的地方，并在 NOTES 里记下这笔欠账。**
- **顺手修掉一处小节号顺移**（新节插在 §2 之后，§3–§8 全部 +1），并核对了全文 5 处"第 N 节"引用的归属：4 处指向别的课或脚本输出段，**只有新加的桥接句需要避开编号** —— 改成引用**小节名**（「四笔账那一节」）而不是编号，免得下次再插节又漂一次。
- **`llm/0005` 仍然没有进阶版**：这轮欠下的账是它 —— 流式事件逐条的语义、`display` 三档的取舍、signature 的加密与校验、各版本保留策略的差异，都还没有去处。**等第 5 课定稿时一起开**，别在基础课还改的时候就单开一轮（学习者在 5.13.7 已经表过态："别单开一轮"）。
- **追问一层：「推理引擎怎么知道哪段是思考」**（同一个学习者，紧接着上面那问）。结论：**它不「知道」，它**认记号**——**切分**（在 token 流上找到记号切一刀、包成块）**而不是理解**。**学习者自己抓到了矛盾**：先接受了「模型输出思考标记」，再发现「API 返回里又明确标了思考」，觉得两处对不上。**这个矛盾是本轮最有价值的东西**，它逼出了"切 vs 懂"这一层。
  - **最强的钥匙是本仓库已有的结论，不是新知识**：跟<a href="../../lessons/agent/0002-tool-use.html">`agent/0002`</a> 的工具调用**完全同构**——模型不声明「我在调工具」，只是写出一段那个形状的字；程序不"理解"，只按格式认出那段字。**判据：解释一个新机制时，先在本仓库里找同构的旧结论；有同构的就直接指过去，别重新造一套说法。** 这一句就把整层讲完了，所以最后只落了一句 + 一个回链。
  - **四条证据**（都是文档硬话，用来确认是「切」不是「懂」）：① 手动模式 API **强制**开启思考那轮必须以 thinking 块开头（**能强制 = 能识别边界**）；② `usage.output_tokens_details.thinking_tokens` **能把一段精确切出来数**（= 边界是离散 token 位置，不是含糊语义）；③ 文档用词就是 "**separated from** the canonical response"（**分离是切分动作**）；④ **切在哪由模型决定不由配置决定**——同一配置下块数与长度每次都不同，简单题可能为零。
  - **签名防的是伪造**：覆盖**原始 token 区间**、不是显示出来的那段文字。所以 `display: "omitted"` 时字段为空仍能原样送回（空字段填字"被忽略"而非被拒，**因为那块根本没参与签名**）。
  - **落盘时保留了推论标记**：正文那句写了"那个『记号』长什么样是我从规则反推的，厂商没公开内部实现"。**判据：压成一句话不等于可以不标推论**——1.1 是硬规则，且**这一句恰好就是最容易被后人当硬事实引用的一句**。
  - ⚠ **本轮已确认下沉但仍无去处**：四条证据链、签名的伪造防护、框架（设计出来的）与内容（RL 里涌现的）之分，**都只有 NOTES 里这一条记录**，课件里一句都没留。
