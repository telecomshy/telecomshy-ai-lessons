# 5.9 `llm/0003` 基础课：注释框收敛到 2 个（2026-10-04 学习者提出）

> 本文件是 `NOTES.md` 第 5 节「决策与教训存档」的原文搬移（内容未改），供「当初为什么这么定」被质疑时查阅。回 [NOTES.md](../../NOTES.md)。

---


学习者两条意见：**① 反复提问改出来的稿子不流畅；② 注释框太多，而且是被当成分段与排版用的。** 这一课原来有 **8 个 `note` ＋ 1 个中途 `goal`**（"一次请求 ＝ 两段" / "术语四连" / "这一层没有命中" / "机制上" / "账单上" / "工具结果" / "为什么对 agent 要命"…），读起来像七块补丁拼的，不像一篇文章。**现在只剩 2 个：钩子 `goal` ＋ 主线 `note`（这两个是 1.2 的必备零件）。**

- **判据（可复用到剩下所有课）**：**注释框只装"不影响主线读下去"的东西。** 一个框如果拆掉之后读者还得顺着正文读下去才明白，那它装的就是主线内容，该融进正文。**框不是排版工具**——`<b>标签：说明</b>` 这种句内形式能替代九成的框。术语也别整框堆：`前缀 / 命中 / cache write / TTL` 那四条，前两条是主线（随文带出），后两条进阶版和术语表已有家 → 降成半句话 ＋ 一个括号直达。
- **"顺便说清…"式的灰字段落同病**，一并清掉：它们是提问时随手加的补丁，读起来像旁白。留下的是**一个短语一个链接**的括号（1.4 认可的那种），整句的灰字说明删掉或改写成正文。
- **数字去重**（1.5"同一件事只量化一次"）：原来 `3.7 倍` 出现两次（一句"差距不是一点半点" ＋ 一个括注），删掉前句；实测改成一张两行表（A 96%/45、B 0%/168），并**把"第 1 次请求永远是冷的"从挑战的提示里提到表前**——不写清的话，96% 这个数跟脚本输出对不上（脚本里第 1 次是 0%）。**判据：正文里的数必须跟实跑输出逐句对账，包括那些"显然是例外"的那一行。**
- **顺手补的两处缺口**：① 加回 `0002` 那样的"想深挖"清单（进阶版 6 问里原本只有 3 问有入口，其余 3 问只有进阶版自己能到）——1.4 说那个去处**继续有效**，不是"放不下"才用；② source 框补 Anthropic 官方 Prompt caching 文档，因为 `0.1×` 与"写入另计费"现在在基础课正文里承重，原来只有进阶版和速查页有出处（`RESOURCES.md` 里早就有，注明"用来：讲缓存的实际接法与成本"）。
- **一处旧措辞残留**：`0003-deep` 的 `<h1>` 还写"**五个**绕人的细节"（5.8 那次只改了 README ＋ 目录页，h1 漏了，而它数的就是问数）。顺手改成"六个"。**教训同 5.7 第 1 条**：改数字要 grep **页面自己的标题**，外链审计抓不到。
- **§4「输出的字有缓存吗」的结论改口径（2026-10-04 学习者提出）**。原来那版是"**机制上 / 账单上**分两栏"，落点是"**账单上对，机制上不完全对**"。学习者改成**跟着"上一轮模型写出来的那几个字"走三笔账**：① 它刚生成那次按**输出价**（最贵那档）→ ② 下一轮它跟着历史进请求，变成**输入**，仍要钱，但**命中缓存按缓存读价（≈0.1×）**→ ③ **动了前缀**（换工具、改系统提示）→ 从改动处往后全部重算，**之前模型写的字一起算进去，按原价输入收费**。
  - **为什么他的版本更好**：原版是"两个维度各说一半"，读者拿不到一个能拿去用的判断；他这版是**一段文字的三笔账**，读完就知道"动前缀的代价里包含历史输出"。
  - **新口径一句话**：**折扣不跟着"输入/输出"走，跟着"这一轮是读缓存还是重算"走。**（依据：进阶版 Q1 那张官方表里，第 2 次请求的 `答1` 已经在"读缓存"那一段里。）
  - **连带必须同一次改的两处**（1.5 第 2 问，否则正文和小测打架）：① **小测 Q3 原正确项"机制上有，账单上不打折"在新口径下是错的**——下一轮它是输入、**它是打折的**。改成「上一轮模型写出来的字，这一轮算是什么？」／正确项「输入，命中缓存就打折」。② **`0003-deep` 总链那句"缓存不打折输出"**收窄成同一句口径 ＋ 一个括注。**判据：改结论时，把全库承载旧结论的句子一起 grep 一遍**——小测选项、别页的总链摘要、反馈文案，都是结论的副本。
  - **术语零新增**：这一版没有引入新词（"缓存读价"是"cache read 约 0.1× 输入价"的落地说法，`0003-deep` Q3 已有），所以术语表不用动。
- **§5 那个"每轮重写系统提示"的例子是编的，学习者一眼问出来（2026-10-04）**。它的毛病不是"不准确"，而是**不真实**——agent 框架一般不会每轮重写系统提示，所以这个"错误示范"没人会犯，读者拿它对不上自己的代码。换成学习者点出的**真正容易犯的那个**：**多轮对话进行到一半时增删／改动工具定义**（这条有出处：`0003-deep` Q1 引的官方文档列了"改早期消息、删消息、调换顺序"三类打断）。**判据（补进 1.1 的执行方式）：举一个"你会犯的错"之前，先问一句"这个场景在实践中真的会发生吗、在哪份资料里写着"**——**例子和结论一样要能追到出处**；追不到就别举，改成机制陈述（"前缀里只要有东西变了，从那儿往后全部重算"），不要包装成一个假想事故。
  - 顺带在这一段里**补上一处反直觉的精确化**：改完工具之后，**只有那一遍请求付全额**，下一次请求又命中（这一遍算完，缓存里重新存下一份对得上的前缀）。原来的写法（"每一遍都从头算"）会让人以为"改一次工具，这一整个任务后面全废"——**方向反了**。**判据：说"从改动处往后作废"，必须把"作废到什么时候"说到底**，否则读者会自动外推成最坏情况。
  - **同一条里还出过第二个错：拿抽象名词代替机制（"新配置又是稳定的"）**。学习者问"新配置是什么意思"，答不上来——因为它没有落到任何具体的东西上。**判据：一句话里如果出现"配置／状态／上下文"这类抽象名词，就检查它能不能被换成"哪一遍请求、哪个位置、什么时刻"**。换成机制之后，行动建议自然就出来了：**要改就在开场之前改好；中途确实要换，就另起一段对话**（学习者自己提的，比我原来那句有用）。顺带把"从改动那一处往后"也钉准了——**工具定义排在最前面，所以改工具是从第一个 token 起全废**，不是"从改动处算起"（§3 已经给过这个顺序）。
- **两处措辞是自造词，被学习者两次点掉（2026-10-04）**：`新观察`（列举请求的第四部分时用）· `捡现成`（全课 6 处）。
  - **`新观察` → `这一轮新加的那点东西（你刚问的那句、工具刚返回的结果）`**。**判据：在"枚举请求里装了什么"的句子里，不能用 agent 圈的术语（观察／action／thought）**——那些词在 `agent/0001`（ReAct 那套）里有它们的定义，在基础课这里没有，读者只会卡住。**同一个词在不同课里的合法性取决于"那节课有没有先给它定义"。**
  - **`捡现成` → 全部换成这课自己的词：`接着用`／`复用`／`命中`／`读缓存`**（全课 7 处，含一处裸用的"跨请求还能捡"）。**这条是自打脸**：§2 已经把 `请求内复用 ＝ 后面每一步接着用这一步之前算好的` 和 `跨请求复用` 定义好了，主线框也写的是"上次算的这次接着用"，**正文却另外造了一个"捡现成"**。**判据：正文用词必须来自本课已定义的术语 ＋ 主线框用同一套**——造第三种说法等于让读者多记一张词表。连带改了进阶版 Q3 那条和目录页卡片文案。
    - **附带一条搜索纪律**：清一个自造词时**别只 grep 整个词**——"捡现成"删干净之后还剩一处裸用的"还能**捡**"，是按整词 grep 漏掉的。**判据：清词要 grep 到它的"词根"**（这里该搜 `捡`），不然会以为自己清完了。
    - ~~**同族还有一个自造词没动**：进阶版 Q5 的 `「白捡」听着很美`~~ —— **2026-10-05 已改**：Q5 开头改成「别以为命中就是免费，实际有三道折扣」。它和 `捡现成` 是同一族的自造词（把"打折"说成"白捡"），清 `捡现成` 那一轮漏了它，因为**只 grep 了「捡现成」整个词，没 grep 词根「捡」**。
