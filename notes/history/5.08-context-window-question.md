# 5.8 上下文窗口这一问的拆放（2026-10-04 学习者提出）

> 本文件是 `NOTES.md` 第 5 节「决策与教训存档」的原文搬移（内容未改），供「当初为什么这么定」被质疑时查阅。回 [NOTES.md](../../NOTES.md)。

---


学习者给 `0001-deep` Q9 列了五个必答：**百万上下文指什么** · **命中缓存的前缀算不算窗口** · **上限是显卡定还是训练定** · **agent 的请求里装什么** · **放哪一课**。逐条落定：

- **百万上下文＝一次请求的序列上限**。多轮会话里每一轮请求都把前面的全部内容重新带上——用户提问、模型回答、**连思考的 token 都算**（第 5 课钉过"思考是真 token"），越聊越长直到顶上限。
- **命中缓存照样占窗口**：缓存省的是"重算"，不是"位置"——K/V 正因为还留在显存里占着位置，才谈得上被命中。
- **上限是模型定的（架构＋位置机制＋训练长度），显存是代价不是上限**。⚠ 现文原写"上限卡在显存"，**把因果说反了**，已纠正为"换更大的显卡窗口不会变大；显卡决定的是每个位置留一份 K/V 的账单"。**判据："上限卡在哪"这类归因要分清「标称上限」和「代价」——两个都真实，但不能互相顶名。**
- **agent 的请求按前缀顺序装：工具定义 → 系统提示 → 消息**（提问、回答、工具调用与返回、思考），全占窗口。
- **拆开放（学习者拍板）**：Q9 留 `0001-deep` 答"是什么/装什么/谁定/没用满填什么"；**"命中缓存算不算窗口"升级成 `0003-deep` 新 Q6**——它原来只是 Q5"三道折扣"里的一条（"照样占位置"），现在提出来成问、两处互链，**不另起一套说法**。收口金句："缓存救时间，不救窗口"。
- 顺带两处数字残留：`0003` 进阶昵称"**五个**绕人的细节"数的是问数 → 改"**六个**"（README + 目录页）。

- **同问第二轮：六处按学习者的追问重写（2026-10-04）**。①"这条流水线"改"模型"——"流水线"是讲内部结构时的比喻，不在本问用。② **"位置"要先定义**：位置＝第几个 token＝表里的第几行（学习者问"什么叫 token 的位置"）。③ **窗口钉成"送进模型那张表的行数上限"**——流程"切分→查编号→查表→送进模型"里卡的是最后一步，超没超切分完数行数就知道。④ **KV 是连带不是关系**：窗口和 KV 缓存没有直接关系，只是"每个位置都要留一份 K/V"，所以窗口越大 KV 越多——**那是代价不是上限**（学习者复述得比我原文准）。⑤ **超窗口＝API 报错拒掉**（新增一手来源：Anthropic Platform "Context windows"——400 `prompt is too long`，不截断不丢前缀，已登 RESOURCES）。⑥ **agent 放最后并扩充**：按"用户看不见的（系统消息、工具定义）／看得见的（提问、回答）／中间产生的（工具调用与返回、思考）"分组；**拼接顺序各家不同**（术语表记的是 Anthropic 的顺序），顺序只影响缓存命中、不影响"全都占窗口"。
- **"没用满的部分填什么"整节删（含 padding 注）**：学习者指出懂了窗口就不会有这疑问；而 padding 注**术语表 `#padding` 逐字已钉**（"空位上本来就没有东西"都在），搬去第 4 课就是三处重复，且 1.5 说次要细节不进基础课正文。**判据：删之前先查术语表——"没地方放"常常是"已经放在术语表了"。**
- **`0003-deep` Q6 标题按学习者措辞改**："命中缓存的前缀，还算不算进上下文窗口"→"**如果前缀命中缓存了，还占不占用上下文窗口？**"（前者"命中缓存的前缀"有歧义），正文加一句"**命中缓存和上下文窗口没有直接关系**"。

- **同问第三轮：形态上"融成一篇"，别切成 FAQ（2026-10-04 学习者提出）**。Q9 上一版按追问点切成 5 个 h3，读起来是"答案清单"不是"回答"——同一问的几个侧面（是什么/数什么/谁定/超了怎样/agent）应该走 Q7 那种连续行文＋一个小列表，h3 只留给真正独立的问（Q3 的"分开答四个问题"是例外）。**判据：一问里的 h3 是"同一问题的分面"时，优先融成段落链；切成 h3 的前提是每个小节本身能独立成问。** 另记一条措辞教训：**为某个词设的解释，必须跟词同生共死**——上一版把正文的"位置"改成了"行/行数"，却留下了"「位置」是什么？"小节，孤儿解释。现在这个词只在真出现的地方随文带一次（"每一行就是一个 token 的位置（第几个进来的，就是第几行）"）。

- **`0001-deep` 的"附 · 五个别误会"转正为 Q11（2026-10-04 学习者提出）**：「附」是体例外的补丁块，改成正问「Q11 · 关于向量本身，哪五个地方最容易说错？」——它就有编号、进"想深挖"清单、可被定位。**位置不动（挂末尾）**：往前挪会让 Q3–Q10 全部重编号、动一堆外链，不值。老锚点 `#q-misconceptions` 留兼容 span，外链仅 1 处（`0002` 基础课那条"附录「五个别误会」"）已改成 Q11 的叫法。同族待办见 4.3。

- **Q10 补"怎么抽"与推荐值（2026-10-04 学习者追问）＋ 全页小标题清零**。学习者问"分表之后到底怎么挑？总不能都挑最大吧"——**正文从来没说破"默认是按百分比掷骰子"**（脚本里抽了 2000 次，正文却没写机制），补上并直接答"不是每次都挑最大的，永远挑最大＝贪心（T→0）"。**例子数字换掉瞎编的 50/30/20，改用本课脚本实跑的那组**（T=0.2 → 98.6% / T=1 → 49.7% / T=2 → 33.7%，与文末输出摘录逐句对账）。补技巧（T=1 原样、T<1 变尖更稳、T>1 变平更发散）与**工程常用值——引 `reference/sampling-params.html` 的推荐表，不凭记忆**。形态：`0001-deep` 全页 h3 清零（Q3 的四个、Q4 的两个、Q6 的一个全部融成"提问式引导句＋段落"），Q3 的"分开答四个问题"路线图保留当目录。**判据汇总：正文要兑现脚本演示的机制（脚本做了、正文没说＝欠账）；示例数字只用实跑/有出处的；推荐值只引速查或一手文档。**
