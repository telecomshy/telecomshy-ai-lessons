## 扩了什么

### MCP（从"三个角色 + 发现"扩成"原理 + 配置"）

- **三个角色**：host / client / server；host 给每个 server 建一个 client；本地 stdio 常单客户端，远程 Streamable HTTP 可服务多个。
- **底下跑什么**：JSON-RPC 2.0、无状态；两种传输（stdio / Streamable HTTP）；server 公布 tools / resources / prompts；发现 `server/discover`、`tools/list`，执行 `tools/call`；工具清单可变更通知。
- **配置**：`mcpServers` JSON 的字段口径（服务名 / `command` / `args` / `env`）；TeleAgent 的「设置 → 工具设置 → 从 JSON 导入/添加」五步；绿色「已连接」、首页 MCP 按钮、连接/断开/编辑；改工具名会断旧引用。
- **安全与排错**：本地 server 以你的用户权限跑；只接可信来源、密钥进 `env`、最小权限；`command` 找不到 / JSON 语法 / 相对路径 / 未配 env / 连上但模型不调 / 改名失效。
- **什么时候不该用 MCP**：一次性、单应用的小工具，直接写函数更省。

### Skill（从"结构 + 渐进加载"扩成"用 TeleAgent 真的建一个"）

- **结构**：目录 + `SKILL.md`（YAML frontmatter 的 `name`/`description` + 正文）+ 可选 `reference.md` / scripts；渐进式加载三层。
- **创建**：技能广场右上角【创建技能】或 `@技能孵化器`；给"名字 / 什么时候用 / 输入 / 步骤 / 输出格式 / 边界"的自然语言模板；生成后进「我的技能」→ 启用 → `@` 手动指定测试。
- **管理/迭代**：详情、评分、启用上限 50、同一技能用 ≥20 次触发自进化、更新/上架；导入 `.zip`/`.skill` 要求根目录 `SKILL.md` + YAML + ≤10MB + 安全审查。
- **技巧**：description 写"做什么 + 什么时候用"；一 skill 一事；正文写成操作手册；长内容外移；给例子；用真实任务迭代；只装可信 skill。
- **常见问题**：不触发、误触发、输出格式不对、导入失败、改了没生效、脚本跑不起来、技能太多互相抢。

- **MCP 加「本地 server / 远程 server」对照表**：跑在哪／传输（stdio vs Streamable HTTP）／配置（`command`+`args`+`env` vs URL+鉴权）／要不要 npx／例子。明说 **`command`/`args` 是本地 stdio 的写法，远程不需要 npx**。

- **client 归属**：在三个角色后加一句 **MCP client 是 harness 内置的**，用户只配 server，不用自己写 client。

## 5.44.2 加「MCP 还是 Skill」决策节（同日续）

学习者总结：两者场景不同但功能有重合，本地 MCP 基本都能用 Skill 代替；用户装 Skill 本地跑脚本也能实现很多 MCP 功能，Skill 也能包含工具；MCP 更多用于"自己的数据只能让别人有限制地读（鉴权）"。

- **判断：大方向对，两处要修正**。
  1. **重合是真的**：本地 MCP server＝本机程序通过 stdio 暴露能力；Skill 也能带脚本。只服务一个 harness、一个团队，很多本地 MCP 可以用 Skill + 脚本替掉（省掉插口标准这一层）。
  2. **但"基本都能代替"要收窄**：MCP 的价值在**多客户端复用、发现/稳定 schema、独立进程或远程、凭据与权限关在 server 里**；这些不是 Skill 的长处。Skill 不对外提供标准接口，换客户端不一定认。
  3. **"只能 MCP"太绝对**：Skill 脚本也能带 token 调内部 API；鉴权不是唯一分界。真正的分界是"要不要标准接口/多客户端/远程隔离"，不是"有没有鉴权"。
  4. **"Skill 也能包含工具"要讲清**：Skill 可以带脚本，但通常不会像 MCP 工具那样作为带 schema 的 callable 注册给模型；模型看到的是"这个技能可用"，再按正文执行脚本。
- **新增 §6「MCP 还是 Skill？先看'谁在用它'」**：先承认重合，再讲两层分工，最后用一张 6 行决策表（单 harness→Skill；多客户端/发现→MCP；远程鉴权/隔离→MCP；教流程→Skill；要可调用函数→MCP 工具；一次性→直接写函数）。
- **收口句**：Skill 管"这件事怎么做"，MCP 管"这个能力怎么被接上"；常常配合，不是替代。
- 小测加 Q12（单 harness 本地小工具最省事的做法→Skill + 脚本），现在 12 题、各一个 correct。
- 没有新增图；引用仍用 MCP 官方架构与 Anthropic Skills 两处一手资料。
