# 「缓存命中率」是 agent 成本结构的第一杠杆

前缀缓存（prompt caching）决定了 agent 每轮循环的真实成本：系统提示、工具定义、历史对话构成稳定前缀，命中时按约 0.1× 计价。因此「稳定内容放前、易变内容放后」不是写法偏好，而是**架构决策**——它直接决定账单倍数。本节点已作为 LLM 底层第 3 课讲过（`lessons/llm/0003-kv-cache-and-prompt-caching.html`），并配了可运行的模拟脚本（`exercises/llm/0003-cache-hit-simulator.py`，实测稳定前缀 vs 破坏前缀成本约差 3.7 倍）。

**Evidence**：学习者主动提出关于 KV cache 与「缓存命中」的详细问题，并要求把此洞见记入学习记录。尚未通过测验或练习验证掌握程度——待其完成 LLM 底层第 3 课小测后确认。

**Implications**：后续涉及 agent 工程（工具设计、记忆、上下文管理）的课程，可默认学习者已接触「前缀稳定」，直接从「如何在多轮循环里维持稳定前缀」这个应用层讲起，不必重讲 KV cache 原理。注意：模拟脚本把「一个空格分隔的词」当作 1 个 token，真实分词不同，别让学习者把它当成精确成本模型。
