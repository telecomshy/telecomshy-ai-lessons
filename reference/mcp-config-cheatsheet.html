MCP 配置速查

照着填、照着查。想懂为什么这么填，回 第 3 课 · MCP。

1. 本地 server：完整例子和字段

{
  "mcpServers": {
    "math-server": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-everything"]
    }
  }
}
字段 必填 说明
mcpServers 是 整份配置的入口，所有 MCP 服务都写在它里面
服务名（第一层的名字） 是 自己起，建议小写字母、数字、连字符；math-server 就是手册例子里起的名
command 是 启动这个 server 用的命令（npx、python、node 这几种常见）
args 是 传给命令的参数。例子里的 -y 是"安装时不逐个确认"；server-everything 是 MCP 项目仓库的测试工具包，里面带一批示例工具
env 否 要给这个 server 的环境变量，比如 API key。放这里，别写进 args 或对话里

本地入口各家不一样：Claude Desktop 读的是 claude_desktop_config.json；TeleAgent 在设置 → 工具设置里粘贴。

2. 远程 server：完整例子

远程 server 跑在服务商那边，配置里没有 command 和 args。下面是腾讯云 CloudBase 的 Hosted 模式例子（CloudBase 文档）：

{
  "mcpServers": {
    "cloudbase": {
      "type": "http",
      "url": "https://tcb-api.cloud.tencent.com/mcp/v1?env_id=YOUR_ENV_ID",
      "headers": {
        "X-TencentCloud-SecretId": "YOUR_SECRET_ID",
        "X-TencentCloud-SecretKey": "YOUR_SECRET_KEY"
      }
    }
  }
}

type 是 http；url 是服务地址；headers 里放身份凭据（证明你有权用这个服务）。不同产品字段名不一样：有的写 streamable-http，有的把凭据放别的字段。以产品文档为准。

3. 配置弄错了，按这个顺序查

先查不用命令行的：

  1. JSON 语法：多一个逗号、少一个引号、args 写成了文字而不是列表——这三种最常见。粘贴后用任意一个在线"JSON 校验"工具过一眼。
  2. 名字改没改过：服务名改了，旧任务里记的还是旧名字。改名前先想清楚。
  3. 连上了但模型不调：先确认工具清单已经报上来了，再看工具说明写没写全。
  4. key 放对没：需要凭据的 server，key 写在 env（或远程配置的 headers）里，不要写进参数、不要发在对话里。

要动命令行才查得清的（需要有人带你做一次）：

  1. command 找不到：npx 属于 Node.js（一个常见的运行环境，装了它才有 npx 命令）；python 不在 PATH（系统找命令的目录清单）里也一样报找不到。
  2. 先手动跑一遍：在终端（Windows 上叫"命令提示符"或"PowerShell"的窗口）里把 command 加 args 原样跑一次，能跑通再填进配置。
  3. 路径写的是相对路径：换成绝对路径（从盘符开头写完整，比如 C:\work\tools\x.py），尤其注意 Windows 的反斜杠。

4. 自己写工具的人：工具说明写全五样

模型看到的只有名字和说明，五样写全，它才调得对、看得懂结果：

  • 名字：动词加名词，一眼看懂干什么。
  • 说明：干什么加什么时候用。
  • 参数：类型、必填、给个示例。
  • 返回什么：结果的结构和单位。
  • 出错怎么说：错误信息要让模型看懂，并且能照着改。
