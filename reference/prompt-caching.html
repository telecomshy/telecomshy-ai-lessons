KV Cache 与「缓存命中」

两个被混为一谈的「缓存」。分清了，agent 的成本账才算得清。

先分清两个东西

KV Cache 前缀缓存 Prompt Cache
范围 单次请求内部 跨多次请求
目的 逐字生成时不重算前面的词 复用多次请求相同开头的算力
「命中」 自动生效，没有命中概念 开头一字不差才命中

KV Cache（同一次生成内）

  • Attention 里，每个词会算出三个向量：Query（去找别人）、Key（被别人比对）、Value（被取走）。三者都来自同一个词，是三种用途，不是三种信息。
  • 生成是「一次一个词」。写第 N 个词，要用前 N−1 个词的 K/V。
  • 把算过的 K/V 存下来 → 下一个词只算新词的，旧的直接接上。
  • 代价：显存。每个词都要存一对 K/V，随序列长度线性增长。

前缀缓存 / 缓存命中（跨请求）

  • 服务商把「多次请求里开头完全相同的那段」的 KV 张量存起来复用。
  • 缓存的是 KV 张量，不是 token 文本本身（OpenAI 官方文档原话）。
  • 顺序：tools → system → messages，严格前缀匹配。
  • 某一处不同 → 从该点往后的缓存全部失效。
  • 计费：cache read（命中读取）≈ 0.1× 输入价；cache write（首次写入）Anthropic 约 1.25×，OpenAI 新版也可能收费。
  • OpenAI：前缀 ≥ 1024 token 才可缓存，命中按 128-token 粒度；可用 prompt_cache_key 影响路由。
  • Anthropic：用 cache_control 显式标断点；缓存有 TTL（默认约 5 分钟，可延长）。

对 agent 的工程结论（重点）

  • 稳定的放前面：系统提示、工具定义、少样本示例、长文档 → 提高命中率。
  • 易变的放后面：用户当前这句话、新的工具结果 / 观察。
  • 别动态改系统提示、别动态增删工具定义、别往中间插内容 —— 都会把前缀打断。
