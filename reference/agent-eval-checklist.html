试一个 agent 该问什么

照着做就行。想懂理由，回 技巧篇 0002 · 怎么判断一个 agent 好不好用。

① 挑任务

  • 用你真实的活，不要用 demo 里的例子——别人的场景跟你的不是一回事
  • 3～5 个就够先看苗头；要认真评估，官方建议 20～50 个
  • 覆盖不同的活：简单的、稍复杂的、要调工具的、要几步才能完的
  • 先把"算成功"的标准写清楚（一个别人也能照着判的标准）

② 每个任务跑 3～5 遍

为什么不能只跑一遍

agent 是不确定的——同样的输入，两次结果可能不一样。跑一次等于掷一次骰子。

单次成功率 连做 3 次全对 连做 5 次全对 连做 8 次全对
95%86%77%66%
90%73%59%43%
75%42%24%10%
60%22%8%2%

用 exercises/practice/0002-agent-scorecard.py 填数就出这张表。

③ 看"真实结果"，别看它的话

别只看 要去查
它说"已为您预订"系统里到底有没有这条记录
它说"文件已修改"文件真的变了没、内容对不对
界面显示"成功"真实状态（数据库 / 邮件 / 工单）
它给的数字和结论抽几个关键事实核对一遍
为什么容易骗过你

工具可能只返回了"部分成功"，agent 却当成成功报了；界面也照样告诉你成功。

④ 顺手记三个数

  • 它走了几步 / 调了几次工具——同样的结果，步数可能差好几倍
  • 每次大概花多少——同样的成功率，成本能差几十倍
  • 慢在哪一段——从你发出到第一个字（等）· 之后每字多久（算）

做法很简单：同一个任务跑两次，比这几个数。第三个还要再比一次——白天和深夜各来一遍：差得多，多半是服务端在排队。

⑤ 四条永远适用的提醒

1. 跑一次不算数　→ 多跑几遍，看稳不稳
2. 它说成了 ≠ 成了　→ 查真实状态
3. 别只问对不对，也问绕了多大圈　→ 代价是要付钱的
4. 别信宣传里的分数　→ 信你自己试出来的

什么时候这些不适用

  • 任务每次都不一样（研究类）→ 没法重复跑，改成"多试几个不同任务"
  • 纯问答、没有外部状态 → 没有"真实结果"可查，改成"核对它说的关键事实"
  • 一次性的大活 → 成本不敏感，不用纠结步数
  • 离线批处理（没人盯着）→ 别盯单次延迟，改盯"一共出了多少字、多久跑完"
  • 模型跑在你自己机器上 → 通常没人跟你抢、也没有排队，慢就是慢

两个词，知道就行

指标 意思 什么场景看它
pass@k k 次里至少成功一次 "多试几次总行"（出方案让你挑）
pass^k k 次全部成功 "每次都必须对"（自动处理真事）

做使用者，你要盯的是后面那个。
