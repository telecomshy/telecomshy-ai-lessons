术语表

全课程统一使用这里的说法。课里出现的词，回来这里对一遍。

Agent（智能体）
一个以 LLM 为"大脑"、能围绕一个目标反复决策并采取行动的系统。关键不在"会回答问题"，而在"会自己决定下一步做什么"。
单次 LLM 调用
输入 prompt、输出文本，一问一答，结束。没有循环、没有工具、没有状态。它是 agent 的零件，不是 agent 本身。
Agent 循环（Agent loop）
本课程的核心：推理 → 行动 → 观察 → 再推理，直到任务完成或触发停止条件。见第 1 课。
Tool（工具）
agent 能对"外部世界"做的事：查数据库、调 API、算数、读文件。模型不直接执行，而是输出一个结构化的调用意图，由程序去执行。
Function calling（函数调用）
让模型按约定格式输出"要调用哪个工具、参数是什么"的机制。是 tool use 的工程实现方式。
MCP（Model Context Protocol，模型上下文协议）
一套开放标准，让"提供工具的一方"和"用工具的一方"说同一种话。类比插座标准：写一次，到处能用，不用为每家 API 重写适配。关键是能被发现（discovery）——先问"你能干什么"，再决定用哪个。server 一般公布 tools / resources / prompts 三样。
Skill（技能）
不是"一个函数"，是"做某一类事的完整做法"：一个目录，装着指令 + 可能的脚本 + 参考资料（核心是 SKILL.md）。类比菜谱：工具是厨具，skill 是"这类菜该怎么做、翻车怎么救"。靠渐进式加载省上下文。
渐进式加载（progressive disclosure）
不把所有东西一次性塞进上下文：先给一句说明，用得上才展开正文，正文里提到的资料再按需打开。理由是上下文是稀缺资源——进上下文的东西都要花钱、占位置、互相干扰。
Harness（运行外壳 / 脚手架）
套在模型外面的那套软件：拼 prompt、执行工具、管上下文、施加护栏、加载 skill、接 MCP、做界面、存状态。Agent ＝ Model ＋ Harness（Martin Fowler / LangChain 的说法）。
注意：agent 是「行为」，harness 是「软件」——你下载安装的其实是 harness，agent 是它跑起来后表现出的能力。同一个模型换 harness，表现会差很多。
Observation（观察）
工具执行后返回的结果。它被喂回给模型，成为下一轮推理的输入——这是循环得以"感知环境"的方式。
Trace / Trajectory（轨迹）
一次任务中，所有"推理—行动—观察"步骤的完整记录。调试 agent 时，看 trace 是第一步。
pass@k / pass^k
评测 agent 的两个指标。pass@k ＝ k 次里至少成功一次（能力）；pass^k ＝ k 次全部成功（一致性）。因为"每次都成"是连乘，单次 90% 连着做 8 次全对只剩约 43%。做使用者要盯 pass^k。
结果（outcome）vs 轨迹（transcript / trajectory）
评 agent 的两个对象。结果＝跑完之后环境的真实状态（数据库里到底有没有那条订单）；轨迹＝它走过的完整记录（调了哪些工具、参数是什么、什么时候停）。
别只看结果——它会掩盖绕路和违规；也别只看轨迹——路走得漂亮不等于真做成了。
ReAct
一种让模型交替产生"推理轨迹"和"动作"的范式（Reason + Act）。现代 agent 循环的理论来源。原论文。
Planning（规划）
把一个大目标拆成可执行的子步骤的能力。agent 三大支柱之一。
Memory（记忆）
短时记忆＝当前上下文窗口里的内容；长时记忆＝跨会话持久化存储、需要时检索回来。agent 三大支柱之一。
Context / 上下文工程
模型这一次能看到的所有内容。它有硬上限，叫上下文窗口（context window）：输入的 token + 已写出来的 token 加起来不能超过它。它是稀缺且昂贵的资源，往里塞什么、丢掉什么，直接决定 agent 表现。
Workflow（工作流）
由代码预先编排好的固定步骤。可靠、可控。与 agent 的区别：agent 让模型动态决定流程。Anthropic 建议：能用工作流解决就别上 agent。
Guardrail（护栏）
限制 agent 行为的边界：最大步数、允许的工具白名单、需要人工批准的动作等。
Human-in-the-loop（人在环中）
在关键节点插入人工确认。高风险动作（转账、删数据）的常见保险。
Multi-agent（多智能体）
多个 agent 分工协作（如"编排者 + 工作者"）。更强也更难调试，通常不是起点。
Token（词元）/ 分词器（tokenizer）
模型处理文字的最小单位，由分词（tokenization）切出来，干这件事的组件叫分词器（tokenizer）——它不等于自然语言的"词"。中文一个词可能切成多个 token，英文生僻词可能被切成子串（如 un / happi / ness），空格与标点也可能是独立 token。token 是文本片段，不是数字；它接着会在词表里拿到一个编号（ID）。
向量（vector）/ 词嵌入（token embedding）
"一个 token 在数字世界里的样子"：一串固定长度的数字（真实模型几千个，本课程的玩具模型只有 4 个）。做法是拿 token 的编号去「嵌入表」里查第 N 行——嵌入表就是一张大数字表，词表多大就有多少行，一行 d 个数，所以这一步只是照抄，不用算；这个查表动作叫词嵌入。嵌入表是模型的第一层，里面的数字是训练学出来的（会被梯度更新），训好后固定不动——同一个字什么时候查都是同一串数字，会变的是它进模型之后被改写成什么样。数字本身没有可读含义，但两串数字越接近，说明两个 token 关系越近——模型靠这个判断相关性。
注意：一次送进模型的是 n 串向量（每个 token 一串），不是把整句压成一串。把整句压成一根向量的是另一个模型，叫文本嵌入，用途完全不同——见 文本嵌入。
文本嵌入（text embedding）/ 向量检索
把一整段文字（一句、一段、一页）压成一根向量，用的是另一个模型（embedding 模型），跟上面那个"词嵌入"是两回事。用途只有一个：比相似度——两段文字压出来的向量越接近，越相关。RAG 里"查资料"的底层动作就是它。
容易混的三点：① 词嵌入是语言模型的第一层，一个 token 一根；文本嵌入是独立的小模型，整段一根。② 词嵌入会被上下文反复改写；文本嵌入算完就固定下来存好，等着被查。③ 词嵌入喂给模型当输入；文本嵌入不喂给模型，只用来排序、挑出该给哪几段。
代价：它只比"像不像"，不懂对错。名字像不等于内容相关——这是 RAG 最常见的翻车点。
稀疏检索（sparse）/ 稠密检索（dense）
检索资料的两种比法。稀疏＝按字面匹配（数两段共有多少个词 / 字组合，像关键词搜索）；专有名词、编号、型号抓得准，但换个说法就漏。稠密＝按语义匹配（把整段压成向量比远近，见 文本嵌入）；换个说法也能找到，但对精确字面反而迟钝。
记法：稀疏看"字面撞没撞"，稠密看"意思近不近"。各有各的失手——查"RFC 7230"这种编号，稀疏赢；查"心梗"要它找出写"心肌梗死"的那页，稠密赢。所以很多系统两个一起用。
神经网络（neural network）
大模型里那副人写的骨架——程序员真正手写出来的那部分。一句话：一大堆"乘加"操作一层层摞起来，上一层的输出按一批权重重新配比（这个动作的学名是向量乘法：向量 × 权重），得出新输出交给下一层。今天大模型用的具体摞法是 Transformer（层 = 注意力 + FFN）。
骨架里那几百亿个权重，一个都不是人填的——那是训练阶段磨出来的。所以"大模型是人写的程序"和"它不是人写出来的"两句话都对：结构是人写的，内容是学出来的。
涌现（emergence）／ 量变到质变
规模（参数量 × 数据 × 算力）涨到某个程度后，能力突然"冒出来"的现象：同一个任务、同一个目标，参数少时看起来很笨，参数多时却"好像懂了"。经典例子是小模型完全不会的算术，大模型突然就会。
所以别用"它只是瞎猜下一个字"去否认它真的会做对事——任务从没变过，变的是规模。但反过来也成立：涌现的是"表现"，不是"对错判断"。既然评价标准只有"接得像"，那么一段胡话只要够像就同样高分——训练里从来没有"真假"这一项打分。
张量（tensor）/ 矩阵（matrix）
就是"一张数字表"。二维的张量也叫矩阵。LLM 的输入是一张 n 行 × d 列的表：宽度 d 固定（每串向量的长度），长度 n 随 token 数变。注意：一张表 = 一次请求（API 调用）的全部内容（你输入的 + 它已写出的，全在里面）。一次请求里模型会连着蹦出很多个字——但送进模型的表不会每轮变长：只有 prefill 那一次是 n 行，之后每轮只送新蹦出来的那 1 行，真正每轮变长的是缓存里的 k、v；而一次任务又会发出很多次请求。
Query / Key / Value（Q/K/V）
Attention 里每个词会算出三个向量：Query 负责"我要找什么"，Key 负责"我容不容易被别人对上"，Value 负责"对上之后交出什么"。三者都来自同一个词，是三种用途，不是三种信息。
点积（dot product）/ 加权求和 / 加权平均
点积：两串数字逐位相乘再加起来，用来比"像不像"——越大越像。
加权求和：每串数字乘上自己的比重，再加起来。当比重加起来正好是 1 时，也就是加权平均（weighted average）（如"平时 30% + 期末 70%"）。
Attention（注意力）
用当前 token 的 Query 去比所有已有 token 的 Key（用点积比相似度），把分数经 softmax 换算成百分比当权重，再对它们的 Value 做加权求和。候选名单包括当前 token 自己。输出是一个"看过前文之后"的向量（还不是字）。
Logits / Softmax / 采样（sampling）
模型最后把向量投影成"词表里每个 token 各得多少原始分"（logits），经 softmax 归一成概率分布，再采样挑出一个——那就是下一个 token。「怎么挑」是另一套旋钮，见 温度 与 Top-p / Top-k。
LM Head（语言模型头 / 输出层）
整摞层外面挂着的最后一张表，把一根向量摊成"词表里每个 token 各得多少分"。通常和嵌入表是同一张表（权重共享），所以不少小模型不单独训练它。基础课不要求记住这个名字——知道"最后拿一根向量去词表逐个对分"这件事就够了，见 Logits。
温度（temperature）
挑字前的一个旋钮：换算百分比之前，把所有原始分除以 T。T = 1 原样；T 越小百分比越尖（几乎只挑最高的那个），T 越大越平（小概率的字也有机会）；T 推向 0 就退化成贪心。它不改模型算出来的分，只改"怎么挑"——所以调它不会让模型变聪明或变笨。
Top-p（核采样 nucleus sampling）/ Top-k
挑字前砍尾巴的两把刀。top_k：只留分数最高的 k 个，按个数砍。top_p：从高到低累加百分比，加够 p 就停，留下的那一批叫核（nucleus），按攒够多少砍——分布尖就少留几个，分布平就多留几个。两把叠着用时，起作用的是更紧的那把。
FFN / MLP（前馈网络）
Transformer 每层里紧跟注意力之后的子层。不跨 token，只对每个位置各自改写一次。不是"检查"——预测还没发生。研究发现它像一张"模式 → 补充信息"的查找表：出现某种模式就往向量里推对应的词（如"埃菲尔铁塔位于" → 把「Paris」的分往上推）。
位置编码（positional encoding）
告诉模型"这是第几个字"的那份信息。光有嵌入表不够——「你」在第 1 位和在第 50 位，光看向量分不出来，所以送进模型的那一行是词嵌入 ＋ 位置编码（同一把尺子量出来的两根向量直接相加）。
三件与 KV cache 有关的事：① 位置不是拼接时用的——拼接只是沿序列轴首尾相接；位置在 k 被算出来之前就参与了计算，所以每一行缓存里的 k 自己就带着它的位置，接上去自然对上（只要顺序没错）。② 新 token 的位置 ＝ 已缓存的长度——缓存里有几行，它的位置就是几，这是它跟缓存唯一的耦合点。③ 所以位置会算错的场合只有一处：位置没接在缓存长度之后，前缀的语义位置就整体错位。
（本课只补了推理期必需的这一条；正弦/可学习的绝对位置编码、后来的 RoPE 等做法，见 权威图对照页。为什么只讲这一条 → 第 2 课进阶 · Q1）
填充（padding）/ 掩码（masking）
批量算多条长短不一的句子时，短的会被补上假 token（填充）凑齐长度；补的部分会被遮住（掩码）——模型看不见，也不参与计算。空位上本来就没有东西。
因果掩码（causal mask）
一条硬规定：每个位置只能看到自己和它之前的 token，看不到后面。因为任务是"猜下一个字"，能看到后面就成了抄答案。
权重共享（weight sharing）
n 个位置用的是同一套换算规则，不是 n 套。更像"一个老师同时批改 n 份卷子，用同一把尺子"。
层（layer）
Transformer 的基本积木：一层 = 注意力 + FFN（各自配一次残差）。真实模型叠几十层（原始论文只有 6 层），层层打磨对"下一个 token"的预测。每层的步骤一样，但每层自己的权重不同——同一个模子压出来的饼干，形状相同、花纹各不相同。
⚠ 别跟「一轮」混：层是模型内部的结构（一根向量进去要穿过全部层才出来），轮是一次请求里的进度（每蹦一个字走一遍）。一轮 = 走完全部层，所以一轮 ≠ 一层。→ 「一轮 / 层」这条
一轮（one pass）· 层 · 一次请求
把全课最容易混的三个数一次钉死（正文见 第 2 课 · 第 2 节）：
一次请求 ＝ 一次 API 往返（你发过去 ＋ 它把答案回过来）｜1 次 prefill（n 行一次算完）＋ 若干次 decode（每轮只算 1 行、往缓存里加 1 行）
一轮 ＝ 模型内部每蹦出一个字，就把整条流水线完整走一遍｜一次请求里有很多轮｜新算的那根向量要穿过所有层；注意力那一步还要读前面所有位置的 k、v（新字自己只占一行）
层 ＝ 模型的内部结构，跟对话流程无关｜一层 = 四个小步（注意力 → 残差 → FFN → 残差）｜真实模型几十层
最容易错的一处：一轮 ≠ 一层，一轮 = 走完全部层。「把流程走完算出一个字」是一轮；「再走一遍」是第二轮，不是第二层。
残差连接（residual connection）
每做完一步，都把"原来的向量"也加回来（新结果 = 旧向量 + 这一步算出的东西），防止改着改着把原有信息弄丢。
词表（vocabulary）
一张清单（不是解释意思的词典）：模型认识的每一个 token 都列上，每条配一个编号。规模几万到二十万条（GPT-2 约 5 万、GPT-4 约 10 万、GPT-4o 约 20 万）。跟分词器绑死，换模型就对不上。词表外的内容只能切成词表里有的小块拼出来。
打分时逐个对分的对象就是它——词表多大，logits 就有多少个数。
自回归生成（autoregressive generation）
"一次蹦一个 token、接上再蹦下一个"的生成方式。注意三件事：只有第一轮是把整段一起送的（prefill 一次并行算完 n 行），之后每轮只送新蹦出来的那 1 个——前面的位置以 KV cache 里的 k、v 在场，不再重送；并且只听最后一个位置的猜测——前面每个位置也都算了一遍、也各自猜了一个字，但没人用。（"每轮都把整句重发一遍"是不带缓存的跑法，见 第 2 课）
hidden state（隐状态）／ hidden 向量
每一层里、每个位置那根向量（长度 d，比如 4096）——就是第 1 课那张"n 行 × d 列"表里的一行，每过一层被改写一次。它不被缓存：要缓存的是从它投影出来的、每层注意力的 K/V。因为算下一个字时，新 token 只用 Q 去查历史的 K/V，历史 hidden 后面再也用不到。
一次任务 / 一次请求 / 一轮 decode
三个容易混的层次。一次任务＝用户发起的一件事；一次请求＝一次 API 调用（一次往返：你发过去 ＋ 它把答案回过来）；一轮 decode＝模型内部每蹦一个字走一遍流水线（新字走一遍，但要跟前面所有字一起算注意力）。
单轮聊天 ≈ 1 任务 = 1 请求（里面几百轮 decode）；agent ＝ 1 任务会发出十几次甚至几十次请求（每调一次工具就是一次新请求）。「缓存命中」只在请求之间才有意义。
训练（training）／ 损失（loss）／ 反向传播（backpropagation）
训练＝ 出题（文本自带答案，不用人标）→ 作答 → 算损失 → 从出口往回追责，把所有权重朝"少扣分"的方向拧极小一步 → 重复几百亿次。损失（扣分）＝ 答案那个字拿到的百分比越低、扣得越多（−log(百分比)），所以是个可以算出来的数。反向传播＝ 算账的顺序：做题从前往后，追责从后往前，一次算出几十亿个权重各该往哪拧。
扣分不会降到 0：语料里同一处本来就有几种答案时，按比例猜已经是最优——那部分扣不掉，是数据本身的不确定性，不是模型笨。同理，模型给的从来不是答案，是一张百分比表。
权重（weights）／ 参数（parameters）
训练学出来的、固定不变的那些数——就是第 1 课说的"同一把尺子"。它不参与被算，它参与算。例：W_q / W_k / W_v、输出投影、FFN 的两层。
K/V 不是权重——K/V 是根据输入算出来的中间结果：k = 这一行的向量 × W_k，v = 这一行的向量 × W_v。同一把尺子，量出来的数每个 token 都不同。
KV Cache（键值缓存）
模型生成文字时，把每个词算过的 Key/Value 向量留下来复用，避免重复计算。只存 K/V、不存 Q——Query 只属于"当前这一位置"，用完即弃；K/V 则要被之后所有新 token 反复读取。每层各有一份（只有注意力产生 K/V，FFN 不产生），也不存 hidden 向量。只影响速度，不影响答案。详见 速查：KV Cache 与「缓存命中」。
前缀缓存 / 缓存命中
跨请求复用前缀的 KV。前缀 ＝ 一次请求从第一个 token 起的那一段，按 工具定义 → 系统提示 → 消息 的顺序拼成——日常说"提示词 + 对话记录"基本就是它。必须从第一个 token 起连续、一字不差才叫命中；中间断一处，从那儿往后全部重算。命中读取约 0.1× 价格。详见 速查。
缓存断点（cache breakpoint）
在请求的某一块末尾写的一个标记（Claude：cache_control；OpenAI：prompt_cache_breakpoint），意思是「从第一个 token 到这一块为止的整段，存进缓存」。一次请求最多 4 个；标记本身不花钱，钱在写入与读取上。
存的是整段，不是「这一小段」——两个断点之间不会被单独存成一份。因为 指纹是从第一个 token 累积的，所以改了前面的内容，包含它的那些份一起作废（改系统提示：断在工具定义那份还活着，断在它后面的全废）。
各家不同：Claude / OpenAI 让你打（或让它自动标在最后一个可缓存块），读取时从断点往回找有限的块数；Gemini / DeepSeek 没有这个概念——服务商自己决定切在哪。⚠ OpenAI 那两个参数只在 Responses API ＋ GPT-5.6 及以后有，更早的模型只有隐式缓存。详见 速查。
指纹（fingerprint）／ 前缀哈希（prefix hash）
「从第一个 token 到某一处为止的整段内容」算出来的一个编号，用来看"这一段我是不是算过"。它是累积的——内容里改一个字，编号就变、对不上，那份就作废；这就是前缀缓存"断一处、后面全废"的机制原因。
指纹只是编号：真正被复用、真正省下算力的是那一段算好的 K/V。所以"存一份"的花费按新增的那一段计，不是把整段重存一遍。
缓存用量三栏（cache_read / cache_creation / input_tokens）
响应 usage 里记账用的三个字段。⚠ 它们是提示词被断点切成的三段，不是"命中／没命中／第三种结果"：
cache_read_input_tokens　断点之前、以前存过的那段 —— 从缓存读回，约 0.1×
cache_creation_input_tokens　断点之前、这次才新算出来的那段 —— 算完存进去，约 1.25×
input_tokens　最后一个断点之后的那截 —— 按定义就进不了缓存，每次重算、原价
官方特意强调过：input_tokens 不代表你送进去的全部输入，只代表最后一个断点后面那一截。三者相加才是这次的总输入。详见 速查。
Prefill（预填充）
一次请求的第一段：对整段输入做一次完整前向（每层都走注意力 + FFN），输入 token 可以并行处理，所以是「算力受限」、决定首字延迟。跑完有两个产出：第 1 个回复 token，以及每层注意力的 K/V（后面 decode 要反复读的那个货架）。注意：每个位置的注意力都要算、一个都不少（含输入的那些位置），只是因为 k、v 各算各的、不依赖别人，所以能一次算完——既不是"逐个字排队算"，也不是"只算 k、v 不算注意力"。
增量 prefill（incremental / partial prefill）
前缀缓存命中时，只对新增的那一段做 prefill，老前缀的 KV 直接复用。判断标准不是"从第 1 个 token 开始算"，而是"对一段已知输入做并行前向、算出 K/V 填进缓存"——新增提问符合这个标准，所以它归 prefill，不归 decode。
Decode（解码）
第二段：处理模型自己蹦出来的那个 token（走的是和 prefill 同一套流水线，只是每次只喂 1 个）。只能串行；每写一个都要把全部历史 KV ＋ 模型权重从显存搬一遍，所以是「显存带宽受限」。它决定打字速度。
算术强度（arithmetic intensity）
量"值不值得算"的一把尺子：干了多少次运算 ÷ 搬了多少字节。prefill 一次算一大批（≈ L 倍），decode 一次只算一个（≈ 1 倍，这是理想化下限）。而显卡的"算力 ÷ 带宽"通常有上百到几百 FLOPs/Byte——真实模型实测 decode 约 60–80 ops/byte，离那个比值仍差着一个数量级上下。所以喂不饱计算单元，卡在带宽。
TTFT（首字延迟）
Time To First Token，从发出请求到看见第一个 token 的时间，主要由 prefill 决定。
TPOT（每 token 耗时）
Time Per Output Token，开始输出之后每个 token 花的时间，由 decode 决定。读者感受到的"打字速度"就是它。
批处理（batching）
一次让多个请求并排前进一个 token，共用同一趟"把模型权重搬进计算单元"的开销。用一点点延迟换巨大吞吐。批里的请求互不可见——每份 KV 是各人自己的，谁的注意力也只在谁的那份里比（第 1、2 课那些机制原样成立）。
批大小（batch size）
同一批里坐了几个请求。它决定这一轮要搬多少东西（权重 ＋ N 份 KV），也决定"多"和"快"怎么分。⚠ 它不是你能设的参数，是每一轮服务商从排队的请求里挑出的一批——挑的是时间上重叠的那些，不是队里所有人；挑多少由服务商自己的上限定（如 vLLM 的 max_num_seqs），见 排队。
排队（queueing）
请求到了服务端、还没被算的那段时间。忙的时候队会排起来，这段等待算进 TTFT（Anyscale 指标文档原话："it may queue incoming requests. This queuing delay adds to the TTFT"）。所以"慢"要先分清两种：排在队里的等（进 TTFT）和批里人多导致的每轮变慢（进 TPOT）。半夜没人用时批会小、吞吐也低——那是常态，不是故障。
吞吐（throughput）
整个系统每秒总共产出多少 token。与延迟（单个请求自己多快）是一对互相拉扯的指标。
连续批处理（continuous batching）
不等一整批跑完：每一步都重新组批，谁结束谁让位、空位立刻塞新请求。避免"短请求陪长请求干等"。vLLM 的核心优化之一。
量化（quantization）／ scale（换算倍数）
换一种存法：把每个权重从 float32（4 字节）改成低精度整数——只留少数几个可挑的值（4 bit ＝ 16 个），每个数四舍五入到离它最近的那个。就像把 1600 万色的照片改成 16 色：相近的值被并成一个，中间的差别直接丢了。每一小组数还配一个换算倍数（scale），记着这组的值间隔多宽，用的时候乘回去。和压缩的区别：压缩能还原，量化原值不保留。那份换算说明本身要占地方，所以「4 bit」实际占用接近 5 bit。
激活（activation）／ 离群值（outlier）
模型算的时候中间产生的那些数（不是学出来的权重，是喂进去之后流过各层的临时结果）。离群值指少数几个数天生比别的大很多——LLM 里它们专挑激活出来（权重好压，激活难压），会把整套取值的范围吃光。所以量化真正难啃的是激活，不是权重；AWQ 那个「重要性」也是看激活的分布，不是看权重本身。
显存带宽（memory bandwidth）／ 算力（compute）
显卡的两条独立资源：算力＝每秒能做多少次运算，带宽＝每秒能从显存搬多少字节。prefill 喂得饱算力（decode 喂不饱、卡在带宽上），见 算术强度。判断一个优化有没有用的问法：它砍的是「搬」还是「算」？——量化砍「搬」，所以只救 decode。
蒸馏（distillation）／ 软标签（soft targets）
让一个小模型照着一个大模型学——训练时拿老师那整张概率表当目标，包括几个"错"字上的分数。那些分数不是噪声：老师不只说「是晴天」，还说「错了多半错成下雨」——这套排序就是它的泛化方式，而只给正确答案的表里一点都留不下。 要先把老师「加热」（调高 温度），因为分布太尖时「第二名是谁」会被吞掉。 ⚠ 别和量化混：量化改「怎么存」，能力不变；蒸馏改「从哪来」，能力会变。顺序是先蒸馏变小、再量化压小。 ⚠ 「蒸馏」今天至少两个意思：搬概率表（本文这种），和搬大模型写出来的回答（R1 用的那种）。见LLM 第 7 课。
推理引擎（inference）
跑模型这件事本身——把权重搬上 GPU、把输入过一遍、把 token 挑出来。vLLM、SGLang、各家 API 的服务端都叫这个名字。⚠ 中文有坑：「推理」这两个字在中文里同时指 inference 和 reasoning，见下面一条。本课程的口径：跑模型＝推理引擎（讲机制时用「跑」字），想事情＝思考。
它管的活：排队与拼车（连续批处理）· 复用前缀缓存 · 从分表里挑字（温度 / top_p 这些旋钮它来执行）· 按语法划掉非法字 · 打草稿加速 · 决定什么时候停。⚠ 模型交出分数表就下班，后面这些全不是它干的。见LLM 第 8 课。
约束解码（constrained decoding）／ 结构化输出（structured outputs）
引擎在挑字之前，先拿一张语法规则把「拼下去会废掉的字」从分数表里划掉，只在剩下的里挑。用户侧的名字是「结构化输出」——按 JSON schema、正则、固定选项，甚至一句 SQL 的文法来限制输出的形状。
关键是「保证」不是「更小心」：官方原话是「通过约束解码来保证回答符合 schema」，所以不会再有解析报错——错字根本没进候选，不是模型变听话了。所以工具调用格式不合法、agent 直接崩，那件事的修法在接口这一层，不在提示词、不在模型大小。
代价：同一份 schema 第一次要多花时间编译、编译结果按 24 小时缓存；改 schema 会重编，还会作废这一轮对话的前缀缓存；schema 太复杂会被拒（400，另有 180 秒兜底超时）。⚠ 它会改答案——和投机解码正好相反，那个是只加速不改输出。详见 LLM 第 8 课。
投机解码（speculative decoding）
让一个便宜的小模型先连打几个字的草稿，再让大模型一次把这一批全验一遍；对的那些留下，错的从断点重接。卖点是「输出完全不变」——原论文就写着「不改变任何输出」地更快采样，T5-XXL 上 2～3 倍，而且不用重训练、不改结构。
和约束解码是一对反例：这一招只加速、不改行为；约束解码就是在改行为（改成你要求的那形状）。别混成一件。⚠ 它主要改善中低 QPS 时的「每个字之间的时间」——正对着 decode 带宽受限那条。见 LLM 第 8 课。
停止原因（stop reason）／ 为什么停了
每次回答回来都带的那个字段，说明这次为什么停。常见几种：答完了 · 撞到 max_tokens 上限 · 碰上了你设的 stop_sequences 停止字 · 要调工具（正常，不是错）· 拒答 · 把上下文窗口填满了。
⚠ 模型不会自己停——停在哪是引擎那层按上面几件事算的。对 agent 有一条要命的：撞上限时那份回答里没写完的工具调用是坏的，直接执行会出错，官方处置是调大上限、重发一次。所以「工具参数不完整」有一种成因不在模型。见 LLM 第 8 课。
API 网关 / 过载（overloaded）
请求穿过的倒数第二层（在你那段程序和推理引擎之间），管鉴权 · 限流 · 计费 · 决定转给哪台机器。它不是模型的一部分，也不是 agent 的一部分。
两种常见报错别混：429 限流是你把配额用超了——⚠ 若是撞到月度花费上限，它不给「等多久能重试」的提示、会一直失败到额度恢复，这种重试没有意义；529 过载是服务端现在人太多，跟你的请求无关，退避一下再试。另外 官方 SDK 默认就会退避重试两次，手写那层重试很可能叠在它之上。
思考（reasoning）／ 会思考的模型
模型在给答案之前先把问题想一遍——先复述题意、试几种办法、检查中间结果、发现不对就放弃那条路。那段「想」是真的 token：按输出计费、占上下文、而且必须原样带回去（否则有的厂商直接报错、有的让前缀缓存断掉）。它不是「更聪明的另一个模型」，而是同一个模型被允许多花时间。 ⚠ 中文有坑：「推理」这两个字也指这个意思（中文里 推理模型 通常＝ reasoning model），但本课程讲跑模型时说的是「推理引擎」＝ inference。看到「推理」先分清是哪一个。 也别把它想成人脑：原厂自己说过，模型"very often make decisions based on factors that they don't explicitly discuss in their thinking process"，所以读思考过程判断不了它在干什么。见 LLM 第 5 课。
？ 思考的深度怎么调：厂商给一个旋钮让你调"想多少"。Anthropic 的两个参数名：budget_tokens（旧模式，给一个 token 目标——是目标不是硬上限，实际用多少随任务浮动）· output_config: {effort: ...}（新模式，按 low / medium / high 分档，文档原话"用它代替 token 预算来控制推理深度"，也就是深度由模型自己定）。⚠ 动这两个会让缓存前缀作废——因为配置被渲染进 prompt 了，见 第 3 课进阶 Q1。别的厂商参数名不通用，别照抄。
思考块（thinking block）／ 内容块（content block）
模型一次回答不是一整段文字，而是一串带类型的内容块按顺序排好。思考是一类块（type: "thinking"），答案是另一类块（type: "text"）。客户端就是靠块的类型认出思考的起止——出现 thinking 块＝开始；这个块结束＝结束，之后才是答案（或工具调用）。请求里给的思考参数只说「允许思考、预算多少」，不含任何位置信息，所以边界只能在响应里读。 ⚠ 它不一定出现：响应里可能一个 thinking 块都没有——那这次就是没想。判断「有没有想」只能靠有没有这个块，请求参数里读不出来；至于什么时候会跳过，取决于模型和配置（有些厂商支持让模型自己判断难易，固定预算的那种配置则每次都想）。开了工具之后它还可能反复出现（夹在工具调用之间），所以「一次沉默、然后给答案」是个简化模型。 ⚠ 看到的 ≠ 付的：厂商可以只回一份摘要，甚至完全不给文字（只留签名），但计费按原始全长算。摘要由谁做的也分厂商：Anthropic 的摘要由另一个模型提炼（原话 "Summarization is processed by a different model"），它的任何档位都拿不到原始思考；开源模型（DeepSeek-R、Qwen3 这类）给的就是原文。见 思考 reasoning。
签名（signature）
思考块里加密的完整思考。服务端靠它验证「这个块确实是这个模型生成的」——这就是思考块必须原样带回去、改一个字就报错的原因：不是规矩，是有一把锁在查。流式下它在思考块结束前单独作为一条事件到达。 ⚠ 别去解析它：厂商明说这个字段是不透明的（opaque）。它的作用是证明来源，不是给你读的。
