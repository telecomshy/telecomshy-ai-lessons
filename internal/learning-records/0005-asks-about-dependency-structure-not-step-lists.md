# 追问的是「谁在什么时候用上它」，不是「这一步算不算」

这一轮连着卡了四次，四次的问法都是同一个模子：**「这个东西是干什么用的？」** 他自己把前三步（prefill 是预测第一个字 / 整批 k、v、q 一次算出来 / 前缀 token 参与第一个字的注意力）**全说对了**，唯独推不出"所以前缀 token 自己的注意力要不要算"——因为**全课从没说过"某个量在哪一层被谁读走"**。他卡的不是机制，是**依赖结构**。

**这个误解已被修正**：他知道了一个位置的注意力结果不是终点，是**下一层的 k、v 的原料**；也知道整条流水线里唯一真正串行的是"挑 token"。更重要的是他自己把因果关系说准了——**"看前面"不等于"等前面"**。

## Evidence

他连续四轮的提问都指向依赖结构，而不是单步计算：①「前缀每个 token 计算注意力向量是做什么用的？貌似预测下一个 token 没有用到这个注意力向量吧」；②「第二轮的输入是什么，以为就是最初的 token 向量」；③「如果每个位置的注意力都要计算，那么是怎么做到并行的」；④ 指出「注意力和 k/v/q 是两步计算，之前总以为是一步算出来的，所以就产生了矛盾」——**他自己定位了矛盾的来源**。

第 ④ 点尤其关键：他能判断"我把两件事当一步了"会产生矛盾，说明他具备自己拆解错误模型的能力，需要的是**课件把隐含的依赖显式说出来**。

## Implications

- **讲并行/批量/流水线时，不能只说"没有依赖"**——要同时给出**消费方**（谁读它）和**时机**（第几层读）。这与 LR-0003（Q 一次性 / K·V 可复用）、LR-0004（FFN 不回头读历史）同族，但更进一步：那两问问的是"这个量是谁产的"，**这一问问的是"这个量什么时候被谁读走"**。建议后续讲缓存、分块、流水线并行时，都按"谁在什么时候用"这个格式写。
- **主链的每一环都要能回答"输入是什么"**。`0002` 长期没明说"第 2 轮的输入 = 刚挑出的 token 编号 → 查嵌入表 → 一根新向量"，他就默认成了"最初的 token 向量"。**凡是"这一轮的输入从哪来"，缺了就会形成错误默认值**，哪怕其它地方都讲对了。
- **"注意力是两步"这类被默认合并的相邻步骤，必须显式拆开。** 他把"投影出 q/k/v"和"用 q/k/v 算注意力"当成了同一步，才导致自相矛盾。同理，"每一层 = 注意力 → 残差 → FFN → 残差"里的**两处残差**、**每层参数不同**也都被默认合并过，已分别补正。
- **该配图就别只写字。** 这条链他用文字版连卡三次；画成"跟踪「气」这一行往下走"（注意力结果被加回这一行 → 成为下一层输入 → 下一层里别的位置读它）之后一次通。**涉及跨层/跨位置的数据流向时，图比文字有效得多。**
- **他说"通了"之前不要急着往下讲。** 这次连续追问其实是**同一个卡点**换了四种问法（用途 / 输入 / 并行 / 步数）。我第一次答偏了（当成"算不算注意力"），他纠正后才接上。**遇到跟上次相似的问题，先确认问的是不是同一层意思。**
