# 能独立说清注意力的不对称：Query 一次性，Key/Value 可复用

学习者在读完 KV cache 那节后，自己推出了注意力机制里最关键的一处**不对称**：当前 token 用它的 Query 去比所有已有 token（**包括自己**）的 Key，按权重把 Value 加权求和；但 **Query 只属于「当前正在推进的那一个位置」，用完即弃；K/V 属于所有位置，要被之后源源不断的新 token 反复读取**。他因此顺带解释了「为什么缓存只叫 KV cache、不叫 QKV cache」——也就是说，他从机制反推出了 KV cache 的存在理由，而不是记住结论。

**Evidence**：两次连续追问。第一次问「下一个 token 还没出现，它的 Q/K/V 是哪来的？」；第二次问「这个『混』是怎么混的？自己的 K/V 此时起什么作用？是不是和其它 token 作用不一样？」——注意他在提问里已经带着正确答案的直觉（"作用是不一样的"）。我用一手来源核对：原始论文 *Attention Is All You Need* §3.2 明确是 "attend to all positions in the decoder **up to and including that position**"，与他的判断一致。此前的一处误解（以为存在「还没出现的 token」提供 Query）已被纠正，属于"误解被修正"型记录。

**Implications**：
- 注意力机制 + KV cache 的「为什么」这一层已站住，后续**默认掌握、不再重讲**；讲 multi-head、上下文窗口、长上下文代价时可直接引用这条不对称。
- 新增一条学习画像：该学习者会以**「这个信息从哪来、用完去哪」**的方式质疑机制（先追问 token 的来源，再追问 K/V 的角色与生命周期）。讲任何机制时最好显式标注每个量的**来源与生命周期**，否则容易卡——这是继 LR-0002（偏数量关系）之后第二次出现同类追问，指向同一偏好。
