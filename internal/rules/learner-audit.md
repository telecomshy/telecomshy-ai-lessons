## 什么时候跑

课件初稿完成后、机器核验之前，每课一轮；改课轮改动成段时重跑。

## 子代理画像（写进 prompt 的只有这些，不给别的）

- 30 岁上下的业务岗或初学者：**对 LLM 和 agent 有初步了解**（用过网页聊天、调过简单 prompt），没系统学过原理。
- **目标：读完这一课，能完全掌握课里的概念**——每个概念都能用自己的话说清「它是什么、解决什么问题」。
- 会跳读、会只扫标题；读不懂的地方不硬啃，直接标记。

## 派单模板

```text
你是一个学习者：<按上面的画像写>。通读这份课件：<文件路径>。
读完后只交一份审计报告，不改文件、不提修改方案：
1. 概念清单：课里的每个概念（术语、机制、数据），逐个标「能用一句话说清 / 说不清」；
   说不清的，写下你此刻的理解——让主代理能看出你卡在哪一步。
   主代理若附了「读者问题清单」（写课前列的 5～8 个应能回答的问题），逐问标「读完能答 / 答不出」。
2. 卡点：哪一段读不下去、哪一句要来回读、哪个词没解释就用了。
3. 「自以为懂」陷阱：哪些地方你觉得懂了，但让你举个例子或答一遍就说不出。
4. 顺带报告：例子像不像真的会发生、小测有没有考课里没讲的、有没有读着像补丁的段落。
```

## 意见处理（主代理做，审计报告只是输入）

1. **逐条核实**：① 对照课件原文——子代理说「没解释」的词，可能解释在别处（真没解释才改）；② 对照 COURSE-STANDARD 与该轨标准——别为了迎合审计意见删掉该留的细节、降了受众。
2. **概念缺口类意见优先级最高**（那是审计的目标）；语言顺不顺只在顺带报告里参考——语言修改不再是审计目标。
3. 驳回的意见留一句话理由（写进当轮报告），防止下一轮被同一个意见带偏。
4. 处理完进机器核验（COURSE-STANDARD 末尾交付检查单 A 段）。

## 护栏

- prompt **只给画像与任务**，不喂学习者或开发者的感受、不喂「这是我们刚写的」（防锚定，沿革见存档 5.59）。
- 只委派学生版，**不委派老师版预演**（存档 5.60 收窄口径，继续有效）。
- **审计不背合规清单**：术语格式、破折号、「官方」、注释框这类编辑判据由主代理对照标准自查（交付检查单 B 段〔主代〕条）——让学生画像去背清单会把「读的人」变成「编辑」，两类意见互相稀释。
- 审计报告不是结论：改不改、怎么改，主代理对照原文与标准拍板；改动的核验纪律（逐串核验、字节对账）照旧。
