## 1. 这一课讲什么

固定流水线假设「一次检索拿到回答所需的全部资料」；真实问题有三类不配合：不用查的、一次不够的、查回来是噪音或没有的。Agentic RAG 把检索从流水线里的固定一步变成循环里的工具，多出四个决定：查不查、查什么、够不够、再查不查。

两种代表做法各占一层：

- **Self-RAG**：把判断练成模型的输出。四类反思 token（Retrieve / IsRel / IsSup / IsUse），推理时按 token 概率给候选打分；`continue` 表示继续用上一段证据，不重新检索。它是训练出来的能力，不是提示词模板。
- **CRAG**：在检索结果外面加一道质检。0.77B 检索评估器给（问题，文档）打相关性分，按 Correct / Incorrect / Ambiguous 三分支决定精炼、网搜或两者都做；Ambiguous 是为了不把系统全押在评估器的准确率上。

多轮收益用 IRCoT 的多跳数字和本课脚本的轨迹说明；代价用串行延迟、上下文增长和 token 算术说明；停止条件五条写进代码，预算按轮数 / token / 墙钟时间三道上限。最后是选型、什么时候不上、怎么把多查的几次记进第 10 课那张成绩单。

## 2. 脚本：决策流程模拟器，不是模型

**决定**：不调模型，也不假装是模型。脚本是一台按规则决策的流程模拟器：检索器仍是二字组合＋点积，切块 90 字，top-k=2；评估器是关键词清单的替身；六个场景覆盖不用查、单跳、多跳、否定、切块坏了。

**为什么值得配**：这一课的核心不是「模型多聪明」，是「多查一轮换来什么、预算卡在哪、什么时候该停」。这三件事只有跑成可数的轨迹才看得见；纯文字讲会退化成清单。

**脚本给的证据**：

- 固定流水线 6 次检索、全中 1 题；agentic（上限 2）8 次、全中 3 题——总次数没降反升，省下的是简单题，多花的是多跳题。
- 上限 1→2 有收益，3→5 不再涨；第 3 轮多出来的一次是白跑；「没有新证据就停」比上限更早生效。
- 切块坏了那道题，查几轮都缺同一段：agentic 能改查询，改不了已经切碎的文本。

**纪律**：脚本确定性双跑一致；课内 `<pre>` 与实跑输出逐行对账（[2][3][4] 全表、[6] 两行，[1][5][7] 明确说不贴）；docstring 说明玩具边界，不把模拟数字当基准。

## 5. 教训

- **薄层课里，借来的词必须当场解释**。这一课借了 Agent 篇的「壳 / trace / max_steps」和论文里的「消融 / TFLOPs / precision」，学生画像全部标了出来；不解释就等于假设读者已经读过另一条轨道。
- **「论文没规定」是可以写进课里的答案**。评估器怎么汇总、Ambiguous 怎么合并，主文确实没给唯一做法；硬编一个反而制造假精确。承认边界，再给工程上可选的固定方式，读者才知道哪里要自己定。
- **表格要和正文对得上人数**。`[4]` 表只有 5 次检索，正文却说六道题；不补「第 1 题跳过」，读者会以为算错。
- **同一个数字在同一课出现两次，要说明它不是同一个东西**。Self-RAG 和 CRAG 的 54.9 碰巧一样；不点破，读者第一反应是抄错。
- **例子要只承担一个岔口**。「离职＋年假」会把读者带到「折算」和「30 天通知」两个岔题上；换成「加班调休和年假申请分别要提前多久」后，两个半句都是用户真问的，缺的那一半也正好是检索漏掉的。
- **脚本摘录的对账要逐行做，不能只看块在不在**。本轮换例子后，`[3]` 的查询行和缩进全变，逐行对账当场抓住；只肉眼扫一遍会漏。
