# 5.69 0004 开课＋首个 deep 关停＋一手资料复抓抓出四处置换

> 触发：2026-11-03 批 1 第二会话，按 `RAG-REVISION-PLAN.md` 施工 0004「建库：清洗与切块」（0002-deep 升格＋新内容），同轮关停 0002-deep——改版以来第一个退役的 deep 页。

## 决策

1. **deep 关停的标准动作（首例定型）**：内容升格进新课 → 旧页 `git rm` → 互链改指新课（本轮 2 处：0001-deep、0009-deep）→ 目录卡与 README 行删除 → **统计同步**（基础 21→22、进阶 12→11；⚠ 总门数 33 不变——新增与关停一加一减，别顺手把总数 +1）→ 配套脚本随课改名（`0002-chunking.py`→`0004-chunking.py`，docstring/运行行同改）。判据照计划 §3-5：**对应课上线同轮关停，双版本不共存**。
2. **升格不白抄**：0002-deep 的尺寸基准、重叠两面、三档切法全数并入 0004，但按新课的叙事重排（清洗→切法→尺寸→重叠→父子块），并把它砍掉的「切太大」补成三切命运图；旧摘录直接复用，写完跑"摘录逐行 ⊂ 实跑输出"脚本确认。
3. **过渡期互链规矩**：新课 next 里"顺着往下"指向**还没建的 0005** 时用纯文本、不挂链接（挂了就是断链）；等 0005 上线同轮补 href。

## 教训

4. **"已核"是待复抓的欠条**：开工前按 1.1「字段名引用前当场再抓」复抓两份一手资料，**两周内抓出四处置换**——docs 线 rc2→rc3；**嵌入锁定换口径**（"选了就不许换"→兼容性抽查：维度一致＋平均余弦 ≥0.9 放行、且**不自动重嵌旧块**）；解析模板 **Tag 下线、Picture 新增**；Extractor 的 **Augmented context 改名 Summary**。厂商字段名与行为断言是最快烂的东西，旧 quote 留着标时代，**新旧口径同一次改掉**（RESOURCES 条目＋计划 §5 两处同步）。0005 嵌入课直接吃这个红利。
5. **改名和改内容别并行**：`git mv` 与 edit 同批发出时 edit 会抢在 mv 前执行、报 File not found——重排操作一律串行（本轮踩到一次，重发即过）。
