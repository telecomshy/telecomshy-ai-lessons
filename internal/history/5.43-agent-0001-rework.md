学习者读过 0001 后提了四条：循环没说清什么时候结束、记忆要按产品讲、翻车一节太空、工具一节没说透。逐条处理：

## 1. 循环什么时候结束、谁在转

- 0001 §4 加两个 h3：**「循环什么时候停」**（出口＝某次回复里没有工具调用；步数按调用模型的次数算；"停"不等于"做对了"）和 **「谁在转这个循环」**（供应商 API 是「一次调用换一次回复」，模型不带状态，转圈、执行工具、塞回结果、强制停都是 harness）。
- 补一段**伪代码**（不是可运行脚本，理论课仍不配脚本）：`messages`＋工具清单 → 调模型 → 没有工具调用就 return → 有就执行、塞回、再循环 → 走满步数 raise。要点：出口不是 `done` 动作，历史每轮重发，工具执行在壳里。

## 2. 记忆改成按产品看

- 旧写法先讲"按内容分／按来源时间分"两种分类，学习者说"不清楚"。改成四个真实产品的**存·取·管**：
  - **OpenCode**：不内置长期记忆；`AGENTS.md`／`CLAUDE.md` 规则文件每次进上下文，代码状态在 git 里。
  - **TeleAgent**（自述）：`USER.md`／`MEMORY.md`／`daily-log`，Markdown 文件；常驻注入＋关键词/正则；改口留痕、过期不删。
  - **Supermemory**：记忆 API；文档 → 块＋记忆图＋profile；updates/extends/derives、自动遗忘；按内容分 facts/preferences/episodes。
  - **Mem0**：抽成事实；SQL＋向量＋实体库；语义/关键词/实体/时间多路检索；默认 ADD-only。
- 研究的三分法降为"研究文献常这么分，产品不一定照这个分"；"没有统一标准"仍然是收口句。
- **口径教训**：Mem0 2025 论文写 ADD/UPDATE/DELETE/NOOP，现产品文档写 ADD-only——**论文和产品不是一回事**，引用必须说清哪一年的口径（写进 RESOURCES 的复核注）。
- 新增一键对照表（产品 × 存/取/管）；表格只是recap，细节在四条短段里。

## 3. 翻车一节整节删除

- 旧 §9"每一步会怎么翻车"（推理/行动/观察/不收尾）被学习者判为"正确的废话、都取决于模型能力，用户又不能做什么"。
- **删整节**，不换成最佳实践：可操作的失败处理已经在 0002（真模型实跑＋兜底）、0007（权限/人审）、0009（排查五类）里，0001 再列一遍只会把主线拖钝。
- 只在 §4"循环什么时候停"里留一句"停不代表做对了：提前收工/绕圈要靠 trace、结果、人审"——这是循环机制的一部分，不是泛泛的翻车清单。

## 4. 工具一节加强

- 先给**函数本体**（`def get_weather`），再说模型看不到函数、只看到**说明卡**（name/description/parameters）。
- 明确：**说明卡每一轮都随请求发出去**，工具越多每轮 token 越多；它是稳定前缀，能吃缓存，所以别中途增删。
- 加"自己写函数写到什么时候是个头"：不能复用（换应用/换 harness 要重搬）→ 每接一家重写（N×M 份适配）→ 工具一多管理全归你；由此引出下一课 MCP（标准插口）与 Skill（做法包）。

## 5.43.1 补「网页版和 harness 后台都是同一次请求/回复」（同日续）

学习者追加：受众只见过网页对话或 TeleAgent，直观感受得到差别，但不知道后台在调 API；要不要在开头说明？

- **加**，放在 §1「一次调用 ≠ 一个 agent」里，做一个小标题：**「不管网页版还是 harness，后台都是同一次『请求 → 回复』」**。
- 三句话：① 网页版／TeleAgent／你自己的脚本，后台都是"打包请求 → 调供应商 API → 拿回回复"；网页版替你打包，自己写程序要自己来（第 2 课真发）。② 请求里装：这句话、之前的对话、工具清单；回复：一段话或一组工具调用。③ 别把网页版和 harness 当两种模型——它们是两种壳；模型只负责这一次回什么，要不要调工具、要不要再问一次由壳决定。
- **不写死"网页版调的就是公开 API"**：厂商自己的 App 走内部通道，机制相同、通道不一定相同；课里只说"同一类请求/回复"。
- 顺手把"网页版没有手"改精确：网页产品可能有预置的搜索等能力，但**你没法把"订票"接进去**；差别三条里的"有没有手"改成"能不能用上你的工具"（只能用产品预置的 vs 能配自己的工具）。
- 放在 §1 而不是新开第 0 节：不改后面 2～9 的编号，也不打断"一次调用 ≠ agent"这一段的论证顺序。
- 同步：导读"学完你能"加一句；无新图、无新脚本；新增几段后 HTML 重新配平、链接重跑。
