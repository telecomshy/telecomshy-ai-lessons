# 5.66 「由浅入深」的口径澄清＋MCP/Skill 开场法对比实验

- 日期：2026-10-26（同日第二批）
- 触发：学习者看过 5.65 拆课稿后纠正——**"由浅入深"不是多写铺垫，是概念上由浅入深**：从初学者已有的感性经验出发（"这个概念我之前有没有见过"），先认出熟悉的东西，再往概念深处走。

## 一、口径澄清（推翻 5.65 里的一半理解）

- 5.65 的阶梯「痛点 → 画面 → 架构 → 机制 → 判断」是**写法顺序**，不是学习者的**认知顺序**。学习者的认知顺序是：
  **我见过它吗（感性经验）→ 它们看起来一样（承认感知）→ 为什么本质不同（概念分层）→ 机制 → 回看产品现象（感知被修正）**。
- 学习者给的具体案例：MCP 与 Skill 在初学者感知里**都是"工具"**——都是广场下载、装上 agent 变能干，"只是配置有所不同"；**TeleAgent 这类 harness 还把两者的区别抹平了**（都在技能广场装）。但本质差很大。课就应该从这个**真实的混淆**出发，而不是从抽象问题出发。
- ⚠ 此口径**尚未写进写作标准**——它与 5.65 的开场法正在对比中，学习者拍板哪种更好之后再入 `COURSE-STANDARD.md` 1.5。

## 二、对比实验（学习者指令：不覆盖原课件，写新的比）

- **两份草稿**（`internal/drafts/`，不动 `lessons/`，不进审计计数）：
  - `mcp-from-familiar.html`——从"你其实已经装过它"写起：装过的感性经验 → 认一认（和 Skill 像不像）→ 安家立命的概念分层（**MCP 给能力/动作，Skill 给做法**）→ USB-C 与协议机制 → 配置（"你在设置里粘的那段 JSON"）→ 边界 → 收口辨认法（怎么认出你装的是哪个）。
  - `skill-from-familiar.html`——从"你其实已经教过它"写起（反复粘同一段要求）→ 认一认 → 做法为什么能装（写成文件）→ 渐进式加载 → 跟做 → 判断（"要动作找 MCP，要做法找 Skill"）。
- 两课用同一根辨认主线互相咬合：**"装完看它多了什么——多动作是 MCP，多做法是 Skill"**；小测第一题就考辨认。
- 体量与原稿相当（MCP 7.6k 字 ≈25 分＋6 题；Skill 6.6k ≈21 分＋6 题），对比的是**概念阶梯**，不是长短。
- 素材口径：「两类扩展入口趋同（都在技能广场装）」标**学习者自述**（2026-10-26，已进 RESOURCES，与手册 2026-10-18 的"设置→工具设置"入口并存）。

## 三、5.66.2 第二稿修正（同日续写，学习者读过两稿＋盲测意见后三条拍板）

2. **使用者的感性经验是"能力出现"，不是内部机制**：原草稿开头"装之前 agent 会的就两样：说话、转循环"是**原理课的内部视角**——初学者不写 agent 代码，感知不到说话/转循环。学习者给的正解：**装之前不会查天气，装了就会查了；这个查天气的工具是别人写好的，你直接安装拿来用**。新稿 §1/§2 按此重写。

## 四、5.66.3 二稿第三轮修正＋AI 味的准确画像（次日）

- **AI 味＝设问/悬念/反转式包装**（学习者范式）：「先分清：本地 server，还是远程 server」→ 直接说「server 有两种：本地和远程」；「装天气工具有两种做法」→ 「TeleAgent 有两种方法可以安装 MCP 工具」；「"远程也是这么配"是误会」→ 「上面配的是本地 server，远程配置不一样」。**执行漏洞的教训**：此前自查只扫黑名单短语（"记住这个感觉"类），没逐句跑 1.5 判据（段头半句删掉后面不受影响＝废话）；且草稿大段继承原课文、被默认当"已验收文字"没重审。**AI 味自查要用判据，不要用黑名单；引用旧课文字＝默认重审。**
- **事实修正三件**（学习者口径）：**安装并启用**才创建连接（只装不启用，连接不建立、清单报不上来）；**server 可以理解为一个服务器**（启动起来等着被问、等着被调用），原解释过简；第 7 节**简写**——广场里除"应用连接"（MCP 工具）还有一种叫"技能"，技能与应用连接的区别**下一课**详讲（不在本课展开比较）。
- **按 5.66.2 的 A 案执行**（配置细节下沉）：新建 `internal/drafts/mcp-config-cheatsheet.html`（字段口径、本地/远程完整例子、**零基础版查错顺序**（终端/PATH/Node.js 白话）、给写工具的人五样）；理论课正文降到 5.3k 字，只留"配置长什么样、粘的是什么"一层＋速查入口。小修六项全落：叫法统一（应用连接/工具/server 首次出现即钉）、JSON/API/上下文半句解释、图注不抢跑术语、删 Function calling 术语链、math-server 与 server-everything 名字对不上处加注、Local/Hosted 与 host 撞脸处加区分。

## 五、教训

- **「由浅入深」要问清是给谁深**：给概念排阶梯（认知层递），不是给讲者排段落（铺垫堆量）。我上一轮按后者理解，写出来的还是"技术叙述＋更多引言"。
- 学习者说"从熟悉场景入手"时，"熟悉"指**学习者的经验**（他装过/见过的产品现象），不是指"生活化比喻"。两者都叫"熟悉"，落到课上完全不同。
- 对比实验的纪律：**不覆盖、不改原稿**；草稿放审计看不见的地方（`internal/drafts/`），比完再定去留。

## 六、5.66.4 三稿：场景引问题＋背景铺垫（2026-10-27）

- 学习者读二稿后给五条意见（都是结构与文字，不是事实错误）：
  1. **开场场景必须把问题带出来**：二稿开头「技能广场点安装、天气查出来了」把接工具说得太容易，跟 §2 的问题对不上——场景不引出问题，MCP 就出不来。换成「你写了个工具要发给同事，他的产品装不上」（每家接法不一样 → N×M）。
  2. **文字仍是总结式短语，不像文章**：点名句「这课就讲这个『接』」「Anthropic 在 2024 年发布 MCP 时说的就是这件事」「只装不启用，连接不会建立，工具清单也报不上来」「连接建好后，先报到再干活」「每次要带的工具清单越长，费用和互相干扰都跟着涨」。全篇按 1.5 句子层重写成通顺句子（同 5.57 口径）。
  3. **缺铺垫**：开头要交代「工具有很多种，MCP 是其中一种（TeleAgent 的应用连接属于这一种），每种机制不一样」，否则初学者分不清技能和应用连接。
  4. **知识点顺序**：「工具清单」要到连接交互那节才建立，不能在安装节就抛「清单报不上来」。顺序定为：背景 → 安装两种方式 → 架构 → 连接交互 → 本地/远程 → 配置 → 去哪找。
  5. **安全内容撤出本课**（MCP 和技能都有的问题，归 0006）；**第 7 节（技能对比）删掉**，结尾一句话引下一课：工具有很多种，还有一种是技能；MCP 给能力，技能给做法。
- **三稿 `internal/drafts/mcp-v3-problem-first.html`**（九节 4.6k 字＋6 题）：场景→问题→USB-C/协议 → 背景（自己写的函数／MCP 工具／技能三类，应用连接=MCP）→ TeleAgent 两种安装（含启用）→ 三角色＋图 → 启用之后发生什么（发现/工具清单/调用；「只装不启用」移到这里）→ 本地/远程（表）→ JSON 配置＋五步 → 三个广场＋装多少的判断＋安全一句指 0006 → 小测 → 结尾引技能。**安全正文移出**（落回 `lessons/` 时并入 0006）。
- 二稿原件备份 `backup/mcp-draft-v2-20261027/`；一稿 `mcp-from-familiar.html` 留档不动，对比件链不覆盖。
- 教训：**场景的职责是把问题带出来**，不是展示功能——「装上就能用」的开场教不了「为什么需要 MCP」。**词汇先建立再使用**（工具清单、发现都先出现，断言后挂）；被点名的句式要按同类查全篇，不是只改那一句。

## 七、5.66.5 文字返工：照 se-lessons 的文章质感重写（2026-10-27 同日续）

- 学习者读三稿仍嫌「AI 味十足」，点名参照 `E:/code/my_projects/telecomshy-se-lessons/lessons/0001-what-is-software-engineering.html`（**文章体标准的源头**，5.51 就是从它引入的）写成文章。
- **差距诊断**：三稿的段落是「断言＋解释」的模板节奏，加包装腔（「记住一条主线，后面就不会晕」「先认识它们，再看……」「先报到再干活」式口诀、「卡住的不是你的工具，是……」式对仗）；参照文是**有时间、有人、有数字的叙事**（「2023 年，你写了一个 40 行的脚本」「财务每月用一次，市场每周用一次，实习生改过两次路径」），句子直陈、段落承接都带内容、标题是叙事节拍（「一个脚本的三年」「同一个词，两种工作」）。
- **做法**：开场改成有细节的场景（上个月／40 行 Python／同事换产品／对接写了三遍）；标题全部换成叙事节拍（「一个工具，三份对接」「『工具』这个词底下有三种东西」「连上以后，它先报自己会什么」）；删两个装熟的框标签（goal「先别急着学，聊两句」、note「记住一条主线，后面就不会晕」）；口诀与对仗句改直陈；承接句都带内容（「下面两节拆开那条连接：先看它连着什么，再看连上以后发生了什么」）。**结构与知识点顺序不动**（仍按 5.66.4 的排法）。改前二存 `backup/mcp-draft-v3-20261027/`。
- 教训：**文章体的标尺是参照文本身，不是「洗掉黑名单词」**——句子层洗完还是 AI 味，是因为「断言＋解释」的段落模板没换掉。要对着 se-lessons 的原文逐段比质感：这段有没有具体的人、时间、数字；这句删掉后文受影响吗；承接句带不带内容。

## 八、5.66.6 两条补充：配置是通用接法＋resources/prompts 进正文（2026-10-27 同日续）

- 学习者两条意见：① 第 7 节要讲清「TeleAgent 应用连接可以直接安装，也能在设置里用配置装；**大多数其它 harness 软件只有配置这一种接法**」，配置要额外介绍；② MCP 不只工具，还有 resources（能读的数据）和 prompts（提示词模板），眼下用的人少，问要不要简单介绍。
- **落法**：§3 预告「配置是通用做法」；§7 开头给定位句——OpenCode 把 MCP 写进配置文件、Claude Desktop 读 `claude_desktop_config.json`，都没有「点安装」，TeleAgent 技能广场是替用户走完这步的便捷层，「所以这段 JSON 值得看懂：换一个 harness 软件，你要写的就是它」；加字段名差异一句（TeleAgent 用 `mcpServers`、OpenCode 用 `mcp`）。**resources/prompts 从「想深究」注释框提升进 §5 正文**（工具／resources／prompts 三样并列，眼下用得多的是工具），注释框只留 JSON-RPC／无状态／订阅。
- **判断（学习者问「要不要介绍」，答：要，而且放正文）**：不写会让读者把「MCP＝工具」当成定义；MCP 是「server 公布三样东西」，工具只是眼下用得最多的那一样。两三句防得住错的概念模型，就值得占正文。
- **事实核验**：OpenCode `mcp-servers` 页（2026-10-27 抓）证实配置接法（`mcp` 字段、local `command` 数组、remote `url`＋`headers`）＋官方 token 提醒；Claude Desktop 的 `claude_desktop_config.json` 公开文档多处记载（未抓一手页，已在 RESOURCES 标注）；「大多数 harness 用配置」记为学习者口径＋佐证。两条均已入 RESOURCES。
- 教训：**「用的人少」不是「不写」的理由，「写多细」才是**；「大家都这么做」这类产品接法断言，要落到具体产品的文档上再写进课。
