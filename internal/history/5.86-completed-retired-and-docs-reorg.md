# 5.86 `completed` 退役＋辅助文档重整

## 背景

2026-11-17，学习者提出四件事：所有课程不再标 `completed`；辅助文档（`internal/rules`、`NOTES.md` 等）职责不清，需要重新规划；`NOTES.md` 里的过期待办与历史索引要清出去；课程已开发完，考虑把「开发标准」与「修改标准」分开。

约束：课程基于 teach 技能开发，改动不能与 teach 冲突。teach 的硬要求只有：`NOTES.md` 继续存在，用来记学习者偏好与约定；`MISSION.md`、`RESOURCES.md`、`lessons/`、`assets/`、`reference/`、`learning-records/`（本仓库改道 `internal/learning-records/`）继续在位。

## 决定

### 1. `completed` 全部退役

- **目录页**：`lessons/index.html` 与文字稿 `lessons-md/index.md` 删除所有徽章、`pillar completed`、进度三档说明。
- **README**：删除「课程进度怎么标记」整节与课程表里的 `<code>completed</code>`。
- **主页**：根 `index.html` 删除「19 门已定稿」stat。
- **样式与工具**：`assets/base.css` 删除 `.pillar.completed`／`.badge`；`tools/html2md.py` 删除 badge 特判；`tools/progress.ps1` 删除 mark/unmark 与「三处落点」检查，改为只读审计。
- **规矩**：`internal/rules/mark-completed.md` 删除；`PROCESS.md` 与 `REVISION.md` 明确「没有定稿课受保护这一档」。
- 理由：学习者不再需要「哪些课是人改过的」这层信息；继续维护徽章与三处计数只会制造漂移。历史存档里的 `completed` 字样保留原样，它们是当时决策的证据。

### 2. 辅助文档按「一类信息一个落点」重整

| 文件 | 职责 |
|---|---|
| `AGENTS.md` | 入口路由与文件职责表 |
| `NEXT-SESSION.md` | 当前进度、下一步、长期欠账、待确认 |
| `NOTES.md` | teach 的学习者画像与教学偏好（不再放流程、待办、历史） |
| `internal/standards/PROCESS.md` | 取材、交付核验、开发一课、文档写入纪律 |
| `internal/standards/COURSE-STANDARD.md` | 页面零件、课型、讲法、互链、交付检查单 |
| `internal/standards/ARTICLE-STYLE.md` | 正文文章体 |
| `internal/standards/REVISION.md` | 改课／精修流程（新增） |
| `internal/standards/tracks/*` | 各轨分版、受众、课型标识、脚本分层 |
| `internal/playbooks/*` | 具体操作手册（联网、改课件、学习审计） |
| `internal/history/INDEX.md` | 历史存档索引（从 NOTES 第 5 节迁出） |
| `internal/history/archive/` | 已执行完的蓝图（Agent 重构蓝图迁入） |

- `internal/rules/` 改名 `internal/playbooks/`：它装的从来不是「规则」，而是「照着做」的操作细节。
- `NOTES.md` 257 行 → 60 行：流程进 `PROCESS.md`，历史索引进 `INDEX.md`，待办只留 `NEXT-SESSION.md`。
- `COURSE-STANDARD.md` 1.5 的「改课：基于整篇」整段移入 `REVISION.md`，原处只留一句指针；通用标准本身不劈成两份。

### 3. 开发标准与修改标准怎么分

**结论：新增 `REVISION.md`，通用标准不动。**

- `COURSE-STANDARD.md` 继续管**所有课共用的结构**：零件、课型、讲法、互链、交付检查单。
- `REVISION.md` 专管**已有课的改动**：md 底稿、对拍、备份、表现层回写、整篇原则、核验边界。
- 不把 `COURSE-STANDARD` 劈成「新建版／修改版」两份：公共部分会重复维护，改一处要同步两处。

### 4. 审计脚本

`progress.ps1` 改为只读六段：A 卡片链接／B 主页 stats／C RAG 三链／D 进阶版别名与问数／E 文档卫生（含 completed 防回潮、标准存在与体量、历史索引双向一致、playbooks 存在）／F md 断链。阈值：NOTES 120 行、PROCESS 160、COURSE-STANDARD 200、ARTICLE-STYLE 200、REVISION 140、INDEX 200、轨道 120。

## 与 teach 的关系

- `NOTES.md` 保留，且内容回到 teach 的原意（偏好与约定）。teach 不要求 `completed`，退役不冲突。
- teach 的目录约定继续有效：`lessons/`、`assets/`、`reference/`、`MISSION.md`、`RESOURCES.md`、`learning-records/`。本仓库把后者放在 `internal/learning-records/`，已在 `AGENTS.md` 登记。
- 新增的标准与 playbook 通过 `AGENTS.md` 会话入口带进上下文，不需要 teach 认识它们。

### 5. 顺手修掉 html2md 的假只读

`html2md.py --check` 原实现是「先全量写 md，再校验」，与 README 和流程里的「只读」承诺不符。本轮整理时实跑一次，覆盖了 `lessons-md/` 全部文件；靠 OpenCode 快照恢复了 `agent/0003` 的文字稿，其余文件只差一行重复的 meta。现在 `--check` 真正不写文件；md 领先于 HTML 时校验会报待回写，属正常状态。同时删掉 `lesson-meta` 在正文里的重复渲染。
