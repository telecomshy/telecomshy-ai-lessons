# 5.50 0004 补「派子代理」最佳实践：审计、TeleAgent、OpenCode

- 日期：2026-10-19
- 触发：学习者要求在第 4 课加“什么该派/不该派”的最佳实践，特别是代码审计——主代理会偏向自己写的代码，适合派子代理；并说明不同 harness 实现不同，用 TeleAgent 和 OpenCode 举例教用户怎么派。
- 结论：在“怎么分工”后新增 §3「什么时候该派：审计是最好的例子」，不是单开一课。

## 内容

1. **该派**：代码审计/安全 review（主代理确认偏差，子代理独立上下文、只读）、多来源调研/事实核查、方案对比/反方视角、大材料/长任务。
2. **不该派**：三五个工具调用的小活、强顺序依赖、共享状态/频繁互改、最终责任/高风险决策。
3. **派单模板**：目标/范围/输出（文件:行号/风险/触发条件/建议）/边界（只读、不参考主代理自我解释、不确定标人工确认）/纪律（只回结论、失败重派）。
4. **不同 harness 的派法**（表）：
   - **TeleAgent**：主 agent 自动委派；这版手册只有任务监控「任务委派＝子智能体执行过程」，没有点名入口；用户能做的是把任务写成几路独立活，观察是否派；不能保证一定派。
   - **OpenCode**：primary/subagents；主 agent 可按 description 自动调用，也可手动 `@general`/`@explore`/`@scout`；自定义 agent 后 `@name`；自然语言也能触发，但 @ 更稳定。
5. **示例**：审计 prompt、TeleAgent 三路并行 prompt、OpenCode @ 示例；强调审计只读、修不修回主流程。
6. 小测 8→11：加 Q9 审计为什么适合派、Q10 TeleAgent 怎么派、Q11 OpenCode 怎么稳定点名。
