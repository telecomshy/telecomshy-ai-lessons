# 5.49 修正「长任务」写法：先讲压缩，再讲交接

- 日期：2026-10-18
- 触发：学习者说「第 4 节长任务我没遇到过；用过的 harness 都是快超上下文就压缩会话」，并问内容出处。
- 判断：学习者的体验是对的。**压缩是主流 harness 的用户可见行为**；「长任务 / long-running agents」是 Anthropic 的工程术语，不是产品菜单里的功能。原稿把它写得太像通用功能，确实容易让人以为「我的 harness 没有这个」。
- 出处：Anthropic《Effective harnesses for long-running agents》（2025-11-26）明确说 **compaction 不够**，并给 initializer/coding agent、feature list、progress、git、端到端测试的工程做法；Learn Harness Engineering 的 State/Verification/Scope/Session Lifecycle 也支撑这套拆法。

## 改法

- 第 4 节标题从「长任务：harness 怎么让 agent 跨会话继续干」改为 **「上下文快满时：压缩、清空，还是交接」**。
- 先讲用户真正见到的：界面提示上下文快满 → 自动摘要/压缩，或者清空。
- 加一张策略表：压缩摘要 / 裁旧工具结果 / 清空或新会话 / 外置状态交接——各自适合什么、代价是什么。
- 明确：**压缩解决「装得下」，不解决「接得上」**。
- Anthropic 的 initializer/coding、feature list、progress、git、验证，降为「任务跨很多窗口时才要加的码」，并标注 **来自 Claude Agent SDK / Claude Code 的工程实践，不是所有 harness 都提供**。
- 小测 Q4 改成「跨过多个上下文窗口时，为什么除了压缩还要留状态文件」，答案落在「压缩 vs 交接」。
- 目标句从「长任务怎么跨会话接上」改为「看懂压缩和交接的区别」。

## 不变

- 公式、五子系统、task-harness fit、四款产品对照、按场景选、隐性成本均保留。
- 12 题；31 门 / 19 基础 / 21 脚本（无脚本变动）。
- 来源补在课内：Anthropic 长任务 harness、Learn Harness Engineering；RESOURCES 已有条目。
