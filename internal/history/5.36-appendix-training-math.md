背景：学习者读第 0 课 / 第 9 课时**反复卡在同一处数学**（换了几种问法：「扣分值是 dL/dw 的结果吗」「w=2、L=4 怎么求导」「扣 8 分会不会比扣 2 分拧得狠」「导数里没损失值怎么知道方向对不对」「要不要新值减旧值」），属 1.4 里「理解型、等提问」的典型——等到了真提问才写。据此开一份**理论附录**，把第 0 课「算扣分→拧→反向传播」那格的数学摊开。

- **「附录」是一类新内容，三不像，单独立区**：落 `lessons/llm/appendix-*.html`，目录页里 LLM 进阶版之后单独一个「附录」区（标「不占课号、不属于正式课程内容」）。判据：**它给推导和算式，所以不是基础课**（基础课「给结论和直觉，不给推导」）；**它不是某课的 `-deep`，所以不是进阶版**；**它是教学正文，所以不是 `reference/` 速查**。⚠ 命名 `appendix-` 前缀是硬约定——下一条计数规则靠它识别。
- **附录不进「门课 / 脚本」主线计数**：`progress.ps1` 的文件计数（`$lessonFiles` / `$nPy`）过滤掉 `^appendix-`，所以主页那几个数（25 基础 / 12 进阶 / 37 门课 / 28 脚本 / LLM 10 门基础）**保持准确、只数正式课**，附录是计数之外的延伸。⚠ **这是新约定，动 `appendix-` 文件或主页计数时留意**——若哪天想把附录算进课数，改的是 progress.ps1 那两处过滤、不是手改主页数字。目录页卡片不被 progress 计数（它数文件不数卡），所以加附录卡不影响任何一段 audit。
- **教学口径（拧多少的机制）**：**损失值（扣分）不进更新算式**；`新权重 = 旧权重 − 学习率 × 斜率`，**拧多少 = 斜率 × 学习率**。「扣分多就拧得多」是**经验观察**（扣分多的地方多半坡也陡），机制上拧多少看斜率不看扣分数——两句不矛盾、分属经验层与算式层。**反向传播传的是「每个权重各自的斜率」，不是扣分数**；损失值只当进度尺子 ＋ 反向传播的起点（前向算出当前位置斜率才有起点）。**求导的对象是「公式」不是「两个具体的值」**：对 `L=f(w)` 求导得 `f′(w)`，再把当前 `w` 代进去；「对权重=2 求导」是不完整的说法。术语表新增 `#gradient`（求导/斜率/梯度/学习率）。
- **两个数是两个 4 的巧合**：`L=w², w=2` 时损失 4、斜率 4（都由 2²=4 与 2×2=4 巧合撞上）；换 `w=3` 就分成损失 9、斜率 6。图 `assets/loss-slope.svg`（海拔 vs 坡度）画的就是这件事。
- **脚本 `exercises/llm/appendix-training-math.py`**：用 `L=w²` 演示「损失值 / 斜率 / 这一步拧多少」三个数摆一行，[1] 两个 4 是巧合、[2] 扣分大不大不决定拧多少。⚠ **踩坑**：Windows Python stdout 默认 GBK，打不出 `²` / `−`(U+2212) / `⚠` / `×`，docstring 里也不行（`print(__doc__)` 会炸）——**脚本里全改 ASCII**（`^2` / `-` / `!!` / `*`）。与 NOTES 1.7「带中文参数的 PowerShell 替换脚本会静默写坏文件」同族的编码坑，但这次是 Python 打印侧。
