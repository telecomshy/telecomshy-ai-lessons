MCP：给工具定一个统一插口

你给自己的 agent 写了个查天气的小工具，40 行 Python，跑得挺好。同事看了也想要。你把文件发过去，他装不上：他用的是另一款 agent 软件，装工具的地方不一样，认的格式也不一样。

你照着他的文档改了一遍对接。没过多久，他又换了一款，你又改一遍。工具还是那个工具，对接已经写了三遍。MCP 要解决的，就是让这件事只做一遍。

学完这课，你能：说清装一个 MCP 工具时发生了什么；看懂配置里每一行在说什么；知道去哪找别人写好的工具，也分得清它和「技能」不是一回事。

MCP 是给工具定的统一插口。装一个 MCP 工具，就是让 agent 多接上一个别人写好的程序。

1. 一个工具，三份对接

问题出在「接」这一步。你手里一个工具，要装进三个产品，就得写三份对接；四个工具装进三个产品，就是十二份。工具和产品再多一些，这份活就看不到头：每一份都要单独维护，对方一改接口，你就得跟着重写。

Anthropic 在 2024 年 11 月发布 MCP，要解决的就是这件事。发布文里说得很直接：每接一个数据源都要单独写一套对接，真正能连起来的系统因此铺不开（原文 "Every new data source requires its own custom implementation"）。

MCP 的做法，是给工具定一个统一插口。MCP 项目的文档拿 USB-C 打比方：MCP 之于 AI 应用，就像 USB-C 之于电子设备。USB-C 统一了怎么插，MCP 统一了怎么接。

它的全名是 MCP（Model Context Protocol，模型上下文协议），一套开放标准，谁都能照着实现。

插口定下来，工具只要写一次。任何支持 MCP 的产品都能装，同事再换产品，你也不用重写第二遍。

2. 工具从哪儿来

不过，不是所有「工具」都能这样共用。agent 能用的工具，来路主要有两种。

一种是你自己写的函数。上一课那种：写一段 Python，再写清它叫什么、干什么、要什么参数，agent 就会调它。它只活在你自己的程序里，发给同事就用不了。

另一种是 MCP 工具。写工具的人把它做成一个独立的服务程序，按 MCP 的规矩报出自己会什么。任何支持 MCP 的产品都能接，接法都一样。你那个查天气的工具，做成这种就发得出去。

TeleAgent 的技能广场里，MCP 工具放在「应用连接」下面。广场里还有一类叫「技能」，装进去的不是工具，是一份做事的方法。两样装完，agent 都更能干，但多出来的东西不一样：应用连接多一个会干活的程序，技能多一份做事的办法。这课只讲 MCP。

3. 在 TeleAgent 里装上它

在 TeleAgent 里装 MCP 工具有两种办法。一种是在技能广场找到「应用连接」，点安装；另一种是打开「设置 → 工具设置」，粘一段 JSON 配置。JSON 是一种有固定格式的文本，照着填就行。两种办法装完，都要再点一下启用。

启用之后回到对话，说「查一下北京天气」，它就能查出来。装之前说同样的话，它只会说查不了。模型并没有学会新知识，只是手里多了一个能用的工具。

从你说出那句话，到拿到查询结果，中间隔着一条连接。这条连接上有三个角色。

4. 三个角色，一条连接

host 是你正在用的那个 AI 应用。在这里，它就是 TeleAgent：你打开它，在对话框里打字，连接和工具都由它来管。

server 是工具背后的服务程序。它启动起来以后，等着被问「你能干什么」，也等着被调用。它可能跑在你的电脑上，也可能跑在服务商那边。

client 是中间那个连接件。host 每接一个 server，就在内部配一个 client，一条连接对一个 client。装好就有，不用你写。

5. 连上以后，它先报自己会什么

连接建好之后，client 先问 server 一句「你能干什么」。这时候还轮不到干活。

server 回一份工具清单：每样工具叫什么、干什么用、要填哪些参数，一条条列清楚。清单会进上下文（模型这一次能看到的全部内容），模型才知道自己手里有哪些工具。

你说「查一下北京天气」，模型从清单里挑出天气工具，填好参数发过去。server 执行完把结果送回来，模型再把它组织成一句回答。

连上先问一遍「你能干什么」，这一步叫发现。普通 API 不走这条路：工具的名字、说明、参数要你逐个整理好，随请求一起发给模型。MCP 的工具是连上以后自己报出来的，清单变了还能刷新。

启用只是把这份清单登记到 host 里，模型这时候还没看见。你第一次提问，host 才把当前启用的工具（名字、说明、参数）随这次请求一起发给模型；之后每轮都重新带一遍，不是启用时写一次、后面一直引用。

server 报的不只是工具。它还能公布 resources，也就是它能读的数据：文件、数据库记录，agent 要用就直接取；以及 prompts，写好的提示词模板，拿来就能发给模型。

一条 MCP 连接主要给你三样东西：工具、resources、prompts。眼下用得最多的是工具，另外两样见到的机会少，知道它们也归 MCP 管就够了。

所以装好之后那一下「启用」不能省。不点，连接不建立，发现和调用都不会发生。

想深究再看，跳过不影响后文

client 和 server 一问一答的格式叫 JSON-RPC 2.0（请求带方法名，回结果）。协议是无状态的，每个请求自带版本和能力，server 不靠「上一次连接」猜。工具清单可以订阅，增删时通知连接件刷新。

6. 两种 server，跑的地方不一样

server 分两种，看它跑在哪。本地 server 跑在你的电脑上，靠配置里的命令把它启动起来。远程 server 跑在服务商的服务器上，你连过去就行。MCP 广场给每个 server 标 Local 或 Hosted，标的就是这件事。跑的地方不同，配置里要填的东西也不同：

本地 server 远程 server
跑在哪 你的电脑上，由配置里的命令启动 服务商的服务器上
配置填什么 command + args，key 放 env URL + 鉴权（证明你有权用这个服务的凭据）
怎么启动 用 npx / uvx 这类命令把工具包拉下来跑 不用启动，填 URL 连过去就行

本地配置里要写启动命令，远程配置里要写地址和鉴权。你粘的那段 JSON，填的就是这两类东西。

7. 你在粘的那段 JSON

写配置文件是 MCP 的通用接法，MCP 项目的文档就是这么教的：在应用的配置文件里写一段 JSON，告诉应用怎么启动这个 server，或者怎么连上它。

TeleAgent 的技能广场把安装做成了一个按钮，但按钮背后做的还是这件事：往配置里写一段 JSON。

OpenCode 没有这个按钮，你得自己把配置写进它的配置文件；Claude Desktop 读的是 claude_desktop_config.json。换一款软件，要写的还是这段 JSON，只是文件名和字段名可能不一样。

本地 server 的配置长这样（例子来自 TeleAgent 手册）：

{
  "mcpServers": {
    "math-server": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-everything"]
    }
  }
}

math-server 是服务名，自己起，不必跟包名一样。command 是启动命令，args 是传给命令的参数。例子里的 server-everything 是 MCP 项目仓库里的测试工具包，装它就是为了连上以后马上有东西可试。字段名各家不完全一样：TeleAgent 用 mcpServers，OpenCode 用 mcp，换一款软件就照它自己的文档填。

在 TeleAgent 里配，按它 2026-10-18 的手册是五步：

  1. 头像浮窗 → 设置 → 工具设置 → 从 JSON 导入/添加。
  2. 粘贴上面的 JSON（根对象要有 mcpServers），保存。
  3. 看状态：连上的 server 会显示绿色的「已连接」；首页的 MCP 按钮能看到正在用的 server。
  4. 工具列表里可以连接 / 断开 / 编辑。工具改过名字之后，旧任务里记的还是旧名字。
  5. 回到对话，说「算一下 2+3」，它会先发现工具，再调用。

远程 server 的配置是另一副样子：填 URL 和鉴权，没有 command 和 args，也不用 npx。字段的完整说明、远程配置的完整例子、配置弄错了按什么顺序查，MCP 配置速查里都有。

8. 去哪找别人写好的工具

工具不必都自己写。大多数时候，别人已经写好了。国内常用的入口有三个（2026-10-18 看，产品会变）：

  • 腾讯云开发者 MCP 广场（cloud.tencent.com/developer/mcp）：腾讯自己的和第三方的 server 都有，每个都标了 Local 还是 Hosted。
  • 阿里云百炼 MCP 广场（文档）：详情页能复制接入配置，用它给的 key 鉴权。
  • ModelScope 魔搭 MCP 广场（modelscope.cn/mcp）：社区 MCP，按页面给的配置接。

广场里标的 Local 和 Hosted，就是第 6 节说的 server 跑在哪。它们跟 host 不是一回事，host 是你在用的那个 AI 应用。

工具不少，但别贪多。每个工具都会进工具清单。清单越长，每次请求要带上的内容越多，费用也跟着涨；工具一多，全挤在同一个上下文里，还会互相干扰。

成本怎么算，上一课讲过；干扰是怎么回事，LLM 底层第 3 课讲过。三个工具、自己用、只在一份脚本里跑，直接写函数最省事。同一个工具要给多个产品用，或者你想把它交给别人用，才值得做成 MCP。

装之前还要想清楚安全。工具接进来以后，用的是你的用户权限：你读写得到的东西，它也读写得到。来源怎么判断、权限怎么收窄，Agent 篇 · 第 6 课 · 提示词注入与护栏专门讲。
