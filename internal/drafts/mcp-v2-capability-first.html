MCP：给工具定一个统一插口

先别急着学，聊两句

在技能广场里找到天气工具，点安装、启用，回到对话里说"查一下北京天气"——它查出来了。装之前你说这话，它说查不了。

会查天气的这个工具是别人写好的程序，你直接安装拿来用。模型没有学会新知识，它多了一个能用的工具。

学完这课，你能：说清安装一个 MCP 工具的时候发生了什么；看懂配置里每一行在说什么；知道去哪找现成的工具、怎么判断它可信。

记住一条主线，后面就不会晕

MCP 装进去的是别人写好的工具。插口统一了，装上就多一个能力。

1. 一开始它不会查天气

你第一次让 agent 查天气，它说查不了，它手里没有这个本事。装上天气工具，再问一遍，查出来了。中间你没教它任何东西。

变的是它手里多了一个工具。工具是别人写好的程序：天气工具知道怎么问天气服务、怎么把结果拿回来。你的 agent 接上它，就有了查天气的能力。

你在产品里做的几步，下载、点安装、启用，干的是同一件事：把工具接上。这课就讲这个"接"。

2. 各家工具的接法不一样

工具是别人写好的，直接装上就行。麻烦在每家工具的调用格式不一样。你的 agent 想用四个不同来源的工具，就要写四套对接；三个产品都接这四个工具，就是十二份对接。工具越多、产品越多，这件事越做不完。

Anthropic 在 2024 年发布 MCP 时说的就是这件事：每接一个数据源都要单独写一套对接，真正连得起来的系统根本铺不开（原话 "Every new data source requires its own custom implementation"）。

解法是给工具定一个统一插口。官方文档给的画面：MCP 之于 AI 应用，就像 USB-C 之于电子设备。USB-C 统一了"怎么插"，MCP 统一了"怎么接"。它的名字是 MCP（Model Context Protocol，模型上下文协议），一套开放标准，也就是公开发布、谁都能照着实现的统一约定。

插口统一之后，工具写一次，任何支持 MCP 的产品都能装。你在 TeleAgent 里装的天气工具，同事换一个软件也能装它。

3. 安装并启用，你创建了一条连接

TeleAgent 有两种方法可以安装 MCP 工具：在技能广场里找到应用连接、点安装；或者在设置 → 工具设置里导入一段 JSON 配置。JSON 是一种固定格式的配置写法，照着填就行。装好并启用，你就创建了一条 MCP 连接。只装不启用，连接不会建立，工具清单也报不上来。

你知道底层发生了什么吗？这条连接把三样东西连在一起：

  • host：你用的 AI 应用，也就是 TeleAgent。
  • server：你装的那个工具背后的服务程序。server 可以理解为一个服务器：它启动起来之后，等着被问"你能干什么"、等着被调用。它可能跑在你电脑上，也可能跑在服务商那边。
  • client：连接件。host 给每个 server 配一个，装好就在那儿了，不用你操心。

连接建好后，先报到再干活。连接件问 server"你能干什么"，server 把工具清单交回来：每样工具的名字、说明、要填什么参数，一样一样列清。清单进了上下文（模型这一次能看到的全部内容），模型才知道自己手里有哪些工具。你说"查一下北京天气"，模型从清单里挑出天气工具、填好参数发过去，server 执行完把结果送回来。三步：先问它会什么，把清单给模型，模型挑一个调。

连上先问一遍"你能干什么"，这一步叫发现。普通 API（一家家单独对接的接口）得先把工具一个个写进提示词里；MCP 的工具是连上后自己报出来的，工具增删了，清单还会更新。

想深究再看，跳过不影响后文

连接件和 server 一问一答的格式叫 JSON-RPC 2.0（请求带方法名，回结果）；协议是无状态的，每个请求自带版本和能力，server 不靠"上一次连接"猜。除了工具，server 还能公布 resources（能读的数据，比如文件、数据库记录）和 prompts（现成的提示词模板）。工具清单可以订阅，增删时通知连接件刷新。

4. 你在粘的那段 JSON

配置是给 TeleAgent 这类应用看的：告诉它怎么启动或者连上这个 server。

server 有两种。本地 server 跑在你电脑上，由你的电脑把它启动起来；远程 server 跑在服务商的服务器上，你只要连过去。这两种的配置不一样：

本地 server 远程 server
跑在哪 你电脑上，配置里的命令把它启动起来 服务商的服务器上
配置填什么 command + args，key 放 env URL + 鉴权（证明你有权用这个服务的凭据）
要 npx 吗 常见 npx / uvx 启动 不要

下面是本地 server 的一份配置（例子来自 TeleAgent 手册）：

{
  "mcpServers": {
    "math-server": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-everything"]
    }
  }
}

math-server 是服务名，自己起；command 是启动命令；args 是传给命令的参数。例子里的 server-everything 是官方的测试工具包，装上它是为了连上就能试。

在 TeleAgent 里配（按它 2026-10-18 的手册）：

  1. 头像浮窗 → 设置 → 工具设置 → 从 JSON 导入/添加。
  2. 粘贴上面的 JSON（根对象要有 mcpServers）→ 保存。
  3. 看状态：连上的 server 会出现绿色的「已连接」；首页的 MCP 按钮能看到正在用的 server。
  4. 在工具列表里可以连接 / 断开 / 编辑。工具名改过之后，旧任务里记的还是旧名字。
  5. 回到对话，直接说"算一下 2+3"——它会先发现工具，再调。

上面配的是本地 server。远程 server 的配置不一样：填 URL 和鉴权，没有 command 和 args，也不用 npx。字段的完整口径、远程配置的完整例子、配置弄错了怎么查，都收在 MCP 配置速查。

5. 去哪找现成的

不用自己写工具。下面是国内常用的入口（2026-10-18 看；产品会变）。广场里每个 server 会标 Local 或 Hosted：标 Local 的跑在本地，要先启动一个程序；标 Hosted 的跑在服务商那边，填 URL 就能连。这两个词说的是 server 跑在哪，和第 3 节的 host（你用的应用）不是一回事。

  • 腾讯云开发者 MCP 广场（cloud.tencent.com/developer/mcp）：腾讯官方加第三方的 server，每个都标了 Local 还是 Hosted。
  • 阿里云百炼 MCP 广场（文档）：详情页能复制接入配置，用它给的 key 鉴权。
  • ModelScope 魔搭 MCP 广场（modelscope.cn/mcp）：社区 MCP，按页面给的配置接。

安装前问三句：格式对得上吗（本地还是远程？）· 要什么权限（API key、本地文件、云账号？）· 来源可信吗（本地 server 以你的用户权限跑）。

6. 用它的边界

本地 server 以你的用户权限运行：你读写得到的东西，它也读写得到。接进来之前把关三条：只用可信来源的 server，不明来源的配置和命令先别粘；只给它需要的目录和数据库，不用的工具断开；key 放 env，不写进对话，也不留在代码里。

什么时候不值得用 MCP？三个工具、自己用、只在一份脚本里跑，直接写函数最省事。MCP 的价值在复用和发现：多个产品要接同一个工具、或者想把工具交给别人用时，才值得多这一层。接得越多，每次要带的工具清单越长，费用和互相干扰都跟着涨。
