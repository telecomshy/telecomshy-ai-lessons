### 1.2 一课的结构（必备零件清单）
一个自包含 HTML，放在 `./lessons/<轨道>/`，命名 `0001-xxx.html`（编号细则见 1.6 与各轨标准）。**必含**：

| 零件 | 说明 |
|---|---|
| **meta 行** | `<div class="lesson-meta">`，内容是 `轨道 · 第 N 课 · 课型标识`。课型标识（LLM：`初学版｜进阶版`；Agent／RAG：`理论`／`实操`）与编号特例**以该轨标准（`tracks/`）为准**。**deep 页必须再带一个 `data-alias="别名"`**——它是别名的**唯一落点**，目录页卡片、`<title>`、README 全部从它派生（NOTES.md 1.7 的 E 段核一致性）。⚠️ **别名若以中文数字开头，按约定那个数字就是「带编号的问」的个数**（「十一个追问」「六个绕人的细节」），E 段会拿它跟实际问数对——所以别让别名以一个不表示问数的数字开头 |
| **subtitle** | **仅 deep 页带**（deep 是「问题＋详解」体例、没有 goal，subtitle 就是它的开门引子）：一行定位——薄层课讲了什么、这篇答哪几个更细的问、按需跳读。**有 goal 的课（LLM 基础课／Agent·RAG 理论课与实操课／附录）一律不放 subtitle**；定位类信息（先导、阅读约定、使用时机）写进 goal 尾段。2026-10-23 学习者拍板，全库 21 文基础课 subtitle 已删（场景／立场句与 goal、note 重复直删，定位句迁移；存档 5.58） |
| **钩子** | `goal` 框开场：日常好奇的提问 → 拆穿"其实很简单" → 说清学完能干嘛。**别一上来就讲知识。** ⚠ **读者问出来的那个问题，钩子里就要当场答掉**——不是留到正文（"拆穿"那一步给的正是那个答案的大白话版）。判据：把钩子单独给一个没读正文的人看，他能不能用自己的话说出那件事。（反例见存档 5.16.1） |
| **主线 note** | 一句话把全课串起来；后面每节都能挂回它 |
| **正文** | 分节，每节短。概念密度高的地方拆成小步 |
| **图** | 至少 1 张。**文字讲不通就配图**（跨层、跨位置的数据流向，文字版会连卡多次）。一图一事 |
| **动手** | 配套可运行脚本 + **实测输出**（贴进课里）。**脚本怎么按课型分层，以该轨标准（`tracks/`）为准** |
| **小测** | 3 题起；选项**等长**、不给格式线索、顺序打乱 |
| **一手资料** | 1～3 个，来自 `RESOURCES.md` |
| **ask-teacher** | 请学习者提问，给两个具体的追问示例 |
| **next** | 互链：前置 / 顺着往下 / 其它轨道 / 术语表 |
| **footer** | 链回 `../index.html` 课程目录 |

配套脚本放 `./exercises/<轨道>/`，**命名与课号对应**，并且**必须本地跑通**再写进课。**脚本可跳过**——但只在主线不靠代码成立时；靠代码建的课要逐句检查"不跑代码能不能读懂"，读不懂就标注"本节可整节跳过"。（Agent 实操课「从零能跑」、RAG 脚本两层、RAGFlow 实验台等细则见各轨标准。）

### 1.3 三种课型的分工

| 类型 | 回答什么 | 会不会过时 | 放哪 |
|---|---|---|---|
| **原理课** | 是什么、**为什么** | 基本不过时 | `lessons/<轨道>/` |
| **技巧课** | 怎么做、**怎么不翻车** | **会**——模型/接口一变就得改 | **不单独设目录**（2026-10-18 起）：进实操课的"怎么不翻车"节／LLM 附录／`reference/` 速查 |
| **速查** | 用的时候照着抄 | 改得最快 | `reference/` |

- **原理能推出来，技巧是踩坑换来的**。技巧课的价值在省掉学习者的试错。
- **技巧类内容每条必须带齐「理由 + 一个反例 + 什么时候不适用」三件**（实操课"怎么不翻车"节／LLM 附录／`reference/` 速查里的都算）：缺"不适用"会被当成普适真理死记；缺"理由 + 反例"会退化成清规戒律清单，遇到没列过的情况就懵。
- **小测风格跟着变**：原理课考"是什么"；技巧类内容所在的课考"**这个场景该用哪个**"。
- **速查承接"贴墙清单"**：具体的表格、对照、检查单进 `reference/`，正文只讲取舍理由。

### 1.4 deep 页体例（与薄层课配对的进阶页）
deep 页是与薄层课配对的进阶页（历史上称「进阶版」，文件名以 `-deep.html` 结尾）：命名成对 `0001-xxx.html`（薄层课）＋ `0001-xxx-deep.html`。**薄层课**＝LLM 基础课／Agent·RAG 理论课（与自查清单同口径）。**哪些轨道有 deep**：LLM 轨成对出版，受众两层见 [LLM 轨标准](tracks/llm.md)；RAG 轨 deep 从零等真问题（存量旧页现状与转制细节见 [RAG 轨标准](tracks/rag.md)）；**Agent 篇无 deep 页**——深度走三条吸收渠道，见 [Agent 篇标准](tracks/agent.md)。

**怎么分工（最重要的一条）**：
- **薄层课保「完整连贯的主线」。** 概念哪怕不简单，只要**前后有顺序、不讲清后面就塌**，就**留在薄层课**。
- **deep 只收「可跳读的细节」。** 判据：**跳过去不影响读懂主线**。

细则：
- **deep 只收「真问题」**：薄层课给了结论、只挂了括号，但**没给理由**的，才配当问题。薄层课已明确答过的（如"token 不是向量"），**不作为问题存在**——课件一完善这类问题就过时，要**定期删或并进仍然有效的那条**。
- **deep 两类内容，分开对待**：
  - **理解型**（读者读的时候卡住的地方）**必须等提问**。证据：真问题都是卡住才写的（问温度那问）；主动写的问题反而最容易过时（例证全过见存档 5.03）。
  - **知识型**（薄层课**因为受众主动砍掉**的那部分）**不用等**——它不是猜，是欠账。
  - **但重机制与取舍，轻具体工具**（RAG 工具链一年一换）。
- **问题标题必须自足**：说清主语是谁。❌「它们互相能看到吗？」→ ✅「表里的 n 行，互相能看到对方吗？」
- **每条正文只回答那一个问题，不复述薄层课**（2026-10-03 改）。
  - **链接只能从薄层课那边进来**，不从 deep 正文往外指。"对应第 X 节那一行 X 字"这种**索路**一律删掉——它把读者的注意力从答案上拽走，而且**九问连着写九句，连着读就是九段噪音**。
  - deep 的读者是**带着问题跳进来的**，他已经知道这是在讲哪一环；正文开头直接给答案。
  - ⚠️ 唯一例外：**问题离开薄层课就看不懂时**，需要一句话补主语（见"标题必须自足"那条）——但那是**补主语**，不是**报出处**。
- **deep 不需要钩子**：它是"问题 + 详解"体例，开头放一句"怎么用这篇"就够（钩子是薄层课的零件）。
- ⚠ **deep 不等于术语版 —— 白话要求与薄层课一样**（2026-10-07 学习者定，见存档 5.16.8）。**deep 多的是"细节"，不是"行话"**：机制和数字该多深就多深，**但每一条都要用大白话先说清，术语真名放括号里**（「迭代级调度」＝每一轮重新挑一次人）。**判据：把这一段给一个读过薄层课的人看，他能不查资料读懂吗**——读不懂就是行话太多，不是他水平不够。同理，「注释框只装正文装不下的细节」这条对 deep 一样成立：能进正文的收口句、总结句，一律进正文。
- ⚠ **deep 不要替薄层课回答"初学者的疑问"**（2026-10-07 学习者提出，见存档 5.16.9）。deep 开头第一句先问一句「**这句是"读者读完薄层课仍会冒出来的疑问"，还是"薄层课本来就要替他挡住的误解"？**」**后者留在薄层课就够了**。**学习者问过、我们答过一次的事，在 deep 再答一遍就是占注意力。** ⚠ 与上一条不冲突：**薄层课给了结论但没给理由的**配当 deep 问题；**薄层课明确答过的**（如「token 不是向量」）不配当。
- **两版互链**：deep 每个问题给 `<h2 id="qN-关键词">`；薄层课讲到相关处，用**括号 + 直达链接**指过去（形如 `（<a href="...-deep.html#q7-mask">为什么必须看不到后面？</a>）`）。
- **括号链接不设上限，多个是对的**（2026-10-01 改）。**deep 的定位是"薄层课的细节补充"，读者本来就是跳着读的**——他卡在哪，就从哪跳进去。**多个入口是功能，不是变花**：实测一课十来个入口早已是常态（`llm/0001` 正文 6 处括号直达 ＋ 文末"想深挖"清单 11 条）。
  - 约束从"**数量**"换成"**位置对不对**"：**挂在那儿，读者真会想知道吗**？会 → 挂；只是"这课还有个 deep" → 不挂。**宁可一处不挂，不要一处硬挂。**
  - 密度高了要护住的是**可读性**，不是条数：括号里**只放一个短语链接**，不写整句话。灰字小字，扫过去不吵。
  - 一条细节的去处：ask-teacher · 文末"想深挖"清单 · 由别的 deep 页直链带过去——它回答的是"这条该放哪"，**不是"放不下"**。

**图放哪（三条硬规则）**：
- **同一张图只放一处。** 薄层课与 deep 不重复放同一张图；薄层课改用**文字钉死 + 括号直达**顶上。
- **去处由"这张图回答谁的问题"决定**：

  | 图的性质 | 放哪 | 例子 |
  |---|---|---|
  | 薄层课读者要的：**整条链长什么样** | 薄层课 | `llm-pipeline` 九站 |
  | deep 读者要的：**某个机制的内部结构** | deep | `causal-mask` 因果掩码 |
  | **拿来跟外部权威图对照的** | `reference/` | `llm-architecture`（只在 `canonical-diagrams.html`） |

  **`reference/` 是图的第三个合法去处，不是孤儿区。** 一张图进 `reference/` 的条件：它是**对照/速查**性质的，且那一页有它存在的理由（"读者会拿它跟别的东西比"）。
- **搬走图不许丢内容。** 原来只在薄层课图注里的解释，要跟着搬进 deep 的 figcaption。

### 1.5 讲法规矩
- **加任何东西之前，先过这三问**（适用于 `lessons/` · `reference/` · 术语表 · `internal/learning-records/`，**以及 `NOTES.md` 与本文件自己**）：
  1. **原文是不是已经说到了？** 换个说法、加个括号、挪个位置——都算重复。**重复不是"同一句写了两遍"，是"读者的注意力被占了两遍"**。
  2. **原文要不要跟着改？** 新增一条会**作废、改窄或冲突**于旧说法时，必须**同一次改掉**。只加不改＝亲手制造两个互相打架的版本，比不加更糟。
  3. **这条真的有必要加吗？** 动手前自问一句"**删掉它，读者会缺什么**"——答不上来就是多余的。**第 N 次"顺便提一句"就是主线在变钝的信号。**
  - **拿不准就问学习者，别自己拍板。** 问的成本远低于返工——本工作区的图已经因为"我以为你要的是示意图"反复返工过好几版，每一版都是我自己拍板拍错的。
- **文章体：课是文章，不是分块清单**（2026-10-21 引入，源自 se-lessons 项目）：课件首先是**一篇有头有尾的文章**，不是一组幻灯片——上一段留下一个问题，下一段回答它；这一节结束时，读者知道为什么要进下一节。**判断标准：把所有小标题遮住，仍能读出前后因果——读不出，写的就是分块清单。**
  - 对照：分块写法是「第一，装环境；第二，配 key；第三，跑脚本」；文章写法是「环境装好了，但它还不知道你的 key 在哪。下一步是告诉它去哪读——这就是配置要解决的问题」。信息量相同，后者让读者知道为什么要往下走。
  - 通俗不等于幼稚。先用读者熟悉的场景说清问题，再给术语（与"先画面、后名字"同一条线）。**生动来自具体，不来自修辞**：写清谁在什么情况下做了什么、看到什么、付出什么代价；少用「赋能」「闭环」「抓手」这类空词。
  - **比喻是工具，不是默认选项**：用了就要能一句话说清它对应什么、哪里不成立，讲完回到真实机制（与"类比之后必须补真实机制"衔接）；找不到合适场景就直接讲问题，**不硬编**。
  - **表格和清单是配角**：表格只做对照，清单只做检查；每张表**前**要说明为什么现在看它、**后**要解释它改变了什么判断。列表条目必须是完整句子；一节不能只有列表、没有正文。（1.2 的零件清单管**页面结构**；本条管零件内部的**正文写法**。）
  - **标题是叙事节拍，不是主题清单**：「先读一遍，再一个字一个字往外蹦」是节拍；「prefill / decode / 批处理」是目录。
  - 段落之间要有过渡句，说明为什么从 A 讲到 B。**「第一、第二、第三」只在真正并列时用**——三点之间有依赖，就写成因果链。
  - **一条叙事线、一个贯穿例子**走完一节课；需要第二个例子时明说它是类比，不中途换主角。**同一个概念只展开一次**，后文一句话回指（与"同一件事只量化一次"同族）。
  - 顺序服从读者的理解路径：先问题后概念，先具体后抽象，先主线后分支。
  - **句子层：语言洗练四条**（2026-10-24 并入——文章体的执行补充，把文章体落到每一句，源自 `agent/0001` 语言整审，见存档 5.55）：
    - **① 一句一事**：一句话只推进一个说法，两层意思拆成两句；破折号＋括号＋分号三层嵌套的句子重写；零信息量的垫词（“你会发现”“也就是说”这类）删掉，直接说；同一内容的完整说法一课只给一次，后文只用一句回指、不换说法复述。
    - **② 破折号节制**：每段至多一处，能新起一句就别用插入语（前两条破折号规矩管**空格与保护**，这条管**密度**，不冲突）。
    - **③ 比喻降密**：每段至多一个比喻；已升为课程术语的（三柱、护栏、说明卡、便签员工）可跨段复用，临时比喻不写（与“一个比喻只用一次”同族：那条管同一比喻不换版本，这条管总量）。
    - **④ 压缩短语黑名单**：“走深一层”“落了地”“拍扁”“一眼看得穿”“都翻在这条账上”这类把两个动作压进一个短语的写法禁用：读者得先解压才能懂，改写成白话直陈（“拿周报走一遍就清楚了”“花多少钱事先算得出”）。
    - **风格参照**（校准尺度用）：阮一峰——教程式短句直陈、术语随用随释，是①③的句子长度感基准；Simon Willison——一句一事实、先结论后解释，是①②的信息密度基准；余光中《中文的常态和病态》——少名词化、让动词干活，是④的改写方向基准。改完拿不准句子拆得对不对，对着这三类原文读一遍（四个毛病与参照的完整对照见存档 5.55）。
    - **执行范围**：存量课例**整课重过**（2026-10-23 学习者定：LLM 轨 21 文全量按此返工——标点级手术不算完成，见存档 5.57）；新写课直接照此执行。改完的核验规矩见存档 5.54/5.55：**每批编辑后逐串核验新旧两串**——本环境批量编辑报失败时可能已部分落地，报成功也不等于落全。（四条、风格参照与执行范围只在本「句子层」一处维护，不另立条目。）
- **白话优先**：不堆砌术语。
- **不写元叙述铺垫**（2026-10-10 学习者定）："先定个落点，免得后面全是术语："“这一条很违反直觉，值得多说两句"这类**替读者解释"我为什么要说这句"的开场白，删掉，直接说事**。学习者给的范式：不写"先定个落点"，直接写"**当前的 AI，也就是通用语言大模型，和 Excel、手机里的 App 一样，都是程序**"。判据：**段落开头的那半句如果删掉、后面完全不受影响，它就是 AI 味铺垫**（与 5.16.7"顺带／另外／补充说一句"同族）。**「一句话钉死」「一句话版本」「把这句翻成大白话」「这一条值得记住」这类给句子贴标签的开场白同族**——标签删掉直接说事，句子照样成立；**「钉死」这类武断收口动词也别用**，说"分清／说清"就行（写收口句时把开头标签删掉试一遍，是最快的自检）。
- **术语必解释**：用到就当场解释，绝不假设学习者已经会。⚠️ **"定义在后面"和"没定义"一样算违规** —— 第 N 问／第 N 节用到的字段和术语，得在这一问／这一节里就自洽。（例：`0003-deep` 曾拿 `cache_read_input_tokens` 说事，而它的解释在后面的 Q4；`effort` 全库只出现一次、零定义。另见存档 5.15 的「断点/块/条目」整页没定义）
- **先画面、后名字**：先给直观画面和类比，再给术语名称。日常话说完，补上术语真名（如"把句子切成零件"之后补一句"这一步叫**分词 tokenization**"）。
- **面向初学者**：**高中生能看懂**是标尺。需要高中以上的数学/概念，要么绕开，要么拆成日常话。
- **类比之后必须补真实机制**。学习者会抓不严谨的措辞，光有类比会被回头质疑。
- **括注和类比不得改动定义的宽度**：给术语配"换个说法"时，宽度必须和**主定义一致**。窄一点（"一次请求 ＝ 一次 API 往返"被写成"你的程序往模型发一次"）或宽一点，都是在**悄悄改定义**，不是解释。
- **带出数量关系**：讲工程取舍时给量级、给算式——**但只在深读的那一层给**（LLM 轨＝deep；Agent/RAG 轨＝实操课，RAG 轨重开的 deep 同算——这一层的读者会自己验算）。**薄的那一层只给结论和直觉**（"输出比输入贵得多"就够，倍数表进深读层或 `reference/`）。
- **薄层课只放主线，"顺便说一下"是它最大的敌人**（薄层课＝LLM 基础课／Agent·RAG 理论课；实操课同样只放主线）：
  - **判断法**：把一句话删掉，读者还能不能顺着读下去？能 → 它是细节。**尤其是"次要但正确的补充"最危险**——它不打断理解，只是让主线变慢、变钝。
  - **发现某个说法有歧义/会骗人时，不要靠追加括注来补救**。**换个更精确的说法，然后闭嘴。**（例：「N 个**相同的** Block」有歧义 → 改成「每个 Block **干的事**完全一样」，一句话就把范围框准。）
  - **次要细节的正确去处，按优先级**：① 薄层课的 **ask-teacher**（做成一个学习者真会问的问题）；② **deep**（或该轨实操课）；③ **术语表**。薄层课正文里**不留**。
- **以下几条是通用写作纪律，不限课型**：
  - **一个框（比如 `goal` / `note`）只装一件事**。它是"记住这一句"的地方，往里塞次要细节等于让最重要的话变长。
  - **注释框只装两类**（2026-10-10 学习者定）：**不影响阅读的术语解释**、**会打断读者阅读的知识点**。比喻、叙事、主线过渡**一律进正文**，用引导句自然接上（"那么整个系统大概是什么样子呢？你可以想象有个外星种族……"）。判据：这段话是**读者顺着读下去需要的**，还是**读到一半会停下来才用的**——前者正文，后者注释。
  - **同一件事只量化一次**。正文和括注各给一个数量、还量化得不一样，等于**亲手制造读者要自己消解的矛盾**。
  - **一个比喻只用一次**。同一个类比在一节课里出现两个不相干的版本（"尺子" + "饼干"）会互相干扰。
  - **破折号分两种写法，先看它在句子里干什么**（2026-10-03 定）：**句中插入语 → 顶格**，贴住前一个字，写成 ` —— ` 就算排版错（`……读一遍——不随 t 变`）。**标签＋说明 → 留空格**，它在这儿是**代替冒号**的标签分隔件（`<b>基础课</b> —— 给初学者`）。**一视同仁地砍掉空格才是错的**——那就抹掉了两种用法本来就有的区别。
  - **破折号有三处不许"顺手修"**：① **脚本实跑输出 / 代码原样**——改了就跟脚本实际输出对不上；② **图的 `alt` 与图注**；③ **`<pre>` 里的 ASCII 流水线图**——对齐装饰，视觉优先。全库扫出来带空格的破折号，多半落在这三处里，**先分类再动手**。
- **比喻的两条落地规矩**（2026-10-10 学习者定）：**比喻生动优先、不必逐句对应机制**，精确性由"类比之后补的那段真实机制"承担，两层不许互相挤；**但比喻里的事实要先核一遍**（16 色弄不坏二维码——比方也要过"它真的会发生吗"这一关，见存档 5.18.1）。
- **收口警句不是不能写，但不许牺牲直白**：短促对仗的收口句，**初学者第一遍就能清晰理解**才许用（「推理强，不等于工具调用强」这种一遍读懂的照留）；读着要自己解谜的（「错和错，不是一样错」）改成把内容直说的句子，或删掉。**自检两问**：这句是不是在重复上一句已经说完的内容（是 → 删）；第一遍能读懂吗（不能 → 改直白）。
- **术语统一**遵循 `../../reference/glossary.html`，新术语当场补进术语表。
- **说「官方」「原厂」「文档」必须注明是哪家**（2026-10-08 学习者定）：模型供应商不止一家，"官方"不写名字，读者根本无从核对。**判据：把句子里的"官方"换成具体厂商名，能不能换——能换就说明它本来就不该写成"官方"**；「官方」紧邻厂商名＝合规不改，**裸的＝改**。已知三家口径就不同（Anthropic / OpenAI / vLLM 开源系），脚本打印串里的"官方"同罪（它会被贴进课里）。这是 5.13.4「厂商行为断言写清对谁成立」的**措辞版**——那条管"断言对谁成立"，这条管"话说的是谁"。（执行细则见存档 5.17.3 / 5.17.8）
- **改课：基于整篇，不打局部补丁**（2026-10-21 引入，源自 se-lessons 项目）：改课前先**通读本课全文**＋前后相邻课＋对应参考卡，不只改被指出的那段——局部修改最容易留下前后矛盾、重复解释或断掉的回指。
  - 学习者指出一句，那句是**症状**：判断全文还有没有同类问题，**一次改完**，不逐轮挤牙膏。
  - 每次修改至少检查六处：开头的承接 · 术语首次出现处 · 贯穿例子 · 表格与图 · 动手与反馈 · 结尾指向下一课——任何一处用了旧说法，同一次改掉（三问里第 2 问的改课版）。
  - 改完用两条标准验收：**遮住小标题仍能读出前后因果**；**前后课不重复、不矛盾**。改到读起来像补丁，就**重写受影响的那一节**，别继续打补丁。
