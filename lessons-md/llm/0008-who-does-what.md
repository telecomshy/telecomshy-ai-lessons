## 开场（页首框｜先别急着学，聊两句）

你有没有过这种时刻：把同一段提示词扔进两个不同的产品，**一个给你的数据（JSON，程序好读的那种格式）规规矩矩，另一个让你自己修格式**。第一反应多半是「后面那个模型不行」。

**可格式这件事，恰恰不归模型管。**模型只负责给下一个字打分，格式稳不稳**由围着它的软件固定住**。有没有固定，差别就是「几乎不出错」和「时不时要你修」。**答得对不对、聪明不聪明，才归模型管。**

**你看到的每一个行为，背后都是某一层在干活。分清是哪一层，就是这课的全部内容。**

**学完这课，你能**看到一个不对劲的行为，先判断它出自哪一层；也会知道四条跟 agent 直接相关的坑。其中两条的正确修法，根本不在模型身上。

【选读框｜一条主线，记住它就不会晕】

**整门课只问一句话：这件事，是哪一层做的？**

你发出的一个请求，其实穿过了**四层**。每层都干自己的活、干完交给下一层。**模型只占最里面那一层，而且只干一件很窄的事。**

## 1. 先补一段背景：模型是怎么「跑起来」的

第 0 课说过，训练一个模型，工程师先写**「骨架」**：几十层怎么摆、每层干什么，**然后再开始训练**。训练完成，产出一个**权重文件**：每一层的数字，全在里面（第 6 课压小的就是它）。

但权重文件就是个**普通文件**：**双击不会跑，自己不会回答任何问题**。

要让它能用，还得有个**配套的软件**：这套程序叫**推理引擎**（inference engine）。它得先做两件事，才轮得到回答问题：**① 把权重从硬盘搬进服务器显卡的显存里**（显存＝显卡自带的内存，第 2～4 课出现过）；**② 启动一个后台服务器，响应你的请求**。你的程序跟它打交道的窗口叫**接口**（API）。这一整套叫**部署**（deployment）。

以部署 DeepSeek 为例：先下载 **vLLM**（一个开源推理引擎），再下载 **DeepSeek 的权重文件**。**vLLM 已经内置了 DeepSeek 的算法**，所以算法不用你下载、也不用导入。**但不是所有引擎都支持所有模型**：算法得由引擎自己实现，**所以部署前先去引擎的官网确认它支持这个模型**。（另外还有几个小文件：`config.json`，骨架的尺寸表；分词器，字怎么切。）

**同一份权重，换一个引擎，行为就不一样**：格式稳不稳、快慢、停在哪，都会跟着变。这正是开头那个例子的原因。所以普通人平时说的**「大模型」**，实际就是**权重文件＋推理引擎**。

## 2. 你的请求穿过了四层

那么，**你向模型提一个问题、它回你一段话，中间到底经历了什么？**从外到里，是这四层：**① 你的程序（行话叫 harness）** · **② API 网关** · **③ 推理引擎** · **④ LLM 模型**。

【图】../../assets/who-does-what.svg（图片文件不动）

替代文字（alt）：四层堆叠图，从上到下依次是：你的 harness，它管拼提示词、装工具、管上下文、决定停在哪一步、失败怎么重试；API 网关，它管鉴权、限流、计费、把请求转给哪台机器；推理引擎，它管排队、拼车、复用缓存、从分表里挑字、按语法划掉非法字、小模型先写候选再由大模型一次验收；最里面是 LLM 模型，它只干一件——把已收到的这些字算成下一张分数表

图注：从外到里四层。**越靠上的层越「你的」，越靠下的层越「服务商的」**。右边两根箭头是本课最要紧的两句话：引擎干的那些活，**模型一个字节都不管**；而模型**交出分表就下班**，后面发生的事全不是它干的。

逐层点名，看清各自的领地：

| 这一层 | 它真正干的活 |
|---|---|
| **你的程序**（harness）<br> 跑 agent 的那段程序 | 拼提示词 · 装上工具 · 管上下文 · **决定什么时候停** · 失败了自己重试。[Agent 篇 · 第 7 课](../../lessons/agent/0007-harness.html)讲的就是它 |
| **API 网关**<br> 服务商门口的"前台" | 验你的身份 · **管你的用量配额**（用超了就限流）· 计费 · 决定把你的请求转给哪台机器 |
| **推理引擎**<br> 本课的主角 | **排队 · 拼车 · 复用缓存**（[第 3 课](../../lessons/llm/0003-kv-cache-and-prompt-caching.html)、[第 4 课](../../lessons/llm/0004-batching.html)）· **从分表里挑字**（[第 1 课进阶](../../lessons/llm/0001-from-token-to-next-token-deep.html#q10-sampling)）· 另有几件新活，第 3、4 节再点名 |
| **LLM 模型**<br> 骨架＋训练出来的数字 | **只干一件：把已经收到的这些字，算成下一张分数表**（每个字打一个分；[第 7 课](../../lessons/llm/0007-distillation.html)那张概率表，就是训练时拿它交出来的分数表换算的）。交出这张表，它就下班了 |

这条边界，[第 1 课](../../lessons/llm/0001-from-token-to-next-token.html)那张流水图的底色带就标着：**从「查嵌入表」到「原始分」之间是模型，之后换算、挑字、拼字符串，全不是它。**模型交出的是一张「哪个字有多少分」的表：**至于从这张表里挑哪个字，它说了不算。**

**平时说的「模型＋外壳」，是解释概念用的分法；真正排查问题，还是按这四层、从外到里逐环节走**：先问「这个行为是哪一层干的」，再问「那层归谁管、能改什么」。（两分法为什么不够用，[进阶版里细说](../../lessons/llm/0008-who-does-what-deep.html#q5-two-blocks)。）

## 3. 引擎干的四件事，其中三件你已经很熟

引擎不是什么神秘的东西。它干的活可以归成四类，**前三类你已经学过了**：

1. **排队与拼车**：把撞在一起的请求凑成一批，共用一趟权重搬运。这正是[第 4 课](../../lessons/llm/0004-batching.html)整节讲的内容。
2. **复用缓存**：K/V（每轮算出来、留给后面用的那些数）存哪、怎么复用，都归它管。同一个请求内，前面字的 K/V 留着不重算（[第 2 课](../../lessons/llm/0002-prefill-vs-decode.html)）。跨请求，认出你这次发来的前半截和上次一样，直接搬用（[第 3 课](../../lessons/llm/0003-kv-cache-and-prompt-caching.html)）。
3. **从分表里挑字**：温度、`top_p`、`top_k`、种子，这些旋钮都是它在执行（[速查页](../../reference/sampling-params.html)）。
4. **按语法划掉非法字**：这一件是新的，下一节讲。

**「同一个模型，两次答案不一样」这件事，根源就在这里**：挑字是引擎在动手，而不同引擎的默认值、计算精度、执行顺序都可能不同。**本来就没有"必须一模一样"这回事。**

## 4. 新的一件：它能把不可能的字直接划掉

第 1 课那张分数表上，模型给**整张词表**（所有候选字）都打了分。在格式要求严格的场景（比如要输出一个 JSON 字符串**供工具解析**，像 `{"city":"北京"}` 这样），**大部分字都是"拼下去就废了"的**，但它们照样在表上、照样有分数。

「废」有两类。**一是语法坏了**：模型很可能输出 `{"city":"北京}` 这样少个引号的，**工具解析直接失败**。**二是语法合法、但不符合要求**：比如输出 `{"city":"北京","nope":null}`，工具能正常解析，**但多了个字段，执行照样失败**。

让模型输出 JSON 字符串供工具解析，这个功能叫**结构化输出**（structured outputs）。JSON 对象需要包含哪些字段、每个字段是什么，就是它的 **schema**（"必须长什么样"的说明书）。引擎的新本事是：**在挑字之前，先拿一张语法规则把所有"拼下去会废"的字从表上划掉**，只在剩下的里面挑。这一招叫**约束解码**（constrained decoding）。结构化输出要确保的，就是**输出能被正确解析、并符合 schema 的 JSON 字符串**。

Anthropic 官方文档的原话是：结构化输出「**通过约束解码来保证回答符合 schema**」。另一家 vLLM 的文档写得更直白：它的后端就是专门干这个的引擎，作用是「**保证输出 100% 的结构正确**」。

这里的关键是**「保证」两个字**。它不是"让模型更小心地写对"，而是**在数学上让写错这条路不存在**——错字根本没有出现在候选里。Anthropic 也把这句写进了文档：**开了之后不会再有 `JSON.parse()` 的报错**（那句报错是程序读不动坏 JSON 时喊的）。

**不过它默认是关的。**请求里没带 schema、没开结构化输出，就还是普通生成，格式全靠模型自己写，偶尔崩很正常。**上面那个「保证」，是打开开关之后的事。**（[本地部署偶尔还是解析失败，为什么？](../../lessons/llm/0008-who-does-what-deep.html#q1-not-guaranteed)）

但有一个例外：**模型会拒答。**拒答就是它按安全规则拒绝回答（问了不该问的事），回你一句「这个我不能答」。**这句话优先于格式约束**，那次回答照样合法，只是不是你要的形状。**所以代码里仍然要检查「我到底有没有拿到数据」，不能假设开了就一定有。**

**这招也不是免费的**：说明书（schema）太复杂会被直接拒掉，所以参数别一口气堆满。（[具体代价有哪些？](../../lessons/llm/0008-who-does-what-deep.html#q3-cost)）

另有一件事，属于同一层但方向相反：**引擎还能让一个小模型先写候选、大模型一次验收，以此加快速度**。这招叫**投机解码**（[术语表](../../reference/glossary.html#speculative-decoding)）。它的卖点恰恰是**输出一个字都不变**，只是快。

这两种招要分清。**投机解码只是提速，它承诺输出一个字不变。****约束解码是明着改输出**：按你的说明书，把不合法的字从候选里掐掉，改成你要的形状。**一个不碰答案，一个改答案（经你允许）。别混成一类。**（[两个能同时开吗？](../../lessons/llm/0008-who-does-what-deep.html#q4-together)）

## 5. 四件跟 agent 直接相关的事

前面是地图，这四条是拿地图去排查。**每一条的修法都不在模型身上**。这是本课最实用的部分。

### ① 工具调用返回的 JSON 不合法，你的 agent 直接崩

你在[Agent 篇 · 第 1 课](../../lessons/agent/0001-what-is-an-agent.html)学到的流程是：模型说「要调哪个工具、参数是什么」，**你的代码去解析它、去执行**。Anthropic 文档开头写的就是这个痛点：**不开结构化输出，模型会吐出坏 JSON 和不合法的工具参数，让你的程序崩掉**。光是提示词写得再仔细也躲不掉。

所以修法不是改提示词、不是换更大的模型，而是**让接口帮你把格式固定住**（打开结构化输出那一类开关；[在哪配](../../lessons/llm/0008-who-does-what-deep.html#q2-config)）。工具参数也能这么固定（Anthropic 管它叫"严格工具调用"），和结构化输出一起用，就能**既要可靠的工具调用，又要可靠的最终答案**。

**「模型很听话、格式很稳」这个结论，前提常常是接口帮你固定着格式。**把它当成模型的功劳，你就找不到修法了。（[怎么验它真开着？](../../lessons/llm/0008-who-does-what-deep.html#q2-config)）

### ② 模型不会自己停——停在哪是引擎说了算

你可能会以为模型自己知道什么时候说完了。**不是的。**每次回答回来都带一个字段说明「为什么停了」，Anthropic 把它列成一张小表：答完了 · **撞到上限了** · **碰上了你设的停止字** · 要调工具 · **拒答** · **把上下文窗口填满了**。

**对 agent 来说，其中一条要命**：**如果撞上限时那份回答里有个没写完的工具调用，那份工具调用是坏的**，直接执行会出错。Anthropic 给的处置是**把上限调大、重发一次**。

也就是说，**「工具调用参数不完整」有一种成因不在模型，在引擎那层的上限设置。**遇到这类坏调用，先看你给的上限够不够，再去怀疑模型。

### ③ 429 和「过载」：都不是你的错，都在网关和引擎那层

接口报错时会给你一个编号。**下面的编号口径来自 Anthropic**（别家不完全一样），常见的有两种，含义完全不同，**处置也不同**：

- **429（限流）**：你把配额用超了。Anthropic 的文档提醒一种特殊情况：**如果是撞到月度花费上限，它不会给你「等多久能重试」的提示，而且会一直失败到额度恢复**。这种**重试没有意义**。
- **529（过载）**：**服务端现在人太多了**，跟你的请求内容无关。原文写着「API 暂时过载」。这种情况**等一会儿再试就行**（行话叫退避：越等越久地重试）。

还有一条能省你事的：**Anthropic 给的工具包（SDK）会自己重试**：连接错误、限流、服务端故障这些临时问题，它默认等一会儿重试两次，还会听服务端给的「等多久」提示。**所以你手写的那层重试，很可能是在它之上又叠了一遍。**

**这属于哪一层**：429 来自**网关**（它管配额和花费上限），529 来自**引擎**（它的机器忙不过来）。**模型在这两件事上完全无辜。**

### ④ 缓存命中的那笔账，会被误读成「这个模型更快」

[第 3 课](../../lessons/llm/0003-kv-cache-and-prompt-caching.html)实测过：**只改提示词开头一处，成本差 3.7 倍**。同样的道理在快慢上也成立。**命中缓存的那次请求，第一个字来得快得多**，而这并不是因为模型更快。

所以做对比时有个坑：**拿命中缓存的一次和没命中的一次比速度，结论是假的**。**要比就得两边都命中，或者两边都没命中。**

## 6. 亲手验一遍

上面这些机制里，脚本把其中三件做了可直接验证的演示。它只用 Python 自带的功能，离线能跑：

```
python exercises/llm/0008-who-does-what.py
```

**演示一 · 约束解码**：造一个玩具场景：合法答案只有三种 JSON，词表里故意混进五个「不听话」的零件。用**同一张分表**抽 2000 次，只改一个变量：加不加那道语法闸。

```
  同一个模型、同一张分表，抽 2000 次：
    不加闸（模型爱挑什么挑什么）        合法  1378 / 2000   不合法率 31.1%
    加了闸（引擎每步划掉不合法字）      合法  2000 / 2000   不合法率 0.0%

  不加闸时，坏的长这样（从 2000 次里挑前 3 次失败的）：
    ✗ {null{"nope":}nullnull
    ✗ {"city":"北京""nope":null}
    ✗ {"cityy""北京"}{"cityy",null
  同一批实验里，成功的长这样：
    ✓ {"city":"北京"}
    ✓ {"city":"广州"}

  再用真解析器（json.loads）跑一遍，只看两件事：会不会崩、能不能取出字段：
    不加闸：解析失败 622 次    解析成功但取不到 city 字段 0 次
    加了闸：解析失败 0 次    解析成功但取不到 city 字段 0 次
```

**看两处**：不加闸时**约三成直接是废的**；加了闸**两千次全部合法**。这正是 Anthropic 文档里「不再有解析报错」那句话的意思：**不是模型变听话了，是错的选项根本不存在了。**

⚠ 那个 31.1% 是脚本**手编的分表**造出来的，只说明机制、**不是任何真实模型的成绩**。能当真的是两头：不加闸会漏，加闸不漏。

**演示二 · 投机解码**：造两个玩具模型（大模型给真答案，小模型只在两个位置上猜错），然后数**大模型被叫了几次**，并**逐字比对两次的输出**。

```
  大模型被叫的次数：
    老实一个个问（基线）         13 次
    小模型打草稿 + 一次验一批     3 次
    省下 77%

  两次输出逐字一样吗？  一样 ✓
    基线： 今天天气不错，我建议带把伞，出门方便。
    投机： 今天天气不错，我建议带把伞，出门方便。
```

**真正该看的不是「省下 77%」**（那是玩具规则造出来的，不是真实加速倍数），**而是那行「一样 ✓」**——引擎加速了，**一个字都没变**。

**演示三 · 凑批会改答案**：显卡算的是小数，而**小数加法换个顺序，末位就可能不一样**（行话叫"浮点加法不满足结合律"）：

```
    (0.1+0.2)+0.3 = 0.60000000000000008882
    0.1+(0.2+0.3) = 0.59999999999999997780
    差 1.110e-16   （完全正常，浮点本来就这样）
  而显卡能分辨的最小刻度，是这个：
    一个「刻度」(1 ulp) = 1.776e-15
    候选甲 = 10.00000000000000000
    候选乙 = 10.00000000000000178
    打印出来长得一模一样，但它们是两个不同的数，甲 < 乙。
```

**凑批会改变「谁跟谁先加」**：你独自一批是一种分法，旁边挤进来八个人是另一种分法。所以**只要两个候选字的分数咬得比一个刻度还紧，「谁的分高」就由末位说了算，而末位会被凑批的方式改变**。

这不是脚本编的巧合，vLLM 自己的文档里就有专讲这件事的一节，明说**批大小的变化可能让分数（行话叫 logprob）变化，进而让同一个请求的输出不同**。**又一条本该在「引擎」名下记账的现象。**

## 7. 检查一下你懂了没

**Q1　同一段提示词，两个产品一个给出的 JSON 规规矩矩、另一个老要你修格式，最可能的原因是？**

- 两个产品用了聪明程度差很远的模型
- ✅ 格式是外面的软件固定的，有一家没固定
- 提示词在传输的路上被改掉了一部分
- 这家服务商的模型今天正好在重新训练

答对时：对。格式稳不稳是软件层的事，有没有固定住，差别就出来了。
答错时：格式稳不稳不归模型管——把格式固定住是外面软件的活，这正是本课的主线。

**Q2　工具调用返回的参数不合法、你的 agent 直接崩了，最该先试哪一步？**

- 换一个参数量大得多的模型来试
- 在提示词里反复强调必须输出合法 JSON
- ✅ 让接口帮你把格式固定住，比如开结构化输出
- 把温度调到 0，让它的输出更确定

答对时：对。格式坏掉这件事的修法在接口那一层，不在提示词、不在模型大小。
答错时：提示词和温度都只是让模型「更想写对」，没有把错的路堵死。

**Q3　模型交出那张分数表之后，挑字这一步是谁在执行？**

- 你的程序，它要读出字才能显示
- 模型自己，它训练时就学会了怎么挑
- API 网关，它负责把结果转成 JSON
- ✅ 推理引擎，温度和 top_p 都由它执行

答对时：对。模型只到「交出分表」为止，挑字是引擎的活（第 1 课进阶 Q9）。
答错时：模型只交出分数表。挑字、温度、top_p 都是引擎执行的。

**Q4　工具调用少写了一半、参数不完整。已知引擎有个输出上限，先该怀疑什么？**

- ✅ 回答被上限截断了，调大后重发
- 这个模型今天状态不好，换一个
- 工具的说明文档写得太含糊了
- 缓存没命中，所以这遍结果算错

答对时：对。撞上限时没写完的工具调用是坏的，Anthropic 给的处置就是调大上限重发。
答错时：截断发生在引擎那层，跟模型当天状态、工具说明、缓存都没关系。

**Q5　服务商回 529「暂时过载」，最接近真相的说法是？**

- 你把配额用超了，所以被拒了
- ✅ 引擎那层忙不过来，等一会儿再试
- 这次生成的内容违反了安全策略
- 提示词有问题，换个写法再试

答对时：对。529 是服务端过载，退避重试。配额用超是 429，两种别混。
答错时：429 才是配额/花费上限（重试没用），529 是服务端忙。

## 一手资料（页脚框，一般不动）

- [Anthropic — Structured outputs（官方文档）](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)：「**通过约束解码来保证回答符合 schema**」；「**不再有 `JSON.parse()` 报错**」；「把 JSON schema 编译成一份语法来约束输出」；工具参数也能这么固定（Strict tool use）；**首次用某 schema 会多花时间编译 · 编译结果按 24 小时缓存 · 改 schema 会重编、并让这一轮对话的前缀缓存作废**；schema 太复杂会返回 **400「编译不出来」**，另有 180 秒兜底超时。
- [vLLM — Structured Outputs（官方文档）](https://docs.vllm.ai/en/latest/features/structured_outputs/)：约束解码的后端与它支持的几种约束形态（固定选项 / 正则 / JSON schema / 上下文无关文法）；以及那条容易被忽略的建议——**在提示词里也写清 schema，通常会让效果明显变好**。
- [XGrammar（开源约束解码引擎）](https://github.com/mlc-ai/xgrammar)：原话「**借助约束解码保证输出 100% 的结构正确**」，且是 vLLM、SGLang、TensorRT-LLM 等引擎的结构化输出默认后端。
- [Leviathan, Kalman, Matias — "Fast Inference from Transformers via Speculative Decoding"（ICML 2023 Oral）](https://arxiv.org/abs/2211.17192)：投机解码的原始论文。原话「**不改变任何输出**（without any changes to the outputs）」；T5-XXL 上 **2～3 倍**加速、输出完全一致；**不用重训练、不改结构**。
- [Anthropic — Stop reasons and fallback（官方文档）](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons)：那张「为什么停了」的表（答完 / 撞上限 / 碰停止字 / 要调工具 / 拒答 / 填满上下文窗口）；以及**撞上限时未写完的工具调用需要调大上限重发**。
- [Anthropic — Errors（官方文档）](https://platform.claude.com/docs/en/api/errors)：**429 限流**（含「撞月度花费上限时没有重试提示、会一直失败到额度恢复」）· **529 过载** · 500 的处置是**指数退避重试** · **官方 SDK 默认自动重试两次**。
- [vLLM — Speculative Decoding（官方文档）](https://docs.vllm.ai/en/latest/features/speculative_decoding/)：这一招主要改善**中低 QPS 的每个字之间的时间**（正对应第 2 课 decode 带宽受限那条）；以及那句诚实的自我说明——**批大小变化可能让 logprob 变化，从而让同一个请求的输出不同**。
