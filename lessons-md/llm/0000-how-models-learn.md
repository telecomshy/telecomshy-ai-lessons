## 开场（页首框｜先别急着学，聊两句）

**大模型确实是人写的程序**，代码是工程师一行行敲出来的。

它和普通程序唯一的区别是：**普通程序写好就写好了；大模型写好的只是"骨架"，还得再训练一次，那才算真正写完。**

而骨架里那些数字，**没有一个是人填的**。你可能一直以为它们是工程师一条条编进去的规则，像写 `if` 那样——**其实一条都没有。**

那这些数是哪来的？——**学出来的**。而且"学"这件事比你想的朴素得多，**就四步**。

**学完这课，你能**说清：这些数字是哪来的、是怎么被调出来的，以及为什么它天生只会"接下一个字"。这门课是全轨的先导课：读第 1 课之前，先看这篇。

【选读框｜记住一条主线，后面就不会晕】

**训练 ＝ 出题（文本自带答案）→ 作答 → 算扣分 → 往少扣分的方向拧一点点 → 重复几百亿次。**

模型里所有的数字，都是被这一句磨出来的。接下来每一节都挂回它。

## 1. 先说背景：大模型也是人写的程序

**当前的 AI，也就是通用语言大模型，跟 Excel、你手机里的 App 一样，都是程序**：有人写代码、有结构、跑在机器上。

**它的作用就一件事：送进去一堆文字，反复猜下一个字。**你跟它聊天，看到的整段回答就是这么一个字一个字攒出来的。

**那么这个系统里面大概是什么样子呢？你可以想象有个外星种族**，他们的文字和我们不一样，科技又非常发达：他们的字典不是二维的纸张，而是高维的：**每一个字就是高维空间里的一个点**（高维想象不出来，先想象三维空间的点）。他们猜下一个字的时候，比如「好一朵美丽的茉莉__」：先把前面每个字在字典上的坐标查出来，送进大模型。在大模型这副身体里，**每个点会看着前面的点不断挪自己的位置，也会按学到的规则自己调整**。走到出口时，最后一个点停在一个新位置上。拿它跟字典里所有点比一比，**看最接近哪几个，从中挑一个出来**。挑出来的就是下一个字。（比喻里的"字典"，真模型里叫**嵌入表**，不是第 1 课那个只管编号的"词表"；挪位置、自己调整、比对挑点的真名字是**注意力、FFN、打分、采样**，第 1 课会一格一格拆开。）

那它跟普通程序真正的差别在哪？**在"规则是谁定的"：**

【三柱框】

**普通程序**

程序员把规则**一条条写死**进去。写完了就是终稿，行为从此确定。

**没有"训练"这回事。**

**大模型**

程序员写完的只是**一副空骨架**：结构有了，但里面该填什么数还不知道。

还要再过一遍**训练**，那些数才会被填上。**训练完才算"写好"。**

这副空骨架有个正式名字：[**神经网络（neural network）**](../../reference/glossary.html#neural-network)。别被名字唬住。它一点也不神秘，说白了就是**一大堆"乘加"操作一层层摞起来**：上一层的输出进来，按一堆数字重新配比一遍，得出新的输出，再交给下一层。今天这个具体摞法叫 **Transformer**，是第 1 课要拆的东西。

所以"训练"这两个字，指的就是**把这个空骨架里的数字一个个填上**。这些数字叫[**权重（weights）**](../../reference/glossary.html#weights)，也叫**参数（parameters）**——也就是本课从头到尾说的那个**"数字"**。训练完的模型落到硬盘上，是**一份程序＋一个权重文件**，数字都装在那个文件里。

所谓**"每个点挪位置"**，落到实处就是**向量乘法**：拿这串数字乘上一大堆权重，算出一串新的数字，点就"挪"到了新位置；一层层乘下去，一步步挪到"该说什么"的位置。**乘的这些权重，没有一个是程序员定的：全是训练练出来的。**比喻里那句"按学到的规则自己调整"，说的就是它。

至于**这个比喻里每一步到底怎么做到的**，是后面几课的事：

【goal 框｜比喻里的每一步，拆开在这些课里】

- 文字怎么变成数字，又怎么变回字？中间那几十层在干什么？→ [第 1 课 · 从「token」到「下一个 token」](../../lessons/llm/0001-from-token-to-next-token.html)
- 一次回答里，这副身体被用了多少次？为什么打字是一个字一个字蹦的？→ [第 2 课 · prefill 与 decode](../../lessons/llm/0002-prefill-vs-decode.html)
- 每次请求都要从头再算一遍，能不能复用？→ [第 3 课 · KV Cache 与缓存命中](../../lessons/llm/0003-kv-cache-and-prompt-caching.html)

**而这些数字是怎么被填上去的，就是本课接下来的全部内容。**不看懂这一步，后面那些"为什么"就都没有着落。

## 2. 这些数字是哪来的？不是人写的

**权重是参与计算的那一方，不是被算出来的结果**：被算出来的，永远是每一层的输出。围绕它，先把下面三件事弄清楚：

- **有多少？**当年的 GPT-2 小模型有 **1.24 亿个**；今天的大模型是几千亿到几万亿。
- **人写的是什么？**只有**骨架**：几十层怎么摆、每层干什么。**但骨头缝里那些数字，一个都不是人填的。**
- **一个常见误会**：以为工程师在"调参数"。工程师调的是**训练怎么跑**（喂多少数据、跑多久、每次拧多少），**不是那 1.24 亿个数本身**。

这三件事说的其实是同一件事：**数字个数再多，也没有一个是人写的，工程师动的只是训练怎么跑。**

## 3. 怎么学的？四步，反复几百亿次

### ① 出题

抓一句现成的话，比如「天气很」，问它：**下一个字是什么？**

### ② 对答案——答案就写在原文里

那句话本来就是「天气很**好**」。**不用人标，文本自己带着答案。**

这就是 LLM 训练最漂亮的一点：随便抓一段话，把它往后挪一格，就**同时**得到一道考题和一份标准答案。语料有多少字，就有多少道带答案的考题。

### ③ 算扣分

它先吐出一张百分比表：好 62%、冷 26%、差 12%。答案是「好」，它给了 62%——还行，**扣 0.47 分**。要是只给 1%，**扣 4.6 分**。

**扣多少是算得出来的，一个数。**给得越准，扣得越少。

### ④ 改：往少扣分的方向拧一点点

回头追一句：**这次没拿满分，是哪些数字造成的？**数学上有个办法，能**一次算出几十亿个数字各自该往哪边拧**，不用一个个试过去。

然后每个数字都往"少扣分"的方向拧**极小**一步。**不能拧猛了**。拧猛了会把之前学会的冲掉。

这个从出口往回追责的顺序，有个学名：**反向传播（backpropagation）**。做题是**从前往后**的：字 → 数字 → 一层层走过 → 一张百分比表。算账是**从后往前**的：先看这张表差多少，再看最后那层该负多少，再往前一层……一路追到第一层。

所以那些数字**虽然没有各自的目标，却被"少扣分"这一句管得死死的**：每层该学什么，是被追责追出来的。

## 4. 所以它天生会什么、不会什么

**会的**：接下一个字，接得很像。

**不会的**：它学的是**语料里的统计规律**，**不是"事实"**。语料里有什么，它就信什么。语料里一处有两种答案，它就学成"五五开"。

- **它给的不是答案，是一张百分比表。**所以同一个问题问两次，答案可能不一样。"挑哪一个"是后面的事，见[第 1 课进阶 · Q10](../../lessons/llm/0001-from-token-to-next-token-deep.html#q10-sampling)。
- **它会一本正经地胡说。**因为它的任务从头到尾都是"接得像"，**不是"说得对"**。它没有"对不对"这个概念，只有"像不像"。

**后面每一课都挂在这儿**：为什么胡说、为什么两次不一样、为什么要小心喂给它的话、怎么判断它做得好不好。

"它只会猜下一个字"这句话，跟你的日常经验是打架的。你用的每一个模型，答起问题来**大部分是对的**，能写代码、能算数、能讲道理、甚至承认自己不知道——**看起来相当有智慧**。

那这两句话怎么对得上？**靠量变到质变**——术语叫[**涌现（emergence）**](../../reference/glossary.html#emergence)。

"猜下一个字"这个任务本身，**从没变过**。变的是它的规模：语料从几 MB 到几万亿 token，权重从几百万到几千亿，参数量、算力、数据一起涨上去。

而这个任务有个特性：**要猜得越准，就得把语料里的一切都压进那些数字里**：语法、事实、推理步骤、代码习惯、说话的分寸。规模足够大之后，被压进去的东西多到**足以覆盖你随手问的绝大多数问题**，于是同一个目标跑出来的结果，**看起来就像"懂了"**。

所以两件事同时成立，而且不矛盾：

- **它表现出来的样子，确实越来越像人**。这是真的，不是错觉，量变确实到了质变那一侧。
- **它内部做的事，仍然只有"接下一个字"**——**没有凭空多出什么"智慧模块"。**

**这件事的代价就摆在旁边：**既然"像"就是全部标准，那么**一段胡话只要写得够像，它就同样高分**。它没有"我说的是不是真的"这根弦，因为训练里从来没有这项打分。**所以你不能拿"它很聪明"去推断"它不会错"，也不能拿"它只是瞎猜"去否认它真的会做对事。**

要拿捏住这个分寸，你只需要随身带着这一句：**模型不管对不对，只管像不像。**

## 5. 动手跑一遍

脚本在工作区：`exercises/llm/0000-how-models-learn.py`。它让一个玩具"学"会接下一个字。**骨架被简化到只剩一张表**（真实模型是几十层矩阵，那是第 1 课的事），**但训练的方式一模一样**。

```
python exercises/llm/0000-how-models-learn.py
```

Windows 终端若中文乱码，先执行 `chcp 65001`。下面是输出摘录（跑了就有完整的）。

```json
[3] 开始训练：每一遍 = 把 18 道考题全做一遍，每题都拧一点点
      第    1 遍   平均扣分 1.539
      第   50 遍   平均扣分 0.627
      第  200 遍   平均扣分 0.605
      第 1200 遍   平均扣分 0.599

[4] 训练后：再让模型看两个字
      看「很」
      「天」  0.0%   「气」  0.0%   「很」  0.0%   「好」 32.7%   「冷」 34.2%   「差」 33.0%   「雨」  0.0%
      看「天」
      「天」  0.0%   「气」 52.5%   「很」 47.4%   「好」  0.0%   「冷」  0.0%   「差」  0.0%   「雨」  0.0%

[5] 扣分最后停在 0.599 就不降了——那不是它笨
      看「天」的那 6 道题，平均每题扣 0.695
      看「气」的那 3 道题，平均每题扣 0.001
      看「很」的那 6 道题，平均每题扣 1.100
```

**输出里有三处要看懂**：

- **扣分一路往下掉**——它在"变好"，而变好的唯一标准就是扣分变少。
- **看「很」那行，三个都在三成上下**：因为语料里「很」后面三种都出现过、而且一样多。**看「天」那行是五五开**：一半跟「气」（天气很…），一半跟「很」（雨天很…）。**它给的是一张百分比表，不是一个答案。**
- **扣分停在 0.599 不再降**。那不是它笨。「气」后面永远是「很」，所以能扣到 0。「天」后面有两种答案、「很」后面有三种，**再聪明也只能按比例猜**，那部分扣不掉。**是语料本身就有不确定性。**

## 6. 检查一下你懂了没

**Q1　模型里那一大堆数字，是谁写进去的？**

- 是一个一个被工程师手动调出来的
- ✅ 没人写，是训练从数据里磨出来的
- 是从别的现成模型那边复制过来的
- 是随机生成出来、之后再也不动的

答对时：对。那一大堆数字是被「出题→扣分→拧」这个循环磨出来的。
答错时：模型里的数字没人手写，也不是抄来的——它们是训练的结果。

**Q2　训练的时候，「标准答案」是从哪来的？**

- 是模型自己先想出来再自己打分的
- 是由工程师事先标注好的标准答案
- ✅ 就写在语料里，下一个字本来就有
- 是网上找来的一堆人投票选出来的

答对时：对。语料里那句话本来就是「天气很好」，答案自带，不用人标。
答错时：训练不用人工标注：把现成文本往后挪一格，就同时有题和答案。

**Q3　扣分为什么不会一路降到 0？**

- 因为模型里的数字个数是固定的
- 因为算力不够，跑不动更多轮了
- 因为每一轮只肯拧一点点，太慢
- ✅ 因为有些题本来就有好几种答案

答对时：对。扣不掉的那部分是语料本身的不确定性——同一处本来就有多种答案。
答错时：不是算力也不是太慢：有些题本来就多解，按比例猜已经是最好的成绩。

**Q4　大模型比普通程序多出来的那一个阶段是什么？**

- ✅ 训练：人先写好骨架，再把数字填上去
- 编译：把代码翻译成机器能跑的东西
- 调试：工程师一条条把里面的 bug 修掉
- 没有多出来什么，它就是个普通程序

答对时：对。普通程序写完就定稿；大模型写完只是空骨架，还得训练一趟才算写好。
答错时：骨架是工程师写的，但骨架里的数字是训练填的——多出来的就是「训练」这一阶段。

**Q5　既然它只是"猜下一个字"，为什么用起来感觉它相当有智慧？**

- 因为它在偷偷查数据库，需要时把事实取出来
- ✅ 规模足够大时，同一个目标的结果就像懂了
- 因为训练时还额外教了它一套判断对错的标准
- 因为猜字本来就是人类思考的本质

答对时：对。任务从没变过，变的是规模——量变到质变。但里面没有多出什么「智慧模块」，所以胡话照样高分。
答错时：它内部始终只有「接下一个字」这一件事。看起来聪明是规模堆出来的效果，不是多了一套判断对错的机制。
