## 开场（页首框）

我们平时使用agent软件时，安装工具很简单。不过这些工具通常不叫工具，叫MCP（有些软件叫应用连接）。为什么叫这么个奇怪的名字，它和你在第二课编写的python脚本又有什么区别呢？

**学完这课你能**：说清MCP工具和普通脚本有什么区别；运行MCP 工具时，后台到底发生了什么；看懂配置里每一行在说什么；知道去哪找别人写好的工具，也分得清它和「技能」不是一回事。

## 主线（记住这一句的框）

**MCP 是给工具定的一套统一插口。** 装一个 MCP 工具，就是让你的 agent 接上一个别人写好的程序。

## 1. MCP 工具到底是什么

在第2课时，我们写了一个最小的agent，同时还写了一个查询天气的工具函数。我们在每次调用模型API时，需要把工具描述拼接在提示词中，告诉模型，当模型决定要调用工具时，响应会多一个tool_calls字段。我们解析这个字段，获取要调用工具的名称和参数，真正执行调用的是我们自己写的代码。

但是如果我们还想要查询网页，则要写查询网页的工具，想要获取当前时间，还要写获取时间的工具，我们不可能一个人写所有的工具。而且每个人的需求也不一样，我们也不可能满足所有人的需求。

最简单的办法是让agent和工具解耦合，任何人都可以写工具，我们只需要把别人写的工具接进来。“接”进来说起来容易，但是要实现有点麻烦。因为是别人写的，所以我们对工具一无所知，不知道是python脚本还是exe程序，也不知道存放在哪里。那该怎么接呢？主要有两种思路：

1. 让工具作者自己写个文档把工具存放在哪里，如何执行说清楚。这个文档放在固定的地方，agent只需要把文档内容送给模型，然后按照模型指示运行指令就好了。skill技能基本上就是通过这种方式调用工具。

2. 工具格式五花八门的，不同格式的工具要接入都要进行适配，既然这样，干脆统一标准。所有工具要接入，都按照我的标准来，工具作者自己对工具进行封装，符合我的标准的才能接入。比如，大家都提供一个API，agent只需要通过标准协议和API交互，不用管工具什么格式，存放在哪。这基本上就是MCP的思路了。

所以，到底什么是MCP呢？MCP全名叫 **MCP（Model Context Protocol，模型上下文协议）**，是Anthropic在204年11月发布的一套开放标准。开发工具的程序员只需要按照这套标准开发工具，所有同样支持MCP协议的agent软件（严格来说，应该叫harness软件）就可以接入这个工具。MCP 自己的文档拿 USB-C 打了个比方：MCP 之于 AI 应用，就像 USB-C 之于电子设备。USB-C 统一了怎么插，MCP 统一了怎么接。

## 3. 三个角色，一条连接

MCP的

**host** 是你正在用的那个 AI 应用，在这里就是 TeleAgent。你打开它，在对话框里打字，连接和工具都由它来管。

**server** 是工具背后那个服务程序。它一启动起来，就等着被问「你能干什么」，也等着被叫去干活。它可能跑在你的电脑上，也可能跑在服务商那边。

**client** 是中间那个接头。host 每接一个 server，就在自己里面配一个 client，一条连接对一个 client。一个 host 常常同时接着好几个 server，每条连接由各自的 client 单独管，互不掺和。client 装好就在，不用你写。

图注：host 不直接连 server，它给每个 server 建一个 client，一条连接对一个 client。图右边是两种 server：本地跑在你的电脑上，远程跑在服务商那边，第 5 节讲它们不一样在哪。

## 4. 连上以后，它先报自己会什么

连接一建好，client 先问 server 一句「你能干什么」。这会儿还轮不到干活。

server 回一份工具清单：每个工具叫什么、干什么用、要填哪些参数，一条条列清楚。这份清单先落在 host 手里，模型还看不见。

你说「查一下北京天气」，host 才把清单连你的话一起发给模型——进了上下文（模型这一次能看到的全部内容），模型才知道自己手里有哪些工具。它从清单里挑出天气工具，填好参数发过去；server 干完活，把结果送回来，模型再把它组织成一句回答。往后每轮提问，这份清单都会原样再发一遍。

连上先问一遍「你能干什么」，这一步叫**发现**。普通 API 不走这条路：工具的名字、说明、参数，得你一个一个整理好，跟着请求一起发给模型。MCP 的工具是连上以后自己报出来的，清单变了还能刷新。

server 报的不光是工具。它还能公布 **resources**，也就是它能读的数据：文件、数据库记录。工具是模型挑着调的动作，resources 是现成的资料，要用就直接取。还有 **prompts**，写好的提示词模板，拿来就能发给模型。

一条 MCP 连接主要给你三样东西：工具、resources、prompts。眼下用得最多的是工具，另外两样见到的机会少，知道它们也归 MCP 管就够了。

所以装完不等于能用：连接没建起来，发现和调用都不会发生。

client 和 server 一问一答的格式叫 **JSON-RPC 2.0**（请求带方法名，回结果）。协议是无状态的：每个请求自带协议版本和这次要用的功能，server 不靠「上一次连接」猜。工具清单支持订阅，server 那边增删了工具，会主动通知 client 去刷新。

## 5. 两种 server，跑的地方不一样

server 分两种，看它跑在哪。本地 server 跑在你的电脑上，靠配置里的命令把它启动起来；远程 server 跑在服务商的服务器上，你连过去就行。MCP 广场（收集现成 server 的入口站，第 7 节列了几个）给每个 server 标 Local 或 Hosted，标的就是这件事。跑的地方不同，配置里要填的东西也不同：

|                | 本地 server                                  | 远程 server                              |
| -------------- | -------------------------------------------- | ---------------------------------------- |
| **跑在哪**     | 你的电脑上，由配置里的命令启动               | 服务商的服务器上                         |
| **配置填什么** | `command` + `args`，key 放 `env`（环境变量） | URL + 鉴权（证明你有权用这个服务的凭据） |
| **怎么启动**   | 用 `npx` / `uvx` 这类命令把工具包拉下来跑    | 不用启动，填 URL 连过去就行              |

你在 TeleAgent 粘的那段 JSON，填的就是这两类东西。

## 6. 你在粘的那段 JSON

写配置是 MCP 通用的接法，MCP 项目的文档就这么教：在应用的配置文件里写一段 JSON，告诉应用怎么启动这个 server，或者怎么连上它。TeleAgent 的技能广场把安装做成了一个按钮，按钮背后干的还是同一件事——往配置里写一段 JSON。

OpenCode 没有这个按钮，你得自己把配置写进它的文件；Claude Desktop 读的是 `claude_desktop_config.json`。换一款软件，要写的还是这段 JSON，只是文件名和字段名可能不一样。

本地 server 的配置长这样（例子来自 TeleAgent 手册）：

```json
{
  "mcpServers": {
    "math-server": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-everything"]
    }
  }
}
```

`math-server` 是服务名，自己起，不用跟包名一样。`command` 是启动命令，`args` 是传给命令的参数，例子里的 `server-everything` 是 MCP 项目仓库里的测试工具包。一个 server 可以带不止一个工具——装上的是 server，agent 多出来的是它报出来的这批工具。

有的 server 还要一把 key，填在配置的 `env` 一格——环境变量，上一课放进 `.env` 的 `DEEPSEEK_API_KEY` 就是这种。别把 key 打进对话。`npx` 这类命令跟着 Node.js（一个常见的运行环境）一起装，电脑上没有它，配置写得再对也起不来。字段名各家不完全一样：TeleAgent 用 `mcpServers`，OpenCode 用 `mcp`，换一款软件就照它自己的文档填。

在 TeleAgent 里配，按它 2026-10-18 的手册是五步：

1. 头像浮窗 → **设置** → **工具设置** → **从 JSON 导入/添加**。
2. 粘贴上面的 JSON（根对象要有 `mcpServers`），保存。
3. 看状态：连上的 server 会显示绿色的**「已连接」**；首页的 **MCP** 按钮能看到正在用的 server。
4. 工具列表里可以**连接 / 断开 / 编辑**。工具改过名字之后，旧任务里记的还是旧名字。
5. 回到对话，说「算一下 2+3」，它会先发现工具，再调用。

远程 server 的配置是另一副样子：填 URL 和鉴权，没有 `command` 和 `args`，也不用 `npx`。字段的完整说明、远程配置的完整例子、配置弄错了按什么顺序查，[MCP 配置速查](../../reference/mcp-config-cheatsheet.html)里都有。

## 6. 在 TeleAgent 里安装MCP工具

在 TeleAgent 里装 MCP 工具，有两条路。一条是在技能广场找到「应用连接」，点安装；另一条是打开「设置 → 工具设置」，粘一段 JSON 配置。JSON 是一种格式固定的文本，照着填就行。两条路装完，都还得先让它连上，才能用。

广场里还有一类叫「技能」的，装上 agent 同样变能干，但多出来的东西不一样：应用连接多一个会干活的程序，技能多一份做事的办法。这一课只讲 MCP。

连上之后回到对话，说「查一下北京天气」，它就查出来了。没连上之前说同样的话，它只会说查不了。模型并没有学会新知识，只是手里多了一个能用的工具。

从你说话，到拿到结果，中间隔着一条连接。这条连接上，有三个角色。

## 7. 去哪找别人写好的工具

工具不必都自己写，多数时候别人已经写好了。国内常去的入口有三个（2026-10-18 看，产品会变）：

- **腾讯云开发者 MCP 广场**（[cloud.tencent.com/developer/mcp](https://cloud.tencent.com/developer/mcp)）：腾讯自己的和第三方的 server 都有，每个都标了 Local 还是 Hosted。
- **阿里云百炼 MCP 广场**（[文档](https://help.aliyun.com/zh/model-studio/official-and-third-party-mcp)）：详情页能复制接入配置，用它给的 key 鉴权。
- **ModelScope 魔搭 MCP 广场**（[modelscope.cn/mcp](https://modelscope.cn/mcp)）：社区 MCP，按页面给的配置接。

广场里标的 Local 和 Hosted，就是第 5 节说的 server 跑在哪；它们跟 host 不是一回事，host 是你在用的那个 AI 应用。

工具不少，但别贪多。每个工具都会进工具清单：清单越长，每次请求要带上的内容越多，费用也跟着涨；工具一多，全挤在同一个上下文里，还会互相干扰。

成本怎么算，上一课讲过；干扰是怎么回事，[LLM 底层第 3 课](../../lessons/llm/0003-kv-cache-and-prompt-caching.html)讲过。所以三个工具、自己用、只在一份脚本里跑，直接写函数最省事；同一个工具要给多个产品用，或者你想把它交给别人用，才值得做成 MCP。

装之前还要想清楚安全。工具接进来以后，用的是你的用户权限：你读写得到的东西，它也读写得到。来源怎么判断、权限怎么收窄，[Agent 篇 · 第 6 课 · 提示词注入与护栏](../../lessons/agent/0006-injection-and-guardrails.html)专门讲。

## 8. 检查一下你懂了没

**Q1　你把写好的工具发给同事，他的产品装不上。卡在哪一步？**

- 你的工具功能太少，不够他用
- 他那边没有安装你的 Python 环境
- ✅ 两家产品调用工具的格式没有统一
- 你的工具没有附一份使用说明书

答对时：对。工具本身没毛病，卡住的是「接」：两家产品调用工具的格式不一样。
答错时：麻烦不在工具的功能和文档，而在接法：每家一套，每接一家都要重写一遍对接。

**Q2　MCP 统一的是什么？**

- 统一了各家模型想问题的方式
- ✅ 统一了工具和 AI 应用之间怎么接
- 统一了各家工具的收费标准
- 统一了各家产品的界面长相

答对时：对。就像 USB-C 统一了「怎么插」，MCP 统一了「怎么接」；工具写一次，各家产品都能装。
答错时：MCP 不管模型、价格和界面，它只管工具和应用之间的那道接口。

**Q3　MCP 里的 server 是什么？**

- 就是模型本身，换了一个名字
- 一个只负责存数据的数据库
- 一份可以复用的提示词模板
- ✅ 工具背后等着被调用的程序

答对时：对。server 启动起来后等着被问、等着被调用；它跑在哪，配置就长什么样。
答错时：server 是程序，不是模型；报工具清单的是它，模型只负责挑工具、填参数。

**Q4　MCP 连接建好之后，做的第一件事是什么？**

- ✅ 问它会什么，把工具清单拿回来
- 让模型把工具的代码读一遍
- 直接让模型开始调用工具
- 把工具的名字一个个抄进提示词

答对时：对。这一步叫发现：先问它会什么，清单给模型，模型挑一个调。
答错时：清单是连上后 server 自己报出来的，不用抄进提示词，也不用读源码。

**Q5　远程 server 的配置长什么样？**

- 用 command 加 npx 把它启动起来
- ✅ 填 URL 和鉴权，不写启动命令
- 把 server 的代码复制进提示词
- 必须先把 server 下载到本地

答对时：对。远程 server 跑在服务商那边，你只要连过去；command 和 npx 是本地的写法。
答错时：远程不需要本地进程；command 和 npx 只用在本地 server 上。

**Q6　装上天气工具之后，agent「会查天气了」。这本事是哪来的？**

- 模型偷偷学会了新的知识
- 你教了它查天气的方法
- 天气服务主动找上了它
- ✅ 别人写好了工具，你把它装上

答对时：对。工具是别人写好的程序，你拿来用；MCP 装进去的就是工具。
答错时：模型不会因为安装就学会新知识，多出来的是接上的工具。
