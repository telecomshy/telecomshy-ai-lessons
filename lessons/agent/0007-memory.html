记忆：它为什么会忘，又怎么记住？

从「聊两句就忘」到「它记得你说过什么」

先别急着学，聊两句

跟 agent 说过"我住浦东、爱靠窗"，换个话题它就忘了；第二天再用，它又像第一次见你。

是模型记性差吗？不是——它压根没有"记忆"这回事。每一轮它能看见的只有"上下文"这一层：你说过的话在不在里面，决定了它知不知道。

所谓记忆，是外面的程序替它存、替它取。把这件事看清，"要不要给 agent 上长期记忆"就不再是玄学。

学完这课，你能：说清短时、长时两层记忆各管什么；面对"要不要上长期记忆"，能给出有依据的判断。

记住一条主线，后面就不会晕

模型永远只看得见上下文一层；所谓记忆，是外面的程序替它存、替它取——取回来的东西还要塞回上下文，它才看得见。

1. 它为什么会忘

模型每来一轮，都要把上下文从头读一遍——它不是"接着上次往下想"，是每次把摊在眼前的记录重看一遍。上下文里没有的事，它就不知道。

而且不是"装满才出事"。实测的规律是：上下文越长，它从里面找回信息的准确度越低——塞得越满，越容易看漏、记混。Anthropic 的文章管这叫 context rot（上下文腐烂），并说各家模型都有这现象。所以"没满就没事"是错觉。

它像一个每天失忆的员工，工作台上摊着一圈便签——便签上有的他都知道，没有的他无从想起。要紧的不是他记性好不好，是谁在替他写便签、换便签。

2. 两层记忆

记忆分两层，分界是"这次的"还是"跨会话的"。短时记忆＝上下文：这一轮里放了什么——你们聊过的话、工具查回来的结果，每轮重看一遍，会话结束就散了。长时记忆＝存在外面的东西：你的偏好、上次的结论，写在文件或数据库里，用到时再取回来。

短时记忆：上下文这一轮模型能看见的全部
→
长时记忆：外面的文件 / 数据库跨会话存着，模型平时看不见
↺ 塞不下时压缩存入；要用时程序挑几条取回，塞进上下文

图里最关键的一步是取回：长时记忆里的东西，模型平时也看不见，要先被挑出来塞回上下文，它才"想起来"。取回来的东西也是便签。

3. 长时记忆怎么存、怎么取

机制白话只有两步，而且都是程序在干——模型自己什么都存不了，它只会吐字：

存：把值得记的东西写成一条短记录（"用户偏好：东航、靠窗"），存到外面。Anthropic 的做法叫结构化笔记（structured note-taking，也叫 agentic memory）：agent 定期把笔记写到上下文之外，之后再拉回来。

取：下次遇到相关的事，把相关的几条挑出来塞回上下文。按关键词挑是最简单的做法；按"像不像"挑，就是 RAG 那条链（RAG · 第 1 课）——记忆的"取回"和 RAG 是同一套本事，只是翻的书不同：一个翻资料，一个翻你的事。

顺手还解决一个老问题：上下文快满时，把旧对话压成一段摘要重新开始（行话叫 compaction）。这不是丢信息，是把一叠便签抄成一张。

4. 该记什么，不该记什么

该进长时记忆的：稳定的偏好（"我住浦东"）、做过的结论（"上次选了东航"）、你纠正过它的话（"别用繁体"）——下次还会用到、而且不会过期的东西。

不该进的：一次性细节（今天顺手查了次天气）、全部流水账（存了也取不准，还越存越贵）、会过期的事实（今天的票价、库存——记下来就是给将来的错误埋雷）、敏感信息（存在外面，就多了一份泄露面）。

翻车的样子：该记的没记（每次都要重新解释你的需求）、记了过期的（把上周的票价当今天的）、什么都往里塞（最后什么都看不清）。

5. 要不要上长期记忆

三个问题过一遍，答案通常自己就出来了：

  1. 忘掉的那件事，下次真的还会用到吗？一次性的事，让用户重说一句，比存起来便宜。
  2. 用到时能不能一句话补回来？能，就别存——存、取、防过期样样都是成本。
  3. 存错了谁收拾？过期的事实、记错的偏好，会让它以后每次都错。

多数场景里，上下文＋让用户补一句就够用；真正值得上长时记忆的，是"反复要用、而且稳定"的东西——常驻助手的用户偏好、长期项目的结论。至于短时那层怎么管（放什么、放哪、怎么裁），是 技巧篇 0001 · 上下文工程 的地盘。

6. 动手：两层记忆跑一遍

脚本在工作区：exercises/agent/0007-memory.py，不需要 API key（用假模型，注意力放在记忆机制上）。它跑两个会话：会话 1 你交代偏好，上下文塞爆后压缩、存进长时记忆；会话 2 上下文从零开始——先答一次（不记得），程序取回长时记忆后再答一次（记得了）。

python exercises/agent/0007-memory.py

Windows 终端若中文乱码，先执行 chcp 65001 切换成 UTF-8。

===== 会话 1：用户交代偏好 =====
[上下文] +「我的偏好：爱坐东航」 已用 9/25 字
[上下文] +「我的偏好：座位要靠窗」 已用 19/25 字
[上下文] +「我的偏好：住浦东，出发走虹桥」 已用 33/25 字
  [上下文] 塞爆了 → 压缩成「用户偏好汇总：东航、靠窗、虹桥出发」，旧内容不白扔
  [长时记忆] 存下一条：用户偏好汇总：东航、靠窗、虹桥出发

===== 会话 2：第二天，上下文从零开始 =====
[上下文] 任务：帮用户订明天上海到北京的机票

-- 先不取回长时记忆 --
  [模型] 我能看见的全部＝上下文 17 字
  [回答] 不知道您的偏好，选了最便宜的那班

-- 程序替它取回长时记忆，塞进上下文 --
  [长时记忆] 按关键词「订票/偏好」取回 1 条：['用户偏好汇总：东航、靠窗、虹桥出发']
  [上下文] 取回后＝['任务：帮用户订明天上海到北京的机票', '长时记忆：用户偏好汇总：东航、靠窗、虹桥出发']
  [模型] 我能看见的全部＝上下文 39 字
  [回答] 给您选了东航 620 元那班，加 20 元要了靠窗

结论：模型两轮都只看得见「上下文」。所谓记忆，是程序存的、程序取的。

重点看两处：会话 2 里模型两报"我能看见的全部＝上下文"，前后变了；变的不是模型，是程序把长时记忆塞进了上下文。
