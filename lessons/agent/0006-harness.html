Agent 原理篇 · 第 6 课 · 初学版

Harness：你天天在用，却没分清的那个词

Agent = Model + Harness。一个公式，把三样东西的边界划清楚。

先别急着学，聊两句

腾讯 WorkBuddy、中国电信 TeleAgent、字节 TraeWork——这些都常被叫作"agent"。

但严格说，它们是 harness。

你现在跟我说话用的这套软件（OpenCode / Claude Code / Cursor 之类），也是 harness。

听着像抠字眼，其实不是：模型、agent、harness 是三个不同的东西，混了就会在后面踩坑——比如"换个模型怎么就不行了"，多半是你动错了那一层。

学完这课，你能：说清三者的区别，并且把前面五课学的东西，全部对号入座到 harness 的零件上。

记住一条主线，后面就不会晕

整个领域最好记的一条公式：

Agent ＝ Model ＋ Harness

这一课就是把公式右边的两样东西讲清楚，顺便看明白"agent"到底指的是什么。

1. 先看那个容易混的地方

日常我们会说"我装了一个 agent"。但你从网上下载下来的、双击打开的那个软件——

它不是 agent，它是承载 agent 的那套软件，名字叫 harness。

而 "agent" 指的是这套东西表现出来的行为：会自己决定下一步、会动手、会看结果再决定。

类比：你不会"下载一个厨师"，你下载的是厨房；厨师是厨房运转起来之后呈现出来的那个人。

所以：agent 是"怎么做"，harness 是"在什么里面做"。

2. 三样东西各是什么

模型（Model）

一堆权重。它只会一件事：给定输入，输出下一个 token。它自己不会挑工具、不会执行、不会记事。

Harness（运行外壳 / 脚手架）

套在模型外面的那套软件。它的活儿包括：

  • 拼 prompt（系统提示 + 工具清单 + 历史）；
  • 执行工具，把结果塞回去；
  • 管理上下文（多长、怎么截、怎么吃缓存）；
  • 施加护栏（最大步数、权限、沙箱）；
  • 加载能力（skill）、接外部工具（MCP）；
  • 以及界面、状态保存、日志。

Agent（智能体）

不是软件，是行为。当 harness 把"模型 + 工具 + 循环"组织起来之后，这套东西表现出来的那种"会自己决定下一步"的能力，就叫 agent。

术语：三个词的边界

模型＝只会算的那个零件。
harness＝套在它外面的软件。
agent＝两者合起来表现出的行为。

口语里"agent"常被借去指那个软件——这就是混淆的来源。严格说法是"agent harness"或"agent 框架/产品"。

3. 把前面五课，全部对号入座

这一步最爽：你已经学的东西，其实全是 harness 的零件。

你学过的 在 harness 里是哪一块
工具调用（tool_use / tool_result） 工具执行层——真的去动手的那部分
工具清单（名字 + 说明 + 参数） prompt 组装——harness 每轮都要拼进去
KV Cache / 稳定前缀 上下文管理——决定什么放前面、什么能省
最大步数 / 工具白名单 / 人审 护栏与权限
Skill（按需加载） 能力加载层
MCP（发现、即插即用） 外部接入层
推理 → 行动 → 观察 主循环——harness 里最核心的那个 while

看到没：你一直在学"agent 是什么"，其实一直在学"harness 里都有什么"。

4. 现实中都有谁

两类，别混：

你举的那几个：面向办公的 agent 产品

  • 腾讯 WorkBuddy——个人 AI 工作台。腾讯云官方称它是"中国 DAU 最高的生产力 agent 工具之一"，还开了 SkillHub 生态；
  • 中国电信 TeleAgent——桌面办公 Agent，官方定位就是"对标 WorkBuddy"；
  • 字节 TraeWork——同赛道的 AI 办公产品。

它们都套着自己的模型 + 自己的工具 + 自己的界面，整套就是 harness。叫它"agent"是口语，指的是它能干 agent 干的事。

面向开发者的 agent harness

Claude Code、OpenAI Codex CLI、OpenCode、Cursor、Devin……你现在用的这套就属于这一类。

一个反直觉但很实用的点

同一个模型，换个 harness，表现差很多。

因为 prompt 怎么拼、工具怎么给、上下文怎么管、护栏怎么设——全是 harness 说了算。模型只是被它喂的那个零件。

所以"某某模型不行"这个结论，得先问一句：是在哪个 harness 里试的？

5. 三个必须记住的画面

① Agent 是行为，Harness 是软件

你"装"的是 harness，"看到"的是 agent 行为。两者不是一回事，混了就会在换模型、换产品时困惑。

② 模型只负责"想"，harness 负责"能"

能不能动手、能不能记事、能不能被拦住——全是 harness 的活。模型永远只在吐字。

③ 前面五课＝harness 的零件清单

工具执行、prompt 组装、上下文管理、护栏、skill、MCP、主循环——你已经把 harness 的骨架学完了。

7. 检查一下你懂了没

Q1 从网上下载安装的那个软件，严格说是什么？

Q2 「能不能动手调工具」这件事，由谁决定？

Q3 同一个模型，换一个 harness，会发生什么？

8. 下一步

harness 这条线一收，agent 工程的全景就闭合了。剩下两个方向：

  • 工具设计：名字、描述、参数怎么写，模型才调得准；
  • 怎么知道它变好了：怎么评估一个 agent（这块资料还缺，是公认的难点）。
这节课的一手资料：
Martin Fowler — Harness engineering for coding agent users：那个公式的出处——"harness 指 agent 里除模型之外的一切，Agent = Model + Harness"。
LangChain — The Anatomy of an Agent Harness：同一公式，拆解 harness 的组成（代码、配置、执行逻辑）。
Databricks — What is an AI Agent Harness?：白话定义——"围在语言模型外面的软件脚手架：工具、记忆、沙箱、反馈回路，把模型变成 agent"。
