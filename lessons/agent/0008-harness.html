Agent 篇 · 第 8 课 · 理论

Harness：Agent = Model + Harness

Agent ＝ Model ＋ Harness。把学过的东西，全部装回这层壳里。

先别急着学，聊两句

学到现在，零件认识了一堆：循环、工具、记忆、MCP 与 Skill、多 agent、安全。但"agent 到底是个什么东西"，可能还是拼不起来。

其实它早就拼好了：你天天在用的那套软件（OpenCode / Claude Code / Cursor 之类），就是这些零件装在一起的样子。这层壳叫 harness。

这课只做一件事：拆开这层壳，指着每一块说——这是你学过的哪一课。

学完这课，你能：把你学过的东西全部对号入座到 harness 的零件上；说清为什么同一个模型换个壳表现差很多。

记住一条主线，后面就不会晕

整个领域最好记的一条公式：

Agent ＝ Model ＋ Harness

第 1 课分清了三个词：模型只会吐字，agent 是跑起来表现出的行为，你装的是中间那层壳。这一课把右边这一半拆开——你学过的课，全是它的零件。

1. 三个词的边界，再往深一层

第 1 课的一句话版本：模型只会算，你装的是壳（harness），agent 是跑起来表现出的行为。往深一层看，这句话里藏着两个经常踩的坑：

  • 口语把"agent"借去指那个软件——"我装了个 agent"，装的其实是 harness。混着说平时没事，一到"换模型怎么就不行了"就开始找错地方：你动的多半是壳那一层，不是模型。
  • 模型和壳的责任线在哪：模型负责"想"（下一个字吐什么），壳负责"能"——能不能动手、能不能记事、能不能被拦住，全是壳的活。模型永远只在吐字。

2. 壳里装了什么：零件清单

一套 harness 的活儿，拆开就这些：

  • 拼 prompt：系统提示＋工具清单＋历史，每轮拼成发给模型的输入；
  • 执行工具：模型说"要调"，它真的去调，把结果塞回去；
  • 管理上下文：多长、怎么截、怎么吃缓存（下一节专讲）；
  • 存取记忆：值得记的存到外面，用到时取回塞进上下文；
  • 施加护栏：最大步数、权限、沙箱；
  • 加载能力、接外部工具：skill 按需加载、MCP 标准接入；
  • 以及界面、状态保存、日志。

3. 专门看一块：上下文管理

壳每天干得最多的活是替你管上下文。三条取舍，都是"放什么、放哪、什么时候丢"：

  • 放什么：当前任务用得上的才进上下文——工具清单、任务说明、刚拿到的观察。用不上的别塞：每一轮都要为它买单，还会互相干扰（上下文腐烂，第 1 课讲过）。
  • 放哪：稳定的放前面（系统提示、工具清单——它们是"稳定前缀"，吃缓存），老在变的放后面（新对话、新结果）。这一条直接决定你的缓存命中率（LLM 底层 · 第 3 课）。
  • 什么时候丢：塞不下就裁——先裁最老的工具结果（往往最大最没用），摘要压缩整段历史，或者把要紧的写进记忆再清空。丢的是"原料"，留的是"结论"。

4. 对号入座：学过的课，全是壳的零件

这一步最爽：

你学过的 在 harness 里是哪一块
推理 → 行动 → 观察（第 1、2 课） 主循环——壳里最核心的那个 while
工具调用 tool_use / tool_result（第 1、2 课） 工具执行层——真的去动手的那部分
工具清单：名字＋说明＋参数（第 1、4 课） prompt 组装——壳每轮都要拼进去
KV Cache / 稳定前缀、上下文放什么（本课第 3 节） 上下文管理——决定什么放前面、什么能省
记忆：程序存、程序取（第 1 课） 记忆与状态管理——存到哪、什么时候取回
Skill（第 3、4 课） 能力加载层——按需加载
MCP（第 3、4 课） 外部接入层——发现、即插即用
多 agent：编排者-工作者、子 agent（第 5、6 课） 编排层——派活、汇总、上下文隔离
最大步数、白名单、人审、防纸条攻击（第 1、7 课） 护栏与权限——决定什么能做、什么要问人

看到没：你一直在学"agent 是什么"，其实一直在学"harness 里都有什么"。

5. 换个壳，表现差很多

最后一条反直觉但很实用的点：同一个模型，换个 harness，表现差很多。因为 prompt 怎么拼、工具怎么给、上下文怎么管、护栏怎么设——全是 harness 说了算，模型只是被它喂的那个零件。所以"某某模型不行"这个结论，得先问一句：是在哪个 harness 里试的？

6. 检查一下你懂了没

Q1 每一轮把「系统提示＋工具清单＋历史」拼成发给模型的输入——这是 harness 的哪块零件？

Q2 同一个模型，换一个 harness，会发生什么？

Q3 上下文"放哪"的取舍，直接影响什么？

这节课的一手资料：
Martin Fowler — Harness engineering for coding agent users：那个公式的出处——"harness 指 agent 里除模型之外的一切，Agent = Model + Harness"。
LangChain — The Anatomy of an Agent Harness：同一公式，拆解 harness 的组成（代码、配置、执行逻辑）。
Databricks — What is an AI Agent Harness?：白话定义——"围在语言模型外面的软件脚手架：工具、记忆、沙箱、反馈回路，把模型变成 agent"。
我是你的老师，随时打断我。比如"harness 好坏怎么比？""为什么有的 harness 特别吃 token？""我该自建还是用现成的？""多 agent 是 harness 的功能还是另一回事？"——直接问我。搞不懂就往下学，是最贵的学费。
