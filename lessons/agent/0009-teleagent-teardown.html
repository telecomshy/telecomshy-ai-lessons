拆解 TeleAgent：一个真实的 harness

拿一个真实产品，把八课的零件一块块对上号——这是收尾的大作业。

先别急着学，聊两句

前面八课都是拿玩具例子讲机制。这课换个对象：星辰超级智能体 TeleAgent——装在桌面上、你能亲手用的办公 agent。

拆它不用螺丝刀，就用一张你已经会的零件表：每个功能问三句——它解决什么？上下文和钱花在哪？翻车在哪？

学完这课，你能：看懂任何一个 harness 产品说明书背后的机制；说出它记忆子系统的设计取向；拆完顺手验一验它到底记没记对。

记住一条主线，后面就不会晕

拆壳就一个口诀：它解决什么、上下文花在哪、翻车在哪。

产品名词千变万化，落回零件表就那几块——认出零件，说明书就变成你认识的东西。

1. 拆解总览：功能名 ↔ 零件

TeleAgent 的说明书里一堆功能名，先整体对一次号（依据：官方《桌面端操作手册》，2026-10-18 抓）：

说明书里的功能 拆开是什么零件 三句问出来的点
工作空间（指定文件夹跑任务） 沙箱边界 任务发起后不能换目录；产物都落在里面
@文件 / @技能 prompt 组装＋能力加载 用什么进上下文，是你手动点名的
技能广场 / 导入 .skill / 技能自进化 Skill 系统 技能＝文件包；同一技能用 ≥20 次会自己改写
工具管理（填 JSON 连 MCP） 外部接入层 接法就是一份 mcpServers 配置
授权（允许一次 / 一直允许 / 拒绝）＋YOLO 模式 护栏与权限 改东西要人点头；全自动是你要来的
任务监控（深度思考 / 操作执行 / 任务委派） 主循环的可视 trace＋编排层 "任务委派"就是子 agent 的面板
上下文用量查看与清理 上下文管理 满了可以清一块给当前任务腾地方
定时任务 / 微信·企微·飞书接入 壳的外围（调度与界面） 循环从哪儿被叫醒、结果回到哪儿

2. 重点拆一块：它的记忆子系统

这是全课最值得看的一块——正好把第 1 课"记忆没有统一标准"坐实。TeleAgent 的记忆（产品自述口径）是按来源＋时间尺度归档的三个文件：

  • USER.md——你明说"记住"的：身份、偏好、习惯；
  • MEMORY.md——它自己从历史里推断的稳定事实（不写时间戳）；
  • daily-log/YYYY-MM-DD.md——每天的工作小结、流水，按时间衰减。

底层就是几个 Markdown 文件，不是向量数据库；检索用关键词/正则（memory_search）＋按文件名读取（memory_get）——所以语义相近但不带关键词的，可能搜不到（产品的自述也承认这点）。三种东西的载入方式完全不同：

  • USER.md＋MEMORY.md：每次会话自动注入系统提示（常驻可见，文件太大会截断）；
  • 每日日志：按需检索（你问"回顾上周"，或它觉得跟当前任务相关才去翻）；
  • 滚动摘录（LATEST_DAILY_MEMORY.md）：最近日志的片段，默认可见但不盲信。

对照第 1 课的清单：取法一族四支，它一支不落全用上了。那"管"呢——改口了怎么办？跑一遍台账演示（exercises/agent/0009-memory-ledger.py，实跑输出）：

  3/01 用户：座位记得要靠窗。
    -> 决定：记新。写进台账 #2（事实）
  ...
  3/20 用户：我现在爱坐走道了，靠窗那个不算了啊。
    -> 决定：推翻。台账 #2 标「已过期」（留底不删）
    -> 并写进台账 #4（事实）

[第二步] 台账长这样：

  编号  类型    内容                              时间    状态
  #1    事实    常坐东航；出发走虹桥（浦东太远）  3/15    有效
  #2    事实    偏好靠窗座位                      3/01    已过期
  #3    做法    订票先查东航 620 那趟             3/08    有效
  #4    事实    偏好走道座位                      3/20    有效

看 #2 那行"已过期"：改口的旧条目留底不删——今天的取回不被它干扰，问"她以前爱坐哪"还答得出。存得干净、管得住过期、取回得准，三件都对，长期记忆才是加分项；三件里任何一件偷懒，就是"时灵时不灵"。

3. 重点拆二块：权限、沙箱与人审

翻车动静越大，护栏越重。TeleAgent 的护栏拆开是四层（手册口径）：

  • 人审关卡：改文件、发消息这类操作弹授权——允许一次 / 一直允许 / 拒绝三选一；拒绝只是跳过这一步，任务继续做能做的部分。
  • 全自动开关：YOLO 模式——默认权限（每个动作都要你点头）还是全自动执行（不用确认），由你选。权限是你要出去的，不是它自己拿的。
  • 入口审查：导入的技能包要过安全审查，有风险会提示你确认——技能是文件，文件能带指令，这就是为什么要审（第 7 课细讲"纸条攻击"）。
  • 执行隔离：工作空间划定目录、代码执行分远程/自定义/关闭三档、系统级安全沙箱护权限。

4. 一个对照：OpenCode 就没有长期记忆

你正在读的这份教程，写作用的 harness 是 OpenCode——它没有长期记忆子系统。这是缺陷吗？不是，是取向。它的场景是"对着一个代码库干活"：状态都在文件和 git 里，记忆靠你喂的说明文件（AGENTS.md 这类）就够了。TeleAgent 的场景是"陪你长期办公"：你的偏好天天要用，没有记忆就是天天重讲。该不该上记忆，看场景，不看谁先进——第 1 课那三个问题（下次还用得上吗／一句话能补回来吗／存错了谁收拾）就是干这个用的。

5. 拆完怎么验：四条就够

光会拆不够，还得会验。用户版验收就四条，一节说完：

  1. 拿你自己真实的 20 个问题去测（"我上次说改走哪了？"），看答对率；故意放两三个没提过的事，看它敢不敢说不知道——瞎编是 agent 最常见的翻车。
  2. 同一任务多跑几遍看一致。单次 90% 的成功率，连做 8 次全对的概率只剩 43%——不稳，是 agent 的天性，不是你的错觉。
  3. 盯代价：积分、时间、返工。干得漂亮但烧掉一下午的，不算好。
  4. 干错了先看它干了什么：任务监控里的"操作执行"面板就是 trace。TeleAgent 的排查口径按五类走：文件读写失败（文件在不在、被占用没）／技能调用失败（选对技能没、技能要不要更新）／工具调用失败（工具连上没）／模型调用失败（key、额度）／网络请求失败（网络、代理）。先归类，再动手。
