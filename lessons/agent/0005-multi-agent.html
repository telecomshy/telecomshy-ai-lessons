Agent 篇 · 第 5 课 · 理论

多 agent 协作：什么时候该上、怎么分工

叫帮手不是白叫的。多 agent 是放大器——活对了路才放大产出，不对路只放大烧钱。

先别急着学，聊两句

一个 agent 干不完的活，叫一群来干，是不是就更快、更好？

不一定。真实数据是：多 agent 烧的 token 是单 agent 的好几倍；活太小，叫帮手纯属亏本。但活真的大——比如横跨十几个来源做调研——它又能把单 agent 甩开一大截。

学完这课，你能：判断什么时候该上多 agent；说清编排者怎么派活才不跑偏；知道这笔账怎么算。

记住一条主线，后面就不会晕

多 agent 的本质是分工换上下文：每个 worker 只看自己那一摊，干完只回结论。

省下的上下文是收益，拆活派单汇总的成本是代价——值不值，看两边的差。

1. 什么时候该上（不是默认）

先说反面：大多数活不该上多 agent。Anthropic 在自己的多 agent 调研系统里给过量级（他们自报的口径）：

  • 简单查证：1 个 agent、3～10 次工具调用就干完了——叫帮手纯属亏本；
  • 直接对比：2～4 个 worker、每人 10～15 次调用，才开始划算；
  • 复杂调研：10 个以上 worker、分工明确，才拉开差距。

该上的信号就三种：能并行的独立分身活（各查一个方向）、需要多个视角的活（正反两方、多个候选）、单个上下文根本装不下的活（一个 worker 啃一块，别硬塞一个脑子）。

2. 怎么分工：编排者-工作者

最常见的形状是一个 lead（编排者）加一群 worker（工作者）：

lead：拆活、派单、汇总

自己几乎不动手，只做三件事：把大任务拆成边界清楚的子任务、派出去、收结论合成答案。

worker：啃一块、回一句

领到一个边界清楚的小目标，自己转自己的循环；干完只交结论，流水留在自己那儿。

接口：派单三件套

每个 worker 必须拿到：目标（干什么）、输出格式（交什么）、边界（别管什么）。

派单写糊了会怎样？Anthropic 的教训原话级大意：让 worker"调研一下半导体短缺"这种含糊指令，会让他们重复劳动、互相抄、留缺口；写成"列出 2024–2026 年关于 X 的 5 篇论文，每篇一句话摘要加链接"才跑得齐。只回结论不回流水同样关键——worker 的十万字流水全塞回 lead 的上下文，lead 第一个被撑死（下一课的对账会给你看数字）。

3. 这笔账：收益和代价

  • 代价：多 agent 的 token 消耗约是单 agent 的 15 倍（单 agent 做复杂任务本身也要约 4 倍，对比的是简单任务）——全出自 Anthropic 自报口径。
  • 收益：同一个来源里，复杂调研任务上"强模型编排＋够用的 worker"比单个强模型好 90.2%（同为自报）。为什么？分工换来的上下文隔离：每个 worker 有一整个干净的上下文啃自己那块。
  • 怎么用这两个数：先问"我这活是第几档"——第一档（几个工具调用）连算都不用算，别上；第二、三档再拿自己任务试一把，比投入的 token 和产出质量。

4. 常见翻车

  • 小题大做：一个小问题 spawn 十几个 worker——烧钱且更乱。
  • 汇总变拼接：lead 把几份报告原文堆一起就交卷——读者要的是结论，不是汇编。
  • 同步等待：一个 worker 卡住，全体干等——慢的那根决定总时长。
  • 编排者一错全错：拆活拆歪了，每个 worker 都在错方向上使劲——lead 是最该测的那一个。
