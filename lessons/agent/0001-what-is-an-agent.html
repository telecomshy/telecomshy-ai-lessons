Agent 原理篇 · 第 1 课 · 初学版

Agent 到底是什么？

从「一次 LLM 调用」到「一个会循环决策的系统」

先别急着学，聊两句

你有没有想过："用 AI"和"用 agent"，到底差在哪？

同一个模型，套上不同的壳（这层壳有个正式名字，第 6 课再讲）——一个只会一问一答；另一个却能自己查资料、读文件、一步步把活干完，中间不用你盯着。

差别不在模型，在外面那层结构：一个"决定了做、做了再看、看了再决定"的循环。

学完这课，你能：说清"用 AI"和"用 agent"差在哪；亲手跑通一个最小循环，并指着它的输出说清每一步在干什么、为什么最后会停。

记住一条主线，后面就不会晕

跟单次调用比，agent 多出来的就是一个循环：推理 → 行动 → 观察 → 再推理，直到任务完成、或者撞上护栏。

本课先把循环跑通；后面每一课，都是往这个循环里加零件。

1. 一次调用 ≠ 一个 agent

大多数人第一次接触 LLM 时的模型是这样：输入一段 prompt（提示词），输出一段文本，结束。这很好用，但它没有"手"，也没有"下一步"——它不知道世界上发生了什么，也没法改变什么。

一个 agent 不一样。你给它一个目标，它会自己决定：现在该做什么？做完看到结果后，再决定下一步做什么。这个"决定了做、做了再看、看了再决定"的反复过程，就叫 agent 循环。

2. 两个真实场景，看清差别

拿一个具体的活来对比：查一张明天上海到北京的机票，合适就订。

在网页对话框里"用 AI"

你打开 ChatGPT、豆包这类网页，把需求打进去。它会回你一段很有用的文字：建议看哪几家航司、什么时段便宜、怎么比价。但它到此为止——它没有"手"：不能真的去查今天的航班，更不能替你下单。之后查航班、比价、付款，每一步都是你自己做；做完想让它总结，还得把结果粘回去。每一轮"下一步做什么"，都是你在安排。

对 agent 说同一句话

你说"查明天上海到北京最便宜的机票，合适就订"，然后去倒杯水。它自己往下走：调航班查询（行动）→ 看到 23 个航班（观察）→ 决定只看直飞、按价格排（再推理）→ 调比价、调下单（再行动）……最后回来："订好了，620 元那班。要不要加 20 元选个靠窗？"每一轮"下一步做什么"，是它在决定。

差别就三点：谁安排下一步（你 vs 它）、它有没有"手"（只能给建议 vs 真能动手）、你要不要盯着（全程在场 vs 交代完就走）。两个场景里跑的甚至可能是同一个模型——差的是外面那层壳，和壳里转的那个循环。

agent 翻车的动静更大：AI 对话答错了，损失是一句废话；agent 答错了，可能是真订错一张票。所以 agent 一定要有护栏——比如下单前先问你一声。这是后面反复出现的零件。

3. 核心循环

循环长这样：

推理 / 规划Reason：下一步做什么？
→
行动Act：调用工具
→
观察Observe：拿到结果
↺ 把观察结果喂回去，继续下一轮推理

循环只有一个出口：模型认为任务完成了，输出最终答案。如果它一直不认为完成，就会卡死在循环里——所以工程上一定要有 护栏，最常见的就是「最大步数」。

4. 每一步会怎么翻车

上面的场景走得很顺，但循环的每一步都有自己的翻车方式。先认认脸，遇到才不慌：

  • 推理翻车：方向就想歪了——比如决定"先订票、再查要不要签证"，第一步就跑偏。
  • 行动翻车：挑错工具、参数填错（把"明天"填成下个月），或者工具本身报错（航班接口超时）。
  • 观察翻车：结果就在眼前，却看错看漏——把"620 元起（中转）"当成了直飞的价格。
  • 不收尾：一直"再查一家""再比一次"，就是不说完成——所以才要最大步数这种护栏把它拦下来。

翻车之后怎么自救，写在 技巧篇 0004 · 失败模式与自救；这里先学会认出它们。循环每转一圈，都有好几处可能出错——这就是 agent"灵活"的代价。

5. 这个循环靠三根柱子撑着

领域里常用一张地图来拆 agent：规划、记忆、工具，常被叫做三大支柱（出处见文末 Lilian Weng 那篇）。对照本轨道七课：工具这条线占大头，规划散在各课的动手环节里，记忆专门用第 7 课讲——上下文里放什么，做法写在技巧篇 0001。

① 规划 Planning

怎么把大目标拆成能一步步执行的子任务？怎么在失败后改主意？

② 记忆 Memory

当前上下文里放什么？跨会话的东西怎么存、怎么取回来？

③ 工具 Tool Use

如何让模型"伸出手"去调 API、查库、改文件，并把结果读回来？

三根柱子各有各的活和翻车方式，往下钻一层：

① 规划：拆任务，和改主意

大活要拆成能执行的小步：「写一份周报」＝查数据 → 算环比 → 写结论。更难的是另一件事——失败后改主意：查不到上周的数据，就换个来源，或者先算前一周。这两件事的行话叫拆子目标和自我反思（self-reflection）：好的 agent 不是一条路走到黑，而是每走一步都回头看看要不要换条路。翻车的样子：拆得太碎、绕圈子，或者改主意改得太勤，原地打转。

还要分清两件事。规划不等于"思考"：思考是"想"的总称——验算、打草稿都算；规划只是其中管"接下来做什么"的那部分。一次普通回答里也有规划（先列提纲再写），但 agent 的规划多一层：它安排的是接下来动手做什么，还会被行动结果打回来重写——所以才有"改主意"这回事。规划的本事是模型练出来的（"会思考是练出来的"见 LLM 底层 · 第 5 课）；要不要规划、按什么格式、什么时候重来，是外壳定的——壳只能把本事叫出来，给不了它本事。

② 记忆：这次的，和跨会话的

记忆分两层。短时记忆＝这一次的上下文里放了什么：你们聊过的话、工具查回来的结果，都在里面——模型每一轮只能看见这一层，塞爆了就会忘事。长时记忆＝跨会话存下来的东西：你的偏好、上次的结论，存在外面，用到时再取回来。翻车的样子：该记的没记（每次都要重新解释你的需求），或者记了过期的错东西（把上周的票价当今天的）。

③ 工具：给模型一双手

模型只会吐字；工具让它真的碰到世界。它伸手，往往是去拿生来没有的三样东西：现在的信息（今天的航班，模型只学到旧闻）、动手算的能力（它只会吐字，真算一遍得靠工具）、你公司的数据（它训练时没见过）。工具怎么"递给"它——一张写清名字、说明、参数的清单——下一课细讲。翻车的样子：挑错工具、参数填错。

三根柱子不是循环之外的三件东西，它们就长在循环上：规划发生在"推理"那一步，工具是"行动"那一步的手段，记忆管"观察到的结果放哪、下次还认不认得"。

还有一个重要的边界概念：能用固定 workflow（预先编排好的固定步骤）解决的事，就别上 agent。agent 的代价是不确定性——它灵活，也因此难预测、难调试。这是 Anthropic 在那篇必读文章里的核心建议。

6. 动手：跑一个最小循环

下面的脚本实现了这节课的循环。它不需要 API key——里面用了一个 fake_model 假装是模型，这样你能把注意力全放在循环机制上。等你看懂了循环，把 fake_model 换成一次真实 LLM 调用，你就拥有了一个（极其简陋的）真 agent。

脚本已存到工作区：exercises/agent/0001-minimal-agent.py。运行：

python exercises/agent/0001-minimal-agent.py

Windows 终端若中文乱码，先执行 chcp 65001 切换成 UTF-8。

任务设定为：把 "hello" 反转，再拼上它的长度。脚本里只有一个循环、两个工具、一个假模型：

# ---- 工具：agent 能对外做的事 ----
def reverse_string(s: str) -> str:
    return s[::-1]


def string_length(s: str) -> int:
    return len(s)


TOOLS = {
    "reverse_string": reverse_string,
    "string_length": string_length,
}


# ---- 假模型：真实世界里，这里是一次 LLM 调用 ----
# 输入：到目前为止的轨迹(trace)。输出：一个动作(action)。
def fake_model(trace):
    used = {s["tool"] for s in trace if s["type"] == "action"}

    if "reverse_string" not in used:
        return {"tool": "reverse_string", "args": {"s": "hello"}}

    rev = next(s["result"] for s in trace
               if s["type"] == "observation" and s["tool"] == "reverse_string")

    if "string_length" not in used:
        return {"tool": "string_length", "args": {"s": rev}}

    n = next(s["result"] for s in trace
             if s["type"] == "observation" and s["tool"] == "string_length")

    return {"final": rev + str(n)}


# ---- 循环：agent 的心脏 ----
def run_agent(task, max_steps=8):
    print(f"任务：{task}")
    trace = []

    for step in range(1, max_steps + 1):
        print(f"\n--- 第 {step} 步：推理 ---")
        action = fake_model(trace)
        print("模型决定：", action)

        if "final" in action:
            print("\n[完成] 最终答案：", action["final"])
            print(f"（共用了 {step} 步）")
            return action["final"]

        tool = action["tool"]
        result = TOOLS[tool](**action["args"])

        trace.append({"type": "action", "tool": tool, "args": action["args"]})
        trace.append({"type": "observation", "tool": tool, "result": result})
        print(f"--- 观察：{tool}({action['args']}) -> {result}")

    raise RuntimeError(
        "达到最大步数仍未完成 —— 这就是经典的 agent 失败模式：死循环。"
    )


if __name__ == "__main__":
    run_agent("把 'hello' 反转，再拼上它的长度")

跑出来是这样：

任务：把 'hello' 反转，再拼上它的长度

--- 第 1 步：推理 ---
模型决定： {'tool': 'reverse_string', 'args': {'s': 'hello'}}
--- 观察：reverse_string({'s': 'hello'}) -> olleh

--- 第 2 步：推理 ---
模型决定： {'tool': 'string_length', 'args': {'s': 'olleh'}}
--- 观察：string_length({'s': 'olleh'}) -> 5

--- 第 3 步：推理 ---
模型决定： {'final': 'olleh5'}

[完成] 最终答案： olleh5
（共用了 3 步）

看这段输出，重点看三件事：① 模型从来不会一次就给出完整答案，它是一步一步来的；② 每一步它都只拿到了"到目前为止的轨迹"（trace），没有别的信息；③ 停下来的唯一原因是模型自己说"完成了"——不是代码知道答案。

再看清一件事：让这个 agent"活"起来的不是模型，是脚本里那个循环。run_agent 就是外面那层壳的袖珍版——那层壳的正式名字和它的边界，第 6 课一次讲清。

7. 挑战（选一个做，5 分钟）

  1. 改任务：把 "hello" 换成别的字符串，让它照样能算对。
  2. 加工具：加一个 to_upper(s)，让 agent 先反转、再转大写、最后拼长度。
  3. 制造失败：把 max_steps 改成 2，跑一遍，观察"死循环"是怎么被护栏拦下的。这一步最重要——它让你亲眼看到 agent 的失败长什么样。
