Agent 到底是什么？

从「一次 LLM 调用」到「一个会循环决策的系统」

先别急着学，聊两句

你有没有想过："用 AI"和"用 agent"，到底差在哪？

同一个模型，套上不同的壳——一个只会一问一答；另一个却能自己查资料、读文件、一步步把活干完，中间不用你盯着。

差别不在模型，在外面那层结构：一个"决定了做、做了再看、看了再决定"的循环。

学完这课，你能：亲手跑通一个最小循环，并指着它的输出说清每一步在干什么、为什么最后会停。

记住一条主线，后面就不会晕

agent 的全部秘密就是一个循环：推理 → 行动 → 观察 → 再推理，直到任务完成、或者撞上护栏。

本课先把循环跑通；后面每一课，都是往这个循环里加零件。

1. 一次调用 ≠ 一个 agent

大多数人第一次接触 LLM 时的模型是这样：输入一段 prompt，输出一段文本，结束。这很好用，但它没有"手"，也没有"下一步"——它不知道世界上发生了什么，也没法改变什么。

一个 agent 不一样。你给它一个目标，它会自己决定：现在该做什么？做完看到结果后，再决定下一步做什么。这个"决定了做、做了再看、看了再决定"的反复过程，就叫 agent 循环。

一句话抓住区别

单次调用里，"下一步做什么"是你在 prompt 里写死的；在 agent 里，"下一步做什么"是模型在循环里反复决定的。

2. 核心循环

整门课都会围绕这张图展开。先把它刻进脑子：

推理 / 规划Reason：下一步做什么？
→
行动Act：调用工具
→
观察Observe：拿到结果
↺ 把观察结果喂回去，继续下一轮推理

循环只有一个出口：模型认为任务完成了，输出最终答案。如果它一直不认为完成，就会卡死在循环里——所以工程上一定要有 护栏，最常见的就是「最大步数」。

3. 这个循环靠三根柱子撑着

顺着这个循环往下钻，会分出 agent 的三大支柱。这是本课程的主线骨架，后面每一课基本都在补其中一根：

① 规划 Planning

怎么把大目标拆成能一步步执行的子任务？怎么在失败后改主意？

② 记忆 Memory

当前上下文里放什么？跨会话的东西怎么存、怎么取回来？

③ 工具 Tool Use

如何让模型"伸出手"去调 API、查库、改文件，并把结果读回来？

还有一个重要的边界概念：能用固定 workflow 解决的事，就别上 agent。agent 的代价是不确定性——它灵活，也因此难预测、难调试。这是 Anthropic 在那篇必读文章里的核心建议，我们下一课会细讲。

4. 动手：跑一个最小循环

下面的脚本实现了这节课的循环。它不需要 API key——里面用了一个 fake_model 假装是模型，这样你能把注意力全放在循环机制上。等你看懂了循环，把 fake_model 换成一次真实 LLM 调用，你就拥有了一个（极其简陋的）真 agent。

脚本已存到工作区：exercises/agent/0001-minimal-agent.py。运行：

python exercises/agent/0001-minimal-agent.py

Windows 终端若中文乱码，先执行 chcp 65001 切换成 UTF-8。

任务设定为：把 "hello" 反转，再拼上它的长度。脚本里只有一个循环、两个工具、一个模型桩：

# ---- 工具：agent 能对外做的事 ----
def reverse_string(s): return s[::-1]
def string_length(s):  return len(s)

TOOLS = {"reverse_string": reverse_string, "string_length": string_length}

# ---- 假模型：真实世界里，这里是一次 LLM 调用 ----
def fake_model(trace):
    used = {s["tool"] for s in trace if s["type"] == "action"}
    if "reverse_string" not in used:
        return {"tool": "reverse_string", "args": {"s": "hello"}}
    rev = next(s["result"] for s in trace if s["tool"] == "reverse_string")
    if "string_length" not in used:
        return {"tool": "string_length", "args": {"s": rev}}
    n = next(s["result"] for s in trace if s["tool"] == "string_length")
    return {"final": rev + str(n)}

# ---- 循环：agent 的心脏 ----
def run_agent(task, max_steps=8):
    trace = []
    for step in range(1, max_steps + 1):
        action = fake_model(trace)          # ① 推理
        if "final" in action:
            return action["final"]          # 出口：模型认为完成了
        result = TOOLS[action["tool"]](**action["args"])   # ② 行动
        trace.append({"type": "observation", "tool": action["tool"], "result": result})  # ③ 观察
    raise RuntimeError("达到最大步数仍未完成 —— 死循环")   # 护栏
看输出的时候，重点看三件事

① 模型从来不会一次就给出完整答案，它是一步一步来的；
② 每一步它都只拿到了"到目前为止的轨迹"（trace），没有别的信息；
③ 停下来的唯一原因是模型自己说"完成了"——不是代码知道答案。

5. 挑战（选一个做，5 分钟）

  1. 改任务：把 "hello" 换成别的字符串，让它照样能算对。
  2. 加工具：加一个 to_upper(s)，让 agent 先反转、再转大写、最后拼长度。
  3. 制造失败：把 max_steps 改成 2，跑一遍，观察"死循环"是怎么被护栏拦下的。这一步最重要——它让你亲眼看到 agent 的失败长什么样。
