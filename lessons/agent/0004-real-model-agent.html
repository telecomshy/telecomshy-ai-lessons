换上真模型：假的骗了你哪些地方

骨架一行没改，只换了一个函数。但你会看到，真模型和假模型差得很远。

先别急着学，聊两句

前三课的脚本里，"模型"都是一个写死的小函数——我们用它把机制看清楚。

但你可能一直有个疑问：假的和真的，到底差在哪？会不会我学了半天，真跑起来根本不是那么回事？

这一课就把它换掉。会发现两件事：一是骨架真的一行不用改；二是假模型其实骗了你不少地方——而且多是往"太顺利"的方向骗。

学完这课，你能：说清换模型该动哪里、以及假模型到底骗了你哪几处。（要动手的人，能让自己的 agent 接上真模型跑起来。）

记住一条主线，后面就不会晕

agent 的骨架是循环，模型只是插在循环里的一个零件。

所以换模型这件事，理论上只该动一个函数。如果发现要改的地方很多，说明你的骨架写歪了。——这本身就是一条很好的检验标准。

1. 先看骨架：真的没改

0003 的 run_agent() 原样搬过来，一行不动：

for step in range(1, max_steps + 1):
    reply = real_model(messages, tools)        # ← 只有这一行换了函数名

    if reply 是「一段话」:
        return reply

    result = 调用那个工具(reply)
    messages.append(result)

差别只在 real_model() 内部：它现在要发一次 HTTP 请求，把各家接口的返回统一成和假模型一样的形状。

一处小差别，要老实说

各家接口要求把"模型说的那句话"原样放回对话历史（连同它那段 tool_calls）。这是接口格式的事，不是逻辑的事——但它确实是假模型时代看不到的细节。

2. 怎么配

（不跑代码可以整节跳过——下面全是运行细节，跟主线无关。）

脚本只用标准库，不用 pip install 任何东西。设两个环境变量就能跑：

$env:OPENAI_API_KEY = "sk-..."
$env:OPENAI_MODEL   = "gpt-4o-mini"          # 可选，默认就是它
$env:OPENAI_BASE_URL = "https://api.deepseek.com/v1"   # 可选，用别家才要改

然后：

python exercises/agent/0004-real-model-agent.py

⚠ 这会真的花钱，但很少——跑三次大概几厘到几分。脚本最后会把 token 账单打出来。

3. 假模型骗了你哪些地方

跑完对比一下，差距集中在这五点：

① 假模型认关键词，真模型读语义

脚本第三个问题问"魔都今天多少度"。假模型认不出"魔都"，直接翻车；真模型知道那是上海。
好处：你不用把用户会怎么问都写进 if。代价：它的"理解"你预测不了，所以它也会在你没料到的地方出错。

② 假模型不会犯错，真模型会

真模型会填错参数（写成"北京市"）、编出清单里没有的工具、该调不调（自己瞎猜个温度）、调了不该调。
所以脚本里给了 try/except 和"没有这个工具"的兜底——真 agent 的代码，一半是在防模型出错。

③ 假模型一轮就完，真模型会绕

假模型每次都精准命中。真模型可能绕几圈、可能中途放弃、也可能自作聪明提前收工。所以最大步数不是摆设。

④ 假模型不要钱不花时间，真模型两样都要

每一步都是真金白银 + 等待。这就是为什么前面 LLM 底层那几课讲的缓存、省 token，在 agent 里特别值钱。

⑤ 输出格式是接口说了算

真模型返回的 tool_calls 是接口规定好的结构（各家还不一样），不是你随便写个 JSON 就行。这就是"适配层"存在的理由。

4. 三个必须记住的画面

① 模型是可以拔插的零件

好 agent 的骨架应该做到换模型只改一个函数。做不到，就说明模型的细节渗进了你的逻辑里。

② 真 agent 的代码，一半在防错

参数校验、工具白名单、try/except、最大步数——这些不是"锦上添花"，是必需品。

③ 每一步都记账

脚本最后打了 token 账单。做 agent 就是要盯这个数——它直接是你的成本和速度。
