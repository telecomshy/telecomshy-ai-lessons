Agent 原理篇 · 第 3 课 · 初学版

把零件装起来：一个真的 agent

推理 → 行动 → 观察，跑起来就是 agent。全部核心代码只有十几行。

先别急着学，聊两句

前两课都是零件：第 1 课给了循环骨架，第 2 课给了工具调用的来回。

这一课把它们装在一起。

你会有点意外：所谓 agent，全部核心代码其实只有十几行——一个循环而已。市面上那些"agent 框架"，大多是在这个骨架上加便利和护栏。

学完这课，你能：看懂一个最小 agent 的骨架是怎么转的，说清每一步在干嘛、护栏为什么得自己加。（要动手的人，能照着写出一个来。）

记住一条主线，后面就不会晕

agent 的全部秘密就是把一个循环转起来：

推理（模型说话）→ 行动（调工具）→ 观察（看结果）→ 再推理……直到模型认为说完了。

第 2 课讲的"工具调用来回"，就是这里「行动」那一环。

1. 骨架：agent 的全部代码

先看骨架，别怕，就这么点：

def run_agent(question, tools, max_steps=5):
    messages = [系统提示, 用户问题]

    for step in range(1, max_steps + 1):
        reply = model(messages, tools)        # ① 推理

        if reply 是「一段话」:                 # 模型认为说完了
            return reply                      #    停

        result = 调用那个工具(reply)           # ② 行动
        messages.append(result)               # ③ 观察（塞回对话）

    return "走满步数，被护栏拦下"              # 护栏

没有别的了。这个 for 循环转一次，就是 agent 循环转一圈。

三种角色，一目了然

推理＝模型读对话、决定说什么或调什么。
行动＝你的程序真的去调工具（第 2 课讲的那半边）。
观察＝把工具结果塞回对话，好让模型下一步"看见"它。

三者串成一圈，转一圈就往目标靠近一点。

2. 循环长什么样

推理模型说话 / 决定调工具
→
行动程序真的去调
→
观察结果塞回对话
→
再推理它现在"看见"结果了
↻ 一圈一圈转，直到模型说「我说完了」，或撞上护栏

关键是观察那一步：结果不塞回去，模型就看不见刚才发生了什么，循环等于断了。

3. 什么时候停？

只有两个出口，都很朴素：

  • 模型说完了：它不再"说要调工具"，而是给了一段人话 → 停；
  • 撞上护栏：转了 max_steps 圈还没完 → 强制停。

为什么要护栏？因为模型可能一直"我觉得还要再查一下"，绕来绕去停不下来。第 1 课说过：agent 的代价是不确定性，所以永远要设最大步数。

4. 三个必须记住的画面

① agent ＝ 一个循环，不是一个模型

模型是零件，循环才是 agent。你换个模型，agent 还是那个 agent；你把循环去掉，就只剩一个问答机器。

② 状态全在 messages 里

这一轮走了几步、查了什么、得到什么——全都在 messages 这个列表里。想调试 agent，第一件事就是打印 messages。

③ 护栏是你的，不是模型的

最大步数、工具白名单、高风险动作人审——这些都写在你的代码里。模型永远不会自己给自己设限。

5. 动手：看它一步步走

脚本在工作区：exercises/agent/0003-mini-agent.py。它跑三个问题，把每一步的推理 / 行动 / 观察打出来。

python exercises/agent/0003-mini-agent.py

Windows 终端若中文乱码，先执行 chcp 65001。里面用的是假模型；真模型只要换掉 fake_model() 一个函数。

用户问：上海比北京热多少？
  [1] 调工具：get_weather({'city': '北京'}) → {"city": "北京", "temp_c": 26, "cond": "晴"}
  [2] 调工具：get_weather({'city': '上海'}) → {"city": "上海", "temp_c": 28, "cond": "多云"}
  [3] 完成：上海比北京热 2 度（北京 26 度 / 上海 28 度）。
  ✔ done，共走 3 步

重点看第二个问题：它连着调了两次工具，中间什么都没输出——这就是"多步循环"的意思。第一次调完，观察塞回去，它才"知道"还差上海。
