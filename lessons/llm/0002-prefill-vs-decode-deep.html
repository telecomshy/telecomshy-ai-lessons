以你输入「你是谁」、模型回「我是…」为例。每环只写三样：发生什么、这一步的输入是什么、详见哪一问。理由不重复讲，一律指回去。

  1. 分词 → 查词表：文字变成一串编号。 这一步的输入：你那段文字。出来的是一串整数。 详见 第 1 课进阶 · Q4（哪几步算"模型"）· Q1（词表多大）
  2. 查嵌入表：每个编号换一根向量，拼成一张表——n 行 × d 列。 这一步的输入：那串编号。出来的表宽度 d 固定、行数 n 随字数变。 详见 第 1 课进阶 · Q5（为什么是"表"不是"一根"）
  3. 一轮 ＝ 一个 token 从第 1 层走到最后一层　（下面这一整段才是"跑模型"） ↻ 层内循环：模型有几十层，每层 4 步——注意力 → 残差 → FFN → 残差。每过一层，表中每一行都被改写一遍。 ↻ 层内是并行的：n 行并排过，不排队。整条链真正串行的只有第 5 环的"挑字"。 ↻ 顺手做的事：每一层算出的 k、v 全部填进缓存（KV cache），后面的轮次直接取。 这一步的输入：上一环那张表。出来的是同样形状、但每行都被改写过的新表。 为什么能并行见 Q9；缓存里为什么只有 K/V 见 Q1；每步的"搬运"见 Q2；两种"键值"别混 · FFN 为什么不进缓存见 Q4
  4. 只取最后一层、最后一个位置，得到一根向量。 这一步的输入：第 3 环改写完的那张表。其它行也出了结果，但推理时没人要——作废。 为什么"只有最后一行被采用"，见 Q10
  5. LM Head：对词表里每个字打分 → 一张分数表（logits），再 softmax 换算成百分比。 这一步的输入：那根向量。出来的是词表里每个字各一个分——十几万个数。 详见 Q8
  6. 按比例挑一个（采样）→ 挑出一个 token 编号。 这一步的输入：那张百分比表。出来的是一个编号——一个整数，不是向量。 ★ 整条链唯一真串行的一步——上一个字没挑出来，就不知道下一个字是谁。详见 Q9。挑的方法（temperature 等）见 第 1 课进阶 · Q10
  7. 拿这个编号，再去查一次嵌入表 → 得到一根新向量，追加到表尾，进入下一轮、回到第 3 环。 这一步的输入：刚挑出来的那个编号。出来的是长了一行的表（n → n+1，宽度 d 不变）。 ★ 最容易跳错的一环：百分比给你的是"哪个字最像"的排行榜，不是内容。↻ 只算新增那一行——前面所有行的 k、v 从缓存取，不重算。详见 Q8
这条链之外，还有两件事

① 前缀缓存（第 3 课）：跨多次请求复用老前缀的 k、v。第 3 环每轮都在造新的 k、v——如果下一次请求的开头一字不差，那些 k、v 就不用重造。→ 第 3 课

Q1 · 「hidden 向量」是什么？为什么盒子里存的是 K/V，不是它？

对应初学版第 3 节末尾那个「货架」的说法。（总图 第 3 环）那儿说"每个字在每层留下一张标签（k）＋ 一个货箱（v）"。那在放上去之前，每个字手里拿的是什么呢？

Transformer 每一层里，每个位置都有一根向量（长度 d，比如 4096）。这根向量叫 hidden state（隐状态），日常就叫 hidden 向量。它其实不是新东西——就是初学版第 1 课那张"n 行 × d 列"表里的某一行。

它一路往上走，每过一层就被改写一次：

token 编号
  → 查嵌入表 → 一根向量
  → 第 1 层（注意力 + FFN）→ 改写成新的一根
  → 第 2 层 → 又改写成新的一根
  → ……
  → 最后一层、最后一个位置 → lm_head → 打分 → 挑出下一个字

（每一层里"改写"具体是哪几步，见 第 1 课第 3 节；这条链的后半段——打分、挑字、再变回一根向量——见 Q8。完整的一条链在上面的总图。）

关键：这些 hidden 向量，模型不存。盒子里存的是每一层注意力算出来的 K/V。

为什么可以不存 hidden？因为算下一个字的时候，历史 hidden 根本用不上：

  • 新字的 Query 要查的，是历史每个位置的 Key（看谁跟它相关）；
  • 再按相关度取走的，是那些位置的 Value。

K 和 V 是从 hidden 投影出来的两样东西——一张标签（K）、一个货箱（V）。要查的时候，扫标签、取货就行，不必把 hidden 序列再算一遍。

所以盒子里装的是：每一层、每一个历史位置的 K/V。不是 hidden 向量。

别跟 Q10 打架：这句话说的是 decode，不是 prefill

Q10 说"前面每个位置的注意力都得算、一个都省不掉"——那是 prefill 阶段的事：那一轮所有位置本来就一起算，hidden 自然会一层层往下传。

而这里说的"用不上历史 hidden"，是 decode 阶段的事：不需要把历史位置重新算一遍，因为它们的 K/V 早就存在货架上了。

两句话讲的是两个阶段，不冲突。prefill 负责把 K/V 造出来，decode 负责复用它们。

（这解释了一个常见的疑惑："为什么缓存不叫 hidden cache？"——因为它存的根本不是 hidden。）

（还有一问常被跟这题混在一起：FFN 是不是也有一份 K/V？不是，那是另一个"键值"。→ Q4）

Q2 · 「搬」和「算」是两个阶段，还是同一个过程？

对应初学版第 4 节。初学版说 decode 卡在"搬"。（总图 第 3 环 · 每一步的代价）但很容易读成"先搬完，再开算"——不是的：搬和算在同一个前向里交替、流水线式发生。

假设正在生成第 t 个字，走进第 l 层：

  1. 搬权重：把这一层的 Q/K/V 投影矩阵、输出矩阵、FFN 权重，从显存读到芯片上；
  2. 搬历史 K/V：把第 l 层货架里所有历史的 K/V 读出来；
  3. 算这一步的 Q/K/V：只用当前这一个字的向量（就是刚挑出来那个 token 重新查嵌入表得到的那根，Q8），算出它自己的 q、k、v；
  4. 写回：把它刚算出的 k、v 追加到第 l 层货架的末尾；
  5. 算注意力：用当前 q 去比货架里所有历史 K/V；
  6. 算 FFN；
  7. 交给下一层，重复 1–6。

把上面那些"搬"和"算"按量排一下，就看出问题在哪了：

动作 每步的量 说明
读模型权重 很大 每吐一个字都要重来一遍
读历史 K/V 大，序列越长越大 这半截随上下文变长
写新的 K/V 很小 只有这 1 个字的量，可以忽略

所以：带宽压力全在"读"，不在"写"。顺序上还有一个容易搞反的点——

一个容易搞反的顺序

是先把当前的 k/v 算出来、写进货架，再拿当前的 q 去比；而不是"先比完再写"。
所以当前这个字也会看上自己一眼——因果掩码的规矩是"能看自己和它之前的所有位置"（原始论文的措辞：attend to all positions in the decoder up to and including that position）。

另外，GPU 会尽量让"搬"和"算"重叠——搬下一批数据的时候，计算单元正在算上一批。但 decode 的问题是搬的活实在太多，重叠也填不满，所以整体瓶颈仍然是搬。

Q3 · 「算力受限 / 带宽受限」是怎么算出来的？

对应初学版第 4 节（prefill 卡算力、decode 卡带宽）。（总图 第 3 环 · 每一步的代价）初学版给的是结论，这里给算式。

用一个词量这件事：算术强度（arithmetic intensity） ＝ 干了多少次运算 ÷ 搬了多少字节。翻译成人话就是：每搬一个字的数据，能榨出多少计算。

看算式（可跳过）——那个数是怎么估出来的

设 d 是向量长度、L 是一次处理多少个 token：

阶段 计算量约 要搬的约 算术强度约
Prefill（一次 L 个） L × d² d²（权重） L
Decode（一次 1 个） d² d²（权重）＋ K/V 1

关键在权重那份是共享的。DistServe 论文（附录 A.2/A.3）把这一步写成四个矩阵乘法（GEMM），形状是这样的：M=(t,h)、N=(h,·)（t 就是这一趟有几个 token，h 是向量长度）。权重 N 那一半不随 t 变——不管 t 是 2 万还是 1，权重都是同一张、都要整张读一遍；变的是 M 那一半，它就是喂进来的行数。

论文给这两个阶段的算术强度（AI ＝ 运算次数 ÷ 搬运字节数）就是 O(t) 对 O(B)（B 是 batch size）：prefill 的 AI 随 token 数线性涨，t 到几百时在 A100 上超过 156 的阈值，确定是算力受限；decode 把 t 换成 B（常常就是 1），AI 掉回常数级，论文原话是"这四个运算全是 memory-bound"。

论文给的延迟公式里能直接看到这件事——T_prefill = C₁(4th²+2thm) + C₂·3ht²/b，T_decode = C₄(4h²+2hm) + C₅·3ht：权重那半截（4h²+2hm）两边一模一样，差的全在后面那几项——2 万行要算 2 万行那么多乘法，1 行就只算 1 行。搬的量级是同一量级，算的量差 2 万倍。这就是初学版那句"卡的不是算，是搬"的公式依据。

结论只看两句：

  • prefill：一次要算一大批 → 强度高，卡算力。
  • decode：一次只算一个 → 强度低，卡带宽。

而一块 GPU 的"算力 ÷ 带宽"这个比值，通常有上百到几百。decode 的强度跟它差得非常远——意思是：它拿到的数据，根本喂不饱计算单元，绝大部分时间在等。

这就是"卡在带宽"的严格含义。

查资料时你会撞上另一个数字：60–80

Weka 那篇里写着 decode 的算术强度实测是 60–80，跟上面这个"1"差得挺远。不矛盾，是两把尺子：上面那个只算"一次矩阵乘"最理想的情况，算出来是个下限；60–80 是整个模型跑一步的实测平均，中间的损耗全算进去了。

你只要带走一句：不管用哪个数，跟显卡的"算力 ÷ 带宽"（上百到几百）比，都还差着一个数量级上下——所以结论永远是那句"喂不饱计算单元"。

（顺带：L 越大，prefill 的算术强度越高。所以输入越长，prefill 越"划算"——一次搬权重，能算一大片。）

看公式（可跳过）——那个 n×n 的"比较表"到底怎么一次算出来

注意力这一步也是矩阵乘。Q、K 都是 n 行，把它们乘起来就是 n×n 的分数表：

S = Q · Kᵀ / √d_k        ← n×n，每一格 = "第 i 行的 q 跟第 j 行的 k 有多像"
O = softmax(S) · V         ← 按每一行的权重，把 V 加权取回来

为什么能一次算完：第 (i, j) 那一格只吃一个 qi 和一个 kj，两样都是现成的 → 每格互不依赖，整张表一次填满。

顺带解释了一件事：因果掩码是在整张 n×n 表算完之后才把"不该看"的那半遮掉的——位置 1 跟位置 3 的相似度白算了，然后扔掉。所以即使有掩码，prefill 干的活仍是完整的 n² 那一份，掩码不影响"算了多少"，只影响"哪些分作废"。这正是 prefill 算力吃紧的根源。

Q4 · 两种「键值」别混：注意力的 K/V 是机制，FFN 的键值记忆是比喻

对应总图第 3 环 · 里面那步 FFN，以及第 1 课第 3 节③那一步。一词两义的坑：论文里 FFN 也常被形容成一张"键值记忆"表，但那和缓存里那份 K/V 不是一回事。FFN 那一步到底在改什么 → 第 1 课进阶 · Q7；这里只讲它为什么不进缓存、以及那个比喻到底怎么回事。

没有。盒子里说的 K/V，专指注意力那一步算出来的东西——每一层只有注意力那一份，FFN 没有。

理由：FFN 不回头读历史。注意力要去看所有历史位置，所以它的产值得留着被后面反复读；FFN 是逐位置处理的（每一行各走各的，谁都不看）——没有"被后面复用"的东西，就不需要缓存。

（跟 Q1 是一对：Q1 讲"盒子里为什么只有 K/V"，这里讲"为什么 FFN 不往盒子里放东西"。）

不过要小心：FFN 也常被形容成一张"键值记忆"表。那是另一个意思的"键值"：

注意力的 K/V FFN 的"键值记忆"
谁产生的 注意力那一步算出来 FFN 的两层权重
「键」是什么 每个 token 的"我是谁" 训练里学到的文本模式
「值」是什么 每个 token 的"我带了什么" 输出词表上的一个分布
干什么用 决定"看谁、取什么" 决定"该补充哪个概念"
会缓存吗 会 不会，也没意义
性质 机制 比喻（解释它"像"查表）

来源是 Geva et al.（EMNLP 2021），论文标题就叫《Transformer Feed-Forward Layers Are Key-Value Memories》：

FFN 层像键值记忆：每个键对应训练语料里的文本模式，每个值对应输出词表上的一个分布。

论文给的原例：前文是 Eiffel Tower is located in 时，某一条"记忆"被触发，把 「Paris」 的分往上推。

那是"解释它怎么工作"的比喻，跟缓存一点关系都没有——它每用一次都要重新查，没有"存起来下次再用"这回事。展开见 第 1 课（进阶版）· Q7。

Q5 · 缓存命中时，「计算」具体指什么？

对应初学版第 2 节末尾那两个词（总图 第 7 环 · 缓存命中时那一段算哪一步）（「一遍」「一次请求」）和第 3 课的前缀缓存。这里要拆开一个容易含糊的词："计算"。

先把两件事分开——它们都常被叫"处理"，但贵贱差着好几个数量级：

步骤 干什么 贵不贵
tokenize 把新文字切成 token 编号 很轻（常在 CPU 上做）
前向传播 编号 → 查嵌入 → 逐层算 → 打分 → 挑出一个字 这才是"计算"

所以命中缓存不等于"新增部分 tokenize 一下就完了"。真实流程是：

新增文字 → tokenize → 查嵌入
   → 逐层前向（每层算出新增 token 的 K/V，追加进货架）
   → 用最后一个位置的输出来预测第一个回复字
   → 之后进入正常 decode 循环

新增部分可能有好几个 token，而且都是已知的输入（不是模型一个个挑出来的），所以可以并行算——这本质上就是一次小型 prefill。

术语：这叫 增量 prefill（incremental prefill），也叫部分 prefill。
判断标准不是"从第 1 个 token 开始算"，而是：对一段"已知输入"做并行前向、算出每层 K/V 填进缓存，最后拿最后一个位置预测下一个字。

新增提问恰好全符合——所以它算 prefill，不叫 decode：

这一段 算不算 叫什么
整个 prompt，从头 要算 全量 prefill
命中的老前缀 不算，复用 ——
新增的那一段 要算（可并行） 增量 prefill
之后每吐一个字 要算（只能串行） decode

Q6 · 多轮对话、agent 跑起来，prefill 会反复发生吗？

对应初学版第 2 节末尾的「一次请求」。（总图 整条链被重跑一遍的场合）初学版已经把"一次回复内部"说清了（prefill 只发生一次）。这里只补更大的一层——请求与请求之间。

每来一段新的输入，就再来一次 prefill。

用户第 1 句  → prefill → decode × N（助手回复）
用户第 2 句  → 又一次 prefill（通常增量，复用前面的 KV）→ decode × N

所以完整口径是：

每一条新的用户输入，都会开启一次新的「prefill + decode」循环。但在一次回复内部，prefill 只发生一次。

agent 就是把这句话放大几十倍：一次任务发出十几次请求，就是十几段这样的循环（初学版第 5 节讲它的代价）。

Q7 · 「必须全部读一遍」有没有例外？

对应初学版第 4 节末尾那句"有没有例外"。（总图 第 3 环 · 读缓存那一步）有——这里展开。

初学版说的"每步都要把整个货架读完"，是标准注意力（dense attention）的性质——不是物理定律。

做法 每步读多少 代价
标准注意力 全部历史 显存和带宽都随长度涨
滑动窗口（sliding window） 只读最近 N 个位置 更快更省，但老信息够不着了

要注意：滑动窗口是真的把老货位扔掉（不是"留着但不读"）——所以它省的不只是带宽，还有显存。

生产上确实在用。Mistral 7B 就是滑动窗口：官方原话是每一层只关注前 4096 个 token，靠层数堆叠把有效上下文撑到 32k。所以这不是教科书里的选项，是跑在生产上的模型的选择。

所以初学版那句"每步都要把整个货架读完"，完整版是：在标准注意力下成立。

Q8 · 模型最后吐出来的，是「字」还是「向量」？

对应初学版第 1 节的「出口」那一条。（总图 第 5–7 环）那儿一笔带过："最后那根向量拿去打分，再挑出一个字"。这里补上中间那个容易漏掉的环节。

最后一层的输出是一根向量——它既不是"字"，也不会变成下一轮的输入。中间隔着整整一套动作：

最后一层、最后那根向量
      │ ① 乘上「反嵌入表」—— 给词表里十几万个字，每个打一个分
      ▼
  十几万个分数（叫 logits）
      │ ② softmax → 换算成百分比
      ▼
  十几万个百分比
      │ ③ 挑一个（挑最高的，或按比例抽——这一步叫采样）
      ▼
  一个 token 编号   ←←←  这个才是「蹦出来的那个字」
      │ ④ 下一轮：拿这个编号去查表
      ▼
  一根新向量 → 再走一遍

向量 →（打分）→ 分表 →（挑一个）→ 字 →（查表）→ 新向量。

中间那一步不能省——模型直接产出的不是字，是一张"对每个字打的分"；字是从那张分表里挑出来的。

为什么要绕这一圈？因为模型天生就是干"从词表里选一个"这件事——它训练的目标就是这个。而下一轮的输入，要求的是一串 token 编号（模型只认编号，不认向量）。

（顺带一个容易说错的：模型的"输出"严格说是一张对词表里每个字打的分表，不是一个字。从分表里挑出一个字这一步叫采样——怎么挑，由你随请求一起传的「采样参数」决定（temperature、top_p、seed 这些，"挑最高分"只是其中一种）；而真正执行"挑"这个动作的，是跑模型的那个推理引擎。三步的细节见 第 1 课第 3 节⑤，那些旋钮各在调什么见 第 1 课进阶 · Q10。）

Q9 · 为什么第 1 轮那一整批字可以一起算，不用排队等前面？

对应初学版第 3 节里"所以第 1 轮能一起算"那一行（初学版只留了一句，展开在这里）。

先分清一件容易混的事：注意力这一步，其实是两步，不是一步。

第一步：把整张表一次性投影出每个位置的 q、k、v（三个大矩阵乘）。
第二步：拿各自的 q 去比 k、按比重取 v——算出每个位置各自的注意力。

很多人以为这两步是一起做完的，于是产生一个矛盾："既然每个字都要看前面的字，那不就得分先后？"——不矛盾。因为第一步已经把全部位置的 k、v 一次性备齐了，轮到第二步时，各查各的，互不等待。

把两步的依赖摊开看：

动作 依赖谁 能不能并行
① 从整张表投影出 q、k、v 只依赖各自的向量，跟别的位置无关 能，n 行一次算完
② 拿 q 比 k、取 v 依赖前面所有位置的 k、v 也能——那些 k、v 在 ① 里已经备齐
③ 挑出下一个 token 依赖本轮所有位置的输出 挑完之后，才知道下一轮该算哪一行

所以 1 和 2 都不构成"排队"。真正让整个流程串行的只有第 ③ 步：下一个 token 还没被挑出来，就没法开始算它。

一张表看完「哪里并行、哪里串行」：

一层之内，n 个位置之间　→　没有依赖，一次算完
层与层之间　　　　　　　→　有（一层做完才做下一层），但每层内部仍是并行的
挑出下一个 token　　　　→　真串行，要等上一个被选出来

整条流水线里唯一真正串行的，就是"挑 token"那一步。其余全是"大矩阵乘"。

看公式（可跳过）——为什么第一步能一次算完

第一步就是三次矩阵乘，X 是那张 n 行 × d 列的表，W 是学出来的权重：

Q = X · W_Q        K = X · W_K        V = X · W_V
（n × d）乘（d × d）得到（n × d）——n 行同时算完

每输出行只依赖自己的输入行加共用的权重，不依赖别的输出行——这就是"能并行"的全部原因。像 Excel 公式往下拉。

（顺带回一句初学版第 2 节：第 2 轮起"只补刚挑出来的那一个字"，不是因为"只能一个一个算"，而是因为下一个字还没被挑出来。这两件事很容易被混为一谈。）

Q10 · 前缀里的字自己也要算注意力吗？（一个很容易想歪的地方）

对应初学版第 3 节那句"每个字的注意力都要算，一个都不少"。初学版给了结论，这里说清为什么不能省。

先摆出那个错想法——很自然，我第一次读也想过：

一个常见的错想法

"第 1 轮不就是为了预测第一个字吗？前面那些字只要把 k、v 提供出来就行，它们自己不用回头看前面的字、不用算自己的注意力。"

答案是：不行，一个都省不掉。理由只有一条，但很关键：

每一层的 k、v，都是从上一层改写后那行数字里投影出来的。
所以位置 2 在第 1 层算出来的注意力结果，会变成它在第 2 层的输入。

换句话说：每个位置算出来的注意力不是终点，是下游每一层都要接着用的原料。你省掉它，后面每一层读到的东西就都变了。

亲手量一量

脚本在工作区：exercises/llm/0002-why-all-positions.py。它用一个 4 层玩具模型，依次让某个字"不回头看前面"，再量最后一个位置偏了多少。

python exercises/llm/0002-why-all-positions.py

Windows 终端若中文乱码，先执行 chcp 65001。数字是手编的，只看关系、不看绝对值。

若「天」不回头看：最终向量最大差 0.0000，原始分最大差 0.0000  （它本来就没有「前面」可看）
若「气」不回头看：最终向量最大差 0.1533，原始分最大差 0.0553

  （让「气」不回头看，每跑完一层就量一次最后一个位置的向量偏差）

    跑完第 1 层    偏差 0.0000
    跑完第 2 层    偏差 0.0482
    跑完第 3 层    偏差 0.1002
    跑完第 4 层    偏差 0.1533
最值得盯的是「跑完第 1 层 偏差 0.0000」这一行

位置 2 在第 1 层明明变了，可最后一个位置一点没受影响。这不是"没影响"，而是影响还没传过来：

因为在第 1 层里，最后那个位置读的是位置 2 的 k、v——而那两个数是从第 0 层的嵌入投影出来的，还没混进位置 2 的注意力结果。位置 2 的注意力要到第 2 层才被读到。偏差正是从那一层开始冒出来的，然后一层层放大。

顺带一提，那行「天 → 0.0000」是个漂亮的反证：位置 1 本来就没有"前面"可看，所以它无论如何都不受影响。这说明影响不是凭空来的——是真真切切把它的注意力结果用掉了。

那么，真正只算最后一个位置的，是哪一步？
只有最后那一步「打分」（把最后一行的向量对词表对分）。
前面每个位置也各自出了个预测，但推理时没人要——那才是真正被丢掉的部分。
（这跟第 1 课第 4 节收尾是同一件事：每个位置都猜了一个下一个字，只有最后一行的猜测被采用。）

附 · 一个容易说错的用词

权重不是"被算"的

"算"这个词容易把权重也卷进来。其实：权重是参数，它是参与矩阵乘的那一方；真正"被算出来"的是激活值、Q/K/V、注意力结果、FFN 输出这些。
说"搬权重、算激活"比说"算权重"准确。
