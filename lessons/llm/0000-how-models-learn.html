模型是怎么学出来的

这是一门先导课：先弄清大模型作为程序是怎么回事、那些数字又是哪来的，再去看它们怎么被算。读第 1 课之前先看这篇。

先别急着学，聊两句

先说一件听着有点怪的事：大模型确实是人写的程序，代码是工程师一行行敲出来的。

它和普通程序唯一的区别是：普通程序写好就写好了；大模型写好的只是"骨架"，还得再训练一次，那才算真正写完。

而骨架里那些数字——也就是模型里唯一的东西——没有一个是人填的。你可能一直以为它们是工程师一条条编进去的规则，像写 if 那样：其实一条都没有。

那这些数是哪来的？——学出来的。而且"学"这件事比你想的朴素得多，就四步：出题 → 对答案 → 扣分 → 改。

学完这课，你能说清：这些数字是哪来的、是怎么被调出来的，以及为什么它天生只会"接下一个字"。

记住一条主线，后面就不会晕

训练 ＝ 出题（文本自带答案）→ 作答 → 算扣分 → 往少扣分的方向拧一点点 → 重复几百亿次。

模型里所有的数字，都是被这一句磨出来的。接下来每一节都挂回它。

1. 先说背景：大模型也是人写的程序

说在最前面，免得后面全是术语没有落点：今天的大模型确实是一个程序——有人写代码、有结构、跑在机器上。这一点和 Excel、和你手机里的 App 没有区别。

它和普通程序唯一的不同，是多了一个阶段。普通程序员写完就完了：代码交出去，行为从此固定，改一行得重发一次版本。

普通程序

程序员把规则一条条写死进去。写完了就是终稿，行为从此确定。

没有"训练"这回事。

大模型

程序员写完的只是一副空骨架——结构有了，但里面该填什么数还不知道。

还要再过一遍训练，那些数才会被填上。训练完才算"写好"。

这副空骨架有个正式名字：神经网络（neural network）。别被名字唬住——它一点也不神秘，说白了就是一大堆"乘加"操作一层层摞起来：上一层的输出进来，按一堆数字重新配比一遍，得出新的输出，再交给下一层。今天这个具体摞法叫 Transformer，是第 1 课要拆的东西。

所以"训练"这两个字，指的就是把这个空骨架里的数字一个个填上。这些数字叫权重（weights），也就是本课从头到尾说的那个"数字"——整个模型里唯一的东西。

读完这节，你大概会想追问这些

骨架有了、数字也填上了——那这副身体里面到底装的是什么，长什么样？

  • 文字怎么变成数字，又怎么变回字？中间那几十层在干什么？→ 第 1 课 · 从「token」到「下一个 token」
  • 一次回答里，这副身体被用了多少次？为什么打字是一个字一个字蹦的？→ 第 2 课 · prefill 与 decode
  • 每次请求都要从头再算一遍，能不能复用？→ 第 3 课 · KV Cache 与缓存命中

本课的主线其实只有一件事：那些数字是怎么被填上去的。因为不看懂这一步，后面那些"为什么"就都没有着落。

2. 这些数字是哪来的？不是人写的

一个模型里只有一样东西：一大堆数字。它们有个名字——权重（weights），也叫参数（parameters）。它们是参与计算的那一方，不是被算出来的结果——被算出来的，永远是每一层的输出。

  • 有多少？当年的 GPT-2 小模型有 1.24 亿个；今天的大模型是几千亿到几万亿。
  • 人写的是什么？是骨架——几十层怎么摆、每层干什么（上一节那个神经网络）。但骨头缝里那些数字，一个都不是人填的。
  • 一个常见误会：以为工程师在"调参数"。工程师调的是训练怎么跑（喂多少数据、跑多久、每次拧多少），不是那 1.24 亿个数本身。

3. 怎么学的？四步，反复几百亿次

① 出题

抓一句现成的话，比如「天气很」，问它：下一个字是什么？

② 对答案——答案就写在原文里

那句话本来就是「天气很好」。不用人标，文本自己带着答案。

这就是 LLM 训练最漂亮的一点：随便抓一段话，把它往后挪一格，就同时得到一道考题和一份标准答案。语料有多少字，就有多少道带答案的考题。

③ 算扣分

它先吐出一张百分比表：好 62%、冷 26%、差 12%。答案是「好」，它给了 62%——还行，扣 0.47 分。要是只给 1%，扣 4.6 分。

扣多少是算得出来的，一个数。给得越准，扣得越少。

④ 改：往少扣分的方向拧一点点

回头追一句：这次没拿满分，是哪些数字造成的？数学上有个办法，能一次算出几十亿个数字各自该往哪边拧，不用一个个试过去。

然后每个数字都往"少扣分"的方向拧极小一步。不能拧猛了——拧猛了会把之前学会的冲掉。

"反向"是什么意思

做题是从前往后的：字 → 数字 → 一层层走过 → 一张百分比表。

算账是从后往前的：先看这张表差多少，再看最后那层该负多少，再往前一层……一路追到第一层。"反向传播"说的就是这个从出口往回追责的顺序。

所以那些数字虽然没有各自的目标，却被"少扣分"这一句管得死死的——每层该学什么，是被追责追出来的。

4. 所以它天生会什么、不会什么

会的：接下一个字，接得很像。

不会的：它学的是语料里的统计规律，不是"事实"。语料里有什么，它就信什么；语料里一处有两种答案，它就学成"五五开"。

  • 它给的不是答案，是一张百分比表。所以同一个问题问两次，答案可能不一样——"挑哪一个"是后面的事，见第 1 课进阶 · Q10。
  • 它会一本正经地胡说。因为它的任务从头到尾都是"接得像"，不是"说得对"。它没有"对不对"这个概念，只有"像不像"。
  • 所以后面每一课都挂在这儿：为什么胡说、为什么两次不一样、为什么要小心喂给它的话、怎么判断它做得好不好。
这一条很违反直觉，值得多说两句

"它只会猜下一个字"这句话，跟你的日常经验是打架的。你用的每一个模型，答起问题来大部分是对的，能写代码、能算数、能讲道理、甚至承认自己不知道——看起来相当有智慧。

那这两句话怎么对得上？靠量变到质变——术语叫涌现（emergence）。

"猜下一个字"这个任务本身，从没变过。变的是它的规模：语料从几 MB 到几万亿 token，权重从几百万到几千亿，参数量、算力、数据一起涨上去。

而这个任务有个特性：要猜得越准，就得把语料里的一切都压进那些数字里——语法、事实、推理步骤、代码习惯、说话的分寸。规模足够大之后，被压进去的东西多到足以覆盖你随手问的绝大多数问题，于是同一个目标跑出来的结果，看起来就像"懂了"。

所以两件事同时成立，而且不矛盾：

  • 它表现出来的样子，确实越来越像人——这是真的，不是错觉，量变确实到了质变那一侧。
  • 它内部做的事，仍然只有"接下一个字"——没有凭空多出什么"智慧模块"。

这件事的代价就摆在旁边：既然"像"就是全部标准，那么一段胡话只要写得够像，它就同样高分。它没有"我说的是不是真的"这根弦，因为训练里从来没有这项打分。所以你不能拿"它很聪明"去推断"它不会错"，也不能拿"它只是瞎猜"去否认它真的会做对事。

要拿捏住这个分寸，你只需要随身带着这一句：模型不管对不对，只管像不像。

脚本在工作区：exercises/llm/0000-how-models-learn.py。它让一个玩具"学"会接下一个字——骨架被简化到只剩一张表（真实模型是几十层矩阵，那是第 1 课的事），但训练的方式一模一样。

python exercises/llm/0000-how-models-learn.py

输出里有三处要看懂：

  • 扣分一路往下掉——它在"变好"，而变好的唯一标准就是扣分变少。
  • 看「很」那行，三个都在三成上下：因为语料里「很」后面三种都出现过、而且一样多。看「天」那行是五五开：一半跟「气」（天气很…），一半跟「很」（雨天很…）。它给的是一张百分比表，不是一个答案。
  • 扣分停在 0.599 不再降——那不是它笨。「气」后面永远是「很」，所以能扣到 0；「天」后面有两种答案、「很」后面有三种，再聪明也只能按比例猜，那部分扣不掉。是语料本身就有不确定性。
