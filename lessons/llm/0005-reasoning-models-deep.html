LLM 底层 · 第 5 课 · 进阶版

会思考的模型：谁写的、怎么切的、谁收着、怎么练出来的

初学版讲「那段思考是什么、值不值」，这篇答四个更细的问：那段字是谁写的、边界是谁切的、签名里收着什么、它又是怎么练出来的。按需跳读——每问都能从初学版末尾那份清单直达。

怎么用这篇

只收读完初学版仍会冒出来的疑问；初学版讲过的（「先打草稿再交卷」「四笔账」「你看到的是摘要」）这里不重复。

⚠ 这一课有个别处：开源和闭源两套做法差得很大——每问里都分开写，别拿一家的机制当通例。

Q1 · 你看到的那段「思考」，到底是谁写的？

先钉最要紧的一条：思考是你对话的那个模型做的——草稿是它一个字一个字写出来的。容易混的是后面那一步：

闭源 API 给你的那段字是摘要，不是草稿（开源给的是原文，见下表）。Anthropic 的文档明说，这个摘要是另一个模型提炼的——原话「Summarization is processed by a different model from the one you target in your requests. The thinking model does not see the summarized output」。也就是说：思考的模型只管想，它自己都看不到摘要。而且摘要不必等全部想完——「summaries can stream as they arrive」，随想随往外冒。

原始草稿谁都拿不到：「No display setting returns the raw chain of thought」，怎么设置都一样。可计费还是按草稿的全长收（「full thinking tokens … not the summary tokens」）。草稿没消失——它被加密收进了块上的 signature 字段（Q3）。

把三家摆在一起看最清楚——同一句「你看到的思考」，三个意思：

谁 你拿到的那段字 草稿去哪了
Anthropic（Claude 的 API） 摘要——另一个模型提炼的 加密收进 signature，原文不给
OpenAI 摘要（分「简版／详版」两档）——没说是谁提炼的 「we don't expose the raw reasoning tokens」；带回答案靠 encrypted_content
开源（DeepSeek-R、Qwen3 这类） 原文——没有摘要这一步 就在 reasoning 字段里（「designed to generate outputs containing both reasoning steps and final conclusions」）

一句话收口：闭源给你「汇报」，开源给你「日记」。而「摘要是另一个模型做的」这句，目前只有 Anthropic 白纸黑字写了——开源没有这一步，OpenAI 没说是谁做，别把它当通例。

Q2 · 草稿的字是怎么变成「块」的？边界是谁切的？

开源那套：模型只吐一条字流，记号是它自己写的。这条流里先草稿、后答案，中间夹着边界记号——Qwen3 和 DeepSeek-R 系就是一对 <think> / </think> 标签。记号本身就是模型词表里的 token：vLLM 里 DeepSeek-R 的解析器源码写着 start_token = "<think>"、end_token = "</think>"，还要先查出它们的 token 编号。

推理引擎（跑模型的服务程序，vLLM 是其中一个）拿到这条流之后，不理解内容，只认记号切一刀，装进「思考／答案」两个字段——vLLM 文档的说法是「extracting reasoning content from the model output」。切分，不是理解。

为什么引擎不能自己插记号？因为它不知道该切在哪。切点是模型自己的决定（它觉得想完了就转去写答案），引擎只看得见一串 token、看不懂字。实证有一条很硬：vLLM 想提前收掉草稿（思考额度用尽）时，做法是逼模型把结束记号自己吐出来——原话「vLLM forces the model to produce reasoning_end_str, effectively terminating the reasoning block」。能自己插，何必逼模型？

闭源那套：接口直接给你已经分好的块（思考一块、答案一块），内部怎么切、记号长什么样，Anthropic 和 OpenAI 都没公开。能确认的只有：边界精确到 token 的位置——Anthropic 能把草稿那一段一个 token 不差地数出来（用量字段里的 thinking_tokens）。（「切不是懂」跟Agent 第 2 课的工具调用是同一招：模型不声明「我在调工具」，程序只认形状。）

Q3 · 闭源 API 的 signature 里装的是什么？为什么必须原样带回？

先说清范围：这是闭源 API 的机制——Anthropic 叫 signature，OpenAI 的同类设计叫 encrypted_content。开源模型没有这一套：思考是明文，多轮把原文拼回去就行（Qwen3 官方的建议就是「passing the content as it is」，聊天模板自己会处理）。

闭源这套里，每个思考块都带一个 signature 字段：加密的完整草稿——原话是「an encrypted copy of the full reasoning」。注意它盖的是模型当初吐出的那一段 token，不是显示给你看的那段摘要。

由此推出两件容易想反的事：

  • 文字清空了也能送回。display 让厂商只回空字段时，块照样能原样传回去——因为签名盖的是那段 token，空字段填点字属于「被忽略」，不属于「被改动」。服务端收到后把签名解开、重建草稿塞回提示词（「The server decrypts the signature to reconstruct the original thinking for prompt construction」）。
  • 改一个字就废。Anthropic 拿签名验证「这块确实是模型生成的」（「verify that thinking blocks were generated by Claude」），所以整块必须完整、不改动地传回去——篡改直接报 400。

Anthropic 还补了一句给开发者的：这字段是不透明的，别解析（「The signature field is opaque: don't interpret or parse it」）。OpenAI 那边是同一族设计：reasoning 条目「remains opaque」、无状态模式下用 encrypted_content 带回。防的都是同一件事：伪造思考。（开源侧则没有「验证」这回事：原文你全有，改了也只是改了提示词，没有任何字段会拦你——这条是从「不存在校验字段」推出来的。）

Q4 · 流式输出的时候，客户端怎么认边界？

字是一个一个流出来的，所以「思考从哪开始、到哪结束」在传输时是一串专门的事件逐条标出来的。真实的事件序列（Anthropic）：

content_block_start    type = thinking     ← 思考开始
content_block_delta    thinking_delta ×N   ← 摘要一段一段流出来
content_block_delta    signature_delta     ← 签名落定
content_block_stop                          ← 思考结束
content_block_start    type = text         ← 答案开始
content_block_delta    text_delta ×N

Anthropic 原话：「Thinking blocks stream as thinking_delta events …, followed by a single signature_delta event just before the block's content_block_stop」——签名是最后一条，紧贴着块的结束。

两个边角要知道：

  • 不给文字时也一样走这套：display: "omitted" 下思考文本不流出来，只流一个空的 thinking_delta ＋ 签名——边界照样清楚。
  • 思考块可能整个不出现：自适应模式下，简单题可能压根不思考——「no thinking block is produced regardless of display」。客户端判断「这次想没想」，只能看有没有块，请求参数里读不出来。

开源那边是同一件事、另一副样子：vLLM 的解析器在字流里认出结束标签之后，把「思考」「答案」两个字段分开往外流（reasoning / content）——边界还是靠记号，只是事件名不同；返回结构里同样没有任何签名字段。

（display 三档：summarized 给摘要（不少老模型的默认）· omitted 只给签名（不少新模型的默认）· updates（beta）。三档计费都按草稿全长，省的只是显示和延迟。）

Q5 · 思考是「练」出来的——那练出来的到底是什么？标签也是练出来的吗？

（这一问答的是开源这边：DeepSeek-R1、Qwen3 的训练配方是公开的，才有下文这些原文。闭源厂商不公开训练配方，「它们怎么练出来的」没有公开资料，不猜。）

一句话：「怎么想」是练出来的，「写成什么格式」是设计好的。这两件事常被并成一句「思考是涌现的」，拆开就清楚了。

涌现的是招式。R1 的练法是只给结果打分（答案对不对、代码跑不跑得过、测试过不过），练着练着，模型自己长出了三类动作——自我检查、验证、动态换策略。论文原话：「facilitates the emergent development of advanced reasoning patterns, such as self-reflection, verification, and dynamic strategy adaptation」。训练中途还有个出名的「aha moment」：它开始写「Wait, wait. Wait. That's an aha moment I can flag here」——学会中途回头，没人教它这句。

但格式从头到尾是人定的。R1-Zero 的模板是工程师写的：「we design a straightforward template, to require DeepSeek-R1-Zero to first produce a reasoning process, followed by the final answer」——「先思考、后答案」这个结构，是开练之前就规定好的。模板原文还把标签写死了：思考装在 <think>…</think> 里、答案装在 <answer>…</answer> 里。

标签不光是约定，还是奖励逼出来的。奖励里有一项专门管格式：「the model is incentivized to encapsulate its reasoning process within designated tags」——把思考装进那对标签才给分。所以模型「会写」这对标签，是模板 ＋ 格式奖励反复教的结果，不是它自己发明的。

标签本身也只是词表里的普通字（token）：Qwen3 官方示例直接拿结束标签的 token 编号（151668）来切分思考和答案。更细一层——连开始标签都未必是模型写的：Qwen3 官方 Note 说，默认聊天模板会自动把 <think> 塞进提示以强制思考，所以「模型输出里只有 </think>、没有开始标签，是正常的」。模型负责的，是写到结束标签收尾。

最后两盆冷水，都是原文自己泼的：

  • 文风是调教的，不是天生的：「the observed vivid reasoning patterns primarily reflect DeepSeek-engineered heuristics, rather than indicating that the model has inherently acquired human-like intelligence」——那些生动的思考样式，更多是 DeepSeek 设计的套路。
  • 正式版 R1 还有一批人写的示范：冷启动阶段先用少量人工整理的长思考数据微调一遍（论文说动机「primarily product-driven」，为了用户体验），然后才进强化学习。

收口：「怎么想」是涌现的，「写成什么格式」是设计的。模板定结构、格式奖励逼它把思考装进标签、冷启动数据定文风；模型自己长出来的只有招式——回头查、换办法、「等等我再想想」。
