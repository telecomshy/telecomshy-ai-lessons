技巧篇 · 0004

失败模式与自救：翻车了怎么办

从「重跑一遍碰运气」到「一张症状对照表」

先别急着学，聊两句

agent 跑一半报错了、答非所问了、卡住不动了——你的第一件事是什么？

大多数人的第一反应是重跑一遍。碰运气能过，但同一个坑会摔第二次。

自救不是玄学，是一张"症状 → 先看哪 → 怎么救"的对照表。第一动作永远是看轨迹（trace）：翻的是循环哪一步，救法基本就定了。

学完这课，你能：对着症状定位到循环的哪一步，选对当场救法，并说清下一跑怎么防。

这一篇的规矩（技巧篇都这样）

每条技巧都配三样：做法、理由 + 一个反例、什么时候不适用。最后一条最重要——技巧会过时，也会有例外。

记住一条主线，后面就不会晕

自救分两半：这一跑当场救，下一跑改防。第一动作永远是看 trace，先定是哪一步翻的车。

1. 先认路：翻车发生在循环哪一步

Agent 原理篇 · 第 1 课 第 4 节认过四张脸：推理想歪、行动翻车（挑错工具 / 参数错 / 工具报错）、观察看错看漏、不收尾。这一课给它们配救法。

trace（轨迹）就是一次任务里所有"推理—行动—观察"的完整记录。症状是表象，trace 告诉你哪一步翻的车——它比猜测有用一百倍。

翻车症状报错 / 答非所问 / 卡住
→
看 trace最后一次推理、行动、观察各是什么
→
定位哪一步推理？行动？观察？收尾？
↺ 对症下药：这一跑怎么救，下一跑怎么防

2. 技巧一：先看 trace，再动手

做法：从后往前读 trace：最后一次"观察"是什么、"行动"是什么、"推理"说了什么。翻车点通常就在这三样之间。

理由 + 反例：猜着改会连环改错——把"工具报错"当成"模型笨"去改提示词，白忙一场。反例：有些系统没记 trace，那只能从报错信息下手。

什么时候不适用：程序根本没跑起来（语法错、没装库）——那是环境问题，看报错就够，轮不到 trace。

3. 技巧二：工具翻车，先读错误信息

做法：把错误信息分三类再动手。工具本身坏了（超时、5xx）→ 退避重试：等一会儿再试，别原地狂点——Anthropic 的官方 SDK 就是这么干的（默认自动退避重试两次）。你调错了（参数格式、权限）→ 改参数，下一跑把工具清单写清楚（那是"工具设计"那一课的地盘，还没开）。工具说"没有"（查无此航班）→ 换来源或回头问用户，别硬编一个。

理由 + 反例：三类的救法完全不同；把"调错参数"当"接口不稳"去狂重试，只会把配额烧光。反例：一次超时不代表坏了，重试一两次还超时才算。

什么时候不适用：撞花费上限那种 429 没有重试提示，会一直失败到额度恢复（Anthropic Errors 文档原话）——重试救不了它，只能等或充值。⚠ 以上是 Anthropic 的口径，别家错误码要看别家文档。

4. 技巧三：格式坏，靠接口钉，不靠嘴求

做法：JSON 断了、字段缺了，就开结构化输出（Anthropic 叫 structured outputs；vLLM 这类引擎叫 response_format / structured_outputs），让接口把格式钉住；提示词里的格式要求只当辅助。

理由 + 反例：在提示词里写十遍"必须输出合法 JSON"，也挡不住它偶尔吐断；接口保证是把非法的路直接堵死。反例：字段写错（"到达日期"填成出发日期）是语义错，结构化输出管不了。

什么时候不适用：拒答（refusal）时拒答内容优先于 schema 约束（Anthropic 口径）——那不是格式问题，别当格式修；开放式写作本来就不该钉格式。

5. 技巧四：停得莫名其妙，先查"为什么停"

做法：每个回答都带一个停止原因（stop reason）。撞 max_tokens＝被上限截断，调大上限重发（Anthropic 文档原话 "Raise max_tokens or continue the response"）；截断的回答里若有没写完的工具调用，更得重发。model_context_window_exceeded＝窗口填满，当截断处理。

理由 + 反例：把"截断"当"答完"，会拿着半截答案下结论。反例：回答确实写完却想让它继续写——那不是截断，是任务边界没说清。

什么时候不适用：end_turn 才是真答完；拒答、要调工具各有各的处理，别一律调大上限。

6. 技巧五：不收尾、看着像编的

做法：不收尾——最大步数护栏兜底，更根本的是给它"什么时候算完成"的约定。看着像编的——让它给出处，关键动作人工批准（人在环中）；同一类任务多跑几遍看一致（那是 技巧篇 0002 的地盘）。

理由 + 反例：模型不会自己保证停下来，也不会自己保证说的是真的——这两样只能工程兜。反例：模型两次答案不一样未必是错，先固定参数、同一缓存状态再比（温度、批大小都会让同请求不同输出，见 LLM 底层 · 第 8 课），不然你比的是随机性。

什么时候不适用：一次性小活，人审比翻车还贵——低风险的就让它跑完自己看。

7. 一张症状对照表，带走

症状 多半翻在哪 当场救 → 下一跑防
工具报错 / 超时 行动 读错误信息，退避重试 → 超时阈值、重试交给 SDK
参数填错（日期 / 单位） 行动 改参数重发 → 工具清单写清格式和示例
JSON 断 / 字段缺 行动 / 输出 开结构化输出 → 同左，schema 写清必填
答案停在半句 输出 查停止原因，调大上限重发 → 预算留白（技巧篇 0001）
不收尾 / 死循环 推理 最大步数拦下 → 约定"什么时候算完成"
看着像编的 推理 / 观察 要出处、人工把关 → 评测多跑几遍（技巧篇 0002）
忘事 / 塞爆 观察 / 记忆 裁剪、压缩（技巧篇 0001）→ 记忆取舍（原理篇第 7 课）
同任务两次结果不一样 全局 先固定参数、同缓存状态再比 → 多跑几遍看一致（技巧篇 0002）

8. 动手：让假 agent 故意翻四种车

脚本在工作区：exercises/practice/0004-failure-modes.py，不需要 API key。四种翻车都是玩具实现，但对应真实症状：工具报错、JSON 断、撞上限截断、不收尾——每种走一遍"症状 → 当场救 → 下一跑防"。

python exercises/practice/0004-failure-modes.py

Windows 终端若中文乱码，先执行 chcp 65001 切换成 UTF-8。

===== 症状 ① 工具报错 =====
  第 1 次调用报错：get_flights 超时（网关 504）
  [当场救] 读懂错误是「超时」→ 退避 2s 再试（玩具里不真等，真系统等的是秒级）
  第 2 次调用报错：get_flights 超时（网关 504）
  [当场救] 读懂错误是「超时」→ 退避 4s 再试（玩具里不真等，真系统等的是秒级）
  第 3 次调用成功：23 个航班
  [下一跑防] 超时阈值写进工具配置；重试交给 SDK（Anthropic 的 SDK 默认自动退避重试两次）
  [trace] ['推理：查一下明天的航班', '观察：工具报错「get_flights 超时（网关 504）」', '观察：工具报错「get_flights 超时（网关 504）」', '行动：查航班 → 23 个航班']

===== 症状 ② 输出格式坏（JSON 断了）=====
  模型吐出：{"city": "北京
  [当场救] 解析报错：Unterminated string starting at: line 1 column 10 (char 9)
  [当场救] 不改提示词碰运气——开结构化输出，接口替你把格式钉住
  开结构化输出后：{"city": "北京"} → 解析成功：{'city': '北京'}
  [下一跑防] schema 写清字段必填；拒答时按 stop reason 另行处理，别当格式错

===== 症状 ③ 撞上限截断 =====
  返回里 stop_reason＝max_tokens，正文停在「第一步：先查航班，第二步：比」
  [当场救] 查 stop reason 就知道为什么停——max_tokens 是撞上限，不是答完
  调大上限重发后：stop_reason＝end_turn，正文完整
  [下一跑防] 预算留白（技巧篇 0001）；回答里若有没写完的工具调用，必须调大重发

===== 症状 ④ 不收尾（死循环）=====
  第 1 步：模型说「再查一家」……（就是不说完成）
  第 2 步：模型说「再查一家」……（就是不说完成）
  第 3 步：模型说「再查一家」……（就是不说完成）
  第 4 步：模型说「再查一家」……（就是不说完成）
  [当场救] 达到最大步数 4 仍未完成 → 护栏拦下
  [下一跑防] 最大步数是兜底；更根本的是给它「什么时候算完成」的约定

带走一句：第一动作永远是看 trace——先定位是循环哪一步翻的车，救法基本就定了。

9. 判断题（技巧篇考这个）

Q1 工具连报三次超时，你先做什么？

Q2 模型输出的 JSON 老是断，最靠谱的一招是什么？

Q3 回答停在半句话，下一步做什么？

Q4 agent 说"任务完成了"，但你怀疑它没做完，怎么办？

这节课的一手资料：
Anthropic — Errors（官方文档）：429 / 529 / 500 各是什么；官方 SDK 默认自动退避重试两次；撞花费上限的 429 没有重试提示、会一直失败到额度恢复。
Anthropic — Stop reasons and fallback（官方文档）："为什么停了"那张表；撞上限（max_tokens）调大重发；上下文填满（model_context_window_exceeded）当截断处理。
Anthropic — "Building effective agents"：最根本的一防——能用固定流程解决的事别上 agent，不确定性是要付的代价。
